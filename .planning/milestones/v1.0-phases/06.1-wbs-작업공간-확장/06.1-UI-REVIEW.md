## Initial Top 3 Priority Fixes

1. **Contain the shared WBS table in a scrollable operational surface** - the current `min-w-[1320px]` table can overflow the page/grid instead of scrolling inside the WBS surface - add a wrapper with `min-w-0 overflow-x-auto` around the table and keep the helper text inside that surface.
2. **Make the shared layout variant-aware for the compact tab** - `WbsWorkspaceContent` applies the same `xl:grid-cols-[minmax(0,2.4fr)_minmax(320px,1fr)]` layout to both the dedicated page and the `max-w-5xl` project hub tab - stack the milestone rail for `variant="tab"` or only enable the two-column layout when the table can be contained.
3. **Add explicit read-only/recovery context** - read-only users only see missing controls, and WBS load failure uses a generic workspace failure title - add short WBS-specific read-only and load-failure copy so disabled authoring states explain themselves.

**Recommended next GSD command:** `$gsd-execute-phase 6.1` with the UI-review fix scope above, then rerun `$gsd-ui-review 6.1`. Do not start Phase 7 until the responsive containment issue is re-reviewed.

## Initial Detailed Findings

### Pillar 1: Copywriting (3/4)

What passes:

- The required Phase 6.1 copy keys are present for the dedicated workspace, open/back CTA, assignee labels, unassigned state, quick-add prompts, action labels, and quick-add validation (`client/src/i18n/locales/en/translation.json:559`, `client/src/i18n/locales/en/translation.json:571`, `client/src/i18n/locales/en/translation.json:585`, `client/src/i18n/locales/en/translation.json:618`, `client/src/i18n/locales/ko/translation.json:557`, `client/src/i18n/locales/ko/translation.json:569`, `client/src/i18n/locales/ko/translation.json:583`, `client/src/i18n/locales/ko/translation.json:616`).
- The compact tab CTA says where the user is going (`Open workspace` / `작업공간 열기`) and sits beside the existing create action (`client/src/components/wbs/WbsTab.tsx:40`).
- Quick-add communicates the details boundary with `Set in details` and has explicit empty-name validation (`client/src/components/wbs/WbsInlineCreateRow.tsx:154`, `client/src/components/wbs/WbsInlineCreateRow.tsx:160`).

What fails:

- The WBS load failure uses the generic `workspace.status.loadFailedTitle` title while the description is WBS-specific (`client/src/components/wbs/WbsWorkspaceContent.tsx:575`).
- Read-only mode removes create, drag, actions, and quick-add affordances without a short WBS-specific explanation (`client/src/pages/project/ProjectWbsPage.tsx:86`, `client/src/components/wbs/WbsWorkspaceContent.tsx:437`, `client/src/components/wbs/WbsWorkspaceContent.tsx:588`).

### Pillar 2: Visuals (3/4)

What passes:

- The dedicated page uses the existing `Header`, project workspace context, compact WBS top band, and avoids `ProjectWorkspaceHero`, matching the spec's non-hero operational page contract (`client/src/pages/project/ProjectWbsPage.tsx:41`, `client/src/pages/project/ProjectWbsPage.tsx:51`, `client/src/pages/project/ProjectWbsPage.tsx:53`).
- The compact hub tab keeps a clear title, description, open-workspace CTA, and create CTA (`client/src/components/wbs/WbsTab.tsx:33`).
- Assignee rendering is visually distinct but restrained: assigned items use a bordered pill and unassigned items use muted text (`client/src/components/wbs/SortableWbsRow.tsx:217`).

What fails:

- The main WBS table is rendered as a bare table inside the grid section, without the single operational border/background shell that would make the table feel like the primary workspace surface (`client/src/components/wbs/WbsWorkspaceContent.tsx:525`, `client/src/components/wbs/WbsWorkspaceContent.tsx:617`).
- The table's width behavior creates the dominant visual problem: at narrow and compact widths, users are likely to see clipped content instead of a deliberately scrollable authoring surface (`client/src/components/wbs/WbsWorkspaceContent.tsx:537`).

### Pillar 3: Color (4/4)

What passes:

- The audited WBS implementation uses semantic tokens and existing surface classes rather than hard-coded hex/RGB colors.
- Primary color usage is sparse and purposeful: quick-add hover border, quick-add active icon, and newly-created row highlight (`client/src/components/wbs/WbsInlineCreateRow.tsx:98`, `client/src/components/wbs/WbsInlineCreateRow.tsx:129`, `client/src/components/wbs/SortableWbsRow.tsx:138`).
- Assignee pills, empty/error states, and controls rely on `bg-card`, `border-border`, `text-muted-foreground`, and existing workspace surface tokens (`client/src/components/wbs/SortableWbsRow.tsx:219`, `client/src/index.css:528`, `client/src/index.css:562`).

No blocking color issue found.

### Pillar 4: Typography (3/4)

What passes:

- The table, quick-add row, dialog helper copy, and tab header mostly stay in the app's operational scale: `text-xs`, `text-sm`, `text-lg`, `font-medium`, and `font-semibold` (`client/src/components/wbs/SortableWbsRow.tsx:183`, `client/src/components/wbs/WbsInlineCreateRow.tsx:160`, `client/src/components/wbs/WbsItemFormDialog.tsx:256`, `client/src/components/wbs/WbsTab.tsx:36`).
- Numeric fields use `tabular-nums`, which helps progress and M/M values scan in a dense table (`client/src/components/wbs/SortableWbsRow.tsx:237`, `client/src/components/wbs/SortableWbsRow.tsx:274`).

What fails:

- The dedicated page title uses `text-3xl sm:text-4xl` plus `tracking-[-0.03em]` in an operational header (`client/src/pages/project/ProjectWbsPage.tsx:72`). That makes the top band read closer to a hero than the compact authoring header requested by the UI spec.

### Pillar 5: Spacing (2/4)

What passes:

- The compact tab header wraps its CTA/action row and avoids overlap (`client/src/components/wbs/WbsTab.tsx:34`, `client/src/components/wbs/WbsTab.tsx:40`).
- The shared app tabs already have a horizontal overflow treatment, so the project-hub tab rail is not the Phase 6.1 spacing problem (`client/src/components/ui/tabs.tsx:19`).

What fails:

- The shared table is fixed to `min-w-[1320px]`, but there is no local `overflow-x-auto` wrapper around the table and no `min-w-0` on the grid child section (`client/src/components/wbs/WbsWorkspaceContent.tsx:537`, `client/src/components/wbs/WbsWorkspaceContent.tsx:617`).
- The same two-column grid is used for both variants (`client/src/components/wbs/WbsWorkspaceContent.tsx:615`). Inside the project hub, that grid sits under `max-w-5xl`, so the table plus the milestone rail cannot fit cleanly (`client/src/pages/diagram/DiagramsPage.tsx:207`).
- The dedicated page uses `max-w-none`, but mobile and tablet still need contained horizontal table scrolling. Page-level `overflow-auto` on the whole `main` is not an adequate table-surface affordance (`client/src/pages/project/ProjectWbsPage.tsx:51`).

Why it matters:

- Phase 6.1 explicitly asks for compact-tab horizontal scroll to be acceptable and for the dedicated WBS surface to remain in the first viewport. Without a contained scroll surface, the implementation can push content outside the safe area and make the milestone rail compete with an oversized table.

### Pillar 6: Experience Design (3/4)

What passes:

- Loading, error, empty, retry, delete confirmation, mutation-disabled, and inline quick-add validation states are implemented (`client/src/components/wbs/WbsWorkspaceContent.tsx:571`, `client/src/components/wbs/WbsWorkspaceContent.tsx:573`, `client/src/components/wbs/WbsWorkspaceContent.tsx:588`, `client/src/components/wbs/WbsWorkspaceContent.tsx:643`, `client/src/components/wbs/SortableWbsRow.tsx:101`, `client/src/components/wbs/WbsInlineCreateRow.tsx:70`).
- The assignee selector uses the existing team member query and degrades by disabling only the assignee field while keeping the rest of the form usable (`client/src/components/wbs/WbsWorkspaceContent.tsx:146`, `client/src/components/wbs/WbsItemFormDialog.tsx:226`, `client/src/components/wbs/WbsItemFormDialog.tsx:256`).
- The dedicated-only quick-add contract is guarded by `variant === 'page' && canEdit`, and the helper tests cover placement and default payload behavior (`client/src/components/wbs/WbsWorkspaceContent.tsx:234`, `client/test/unit/wbs-inline-create.test.ts:40`, `client/test/unit/wbs-inline-create.test.ts:97`).

What fails:

- Read-only users do not get an explicit explanation that WBS structure is view-only; they only infer it from missing controls and disabled drag/action paths.
- The responsive containment issue interrupts the primary repeated-authoring workflow because append rows, action cells, and later columns can sit outside the visible workspace without a clear local scroll affordance.
