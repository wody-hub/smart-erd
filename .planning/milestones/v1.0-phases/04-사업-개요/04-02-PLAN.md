### 3-2. `lib/format.ts` — 신규 생성

React 의존성 없는 순수 유틸:

```typescript
/**
 * 숫자를 한국 원화 표기로 포맷한다.
 * SI 프로젝트 특성상 원화 고정 — 다통화 지원은 현재 스코프 외.
 *
 * @param amount 금액 (원화 단위 정수)
 * @returns 포맷된 금액 문자열 (예: "150,000,000원")
 */
export function formatCurrency(amount: number): string {
  return `${amount.toLocaleString('ko-KR')}원`;
}

/**
 * ISO 8601 날짜를 locale 기준으로 포맷한다.
 *
 * @param date ISO 8601 날짜 문자열 (예: "2026-01-01")
 * @param locale BCP 47 언어 태그 (예: "ko", "en")
 * @returns 포맷된 날짜 문자열 (ko: "2026년 1월 1일")
 */
export function formatProjectDate(date: string, locale: string): string {
  return new Intl.DateTimeFormat(locale, {
    year: 'numeric', month: 'long', day: 'numeric',
  }).format(new Date(date));
}

/**
 * 시작일이 종료일 이전 또는 같은 날인지 검증한다.
 * 둘 다 빈 문자열이면 유효(미입력 허용).
 *
 * @param startDate 시작일 (ISO 8601 또는 빈 문자열)
 * @param endDate 종료일 (ISO 8601 또는 빈 문자열)
 * @returns 유효하면 true
 */
export function isDateOrderValid(startDate: string, endDate: string): boolean {
  if (!startDate || !endDate) return true;
  return new Date(endDate) >= new Date(startDate);
}

/**
 * 날짜 쌍의 정합성을 검증한다 (둘 다 입력 또는 둘 다 미입력).
 *
 * @param startDate 시작일 (ISO 8601 또는 빈 문자열)
 * @param endDate 종료일 (ISO 8601 또는 빈 문자열)
 * @returns 정합하면 true
 */
export function isDatePairValid(startDate: string, endDate: string): boolean {
  const hasStart = !!startDate;
  const hasEnd = !!endDate;
  return hasStart === hasEnd;
}
```

- `formatCurrency`: `'ko-KR'` 고정 — 금액 단위는 항상 원화 (이미 "원" 접미사 포함, 호출부에서 추가하지 않음)
- `formatProjectDate`: `locale` 파라미터 수신 — `i18n.language` 주입
- `isDateOrderValid`: FE 날짜 순서 사전 검증용 (BE에도 동일 검증 존재)
- `isDatePairValid`: FE 날짜 쌍 정합성 사전 검증용 (BE `@AssertTrue`와 대응)

### 3-4. `api/projectApi.ts` — 함수 2개 추가

```typescript
import type { BusinessOverviewResponse, UpdateBusinessOverviewPayload } from '@/types/project';

/**
 * 사업 개요를 조회한다.
 *
 * @param teamId 팀 ID
 * @param projectId 프로젝트 ID
 * @returns 사업 개요 + 요약 지표 (memberCount, documentCount, progressRate 포함)
 */
export async function fetchBusinessOverview(
  teamId: string, projectId: string
): Promise<BusinessOverviewResponse> {
  const res = await axiosInstance.get<BusinessOverviewResponse>(
    `/teams/${teamId}/projects/${projectId}/business-overview`
  );
  return res.data;
}

/**
 * 사업 개요를 수정한다 (전체 교체 방식의 PATCH).
 *
 * @param teamId 팀 ID
 * @param projectId 프로젝트 ID
 * @param data 6개 사업 개요 필드 전체
 * @returns 수정된 사업 개요 응답
 */
export async function updateBusinessOverview(
  teamId: string, projectId: string, data: UpdateBusinessOverviewPayload
): Promise<BusinessOverviewResponse> {
  const res = await axiosInstance.patch<BusinessOverviewResponse>(
    `/teams/${teamId}/projects/${projectId}/business-overview`, data
  );
  return res.data;
}
```

- HTTP 메서드: **PATCH** (BE와 일치 — 기존 `PUT /{projectId}`와 구분하기 위한 선택, 실제 동작은 6개 필드 전체 교체)
- `UpdateBusinessOverviewPayload`: 명시적 payload 타입 (6개 필드 전체 전송 필수)

## 4. 데이터 흐름

```
BusinessOverviewTab (Phase 04-03)
  │
  ├─ useQuery({
  │    queryKey: queryKeys.projects.businessOverview(teamId, projectId),
  │    queryFn: () => fetchBusinessOverview(teamId, projectId),
  │  })  → BusinessOverviewResponse (11 필드 — memberCount, documentCount 포함)
  │
  ├─ useMutation({
  │    mutationFn: (data: UpdateBusinessOverviewPayload) =>
  │      updateBusinessOverview(teamId, projectId, data),
  │    onSuccess: invalidateQueries + toast.success,
  │    onError: toast.error(getErrorMessage),  ← isEditing 유지 (false로 전환하지 않음)
  │  })
  │
  └─ 렌더링
       ├─ formatCurrency(data.contractAmount)  ← "원" 접미사 포함, 호출부에서 추가 금지
       └─ formatProjectDate(data.projectStartDate, i18n.language)
```
