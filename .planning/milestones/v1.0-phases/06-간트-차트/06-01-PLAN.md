2. `client/src/components/gantt/gantt-date-utils.ts`를 새로 만든다.
   - `parseDateOnly(value: string): Date`
   - `formatDateOnly(date: Date): string`
   - `inclusiveDurationDays(start: Date, end: Date): number`
   - `expandDateRange(min: Date, max: Date, padDays: number): { start: Date; end: Date }`
   - 구현 규칙:
     - `new Date('2026-04-16')` 금지
     - 문자열은 `yyyy-MM-dd`를 split 후 `new Date(year, month - 1, day)`로 local date 생성
     - serialization은 local getter(`getFullYear/getMonth/getDate`) 기반으로 되돌린다
   - 목적은 KST/UTC 경계에서 간트 바가 하루 밀리는 문제를 막는 것이다.

3. `client/src/components/gantt/gantt-adapter.ts`를 새로 만든다.
   - exported API는 `buildGanttModel({ wbsItems, milestones })` 1개로 좁힌다.
   - 반환값은 다음을 포함한다:
     - `tasks`: SVAR task 배열
     - `range`: 초기 viewport용 `{ start, end }`
     - `stats`: omitted item count, dated task count, milestone count
   - WBS 매핑 규칙:
     - raw API 순서를 그대로 신뢰하지 않고, 기존 `buildChildrenByParent` / `flattenTreeItems` 또는 동등한 정렬 로직으로 `sortOrder` 기반 순서를 먼저 확정한다
     - `startDate` + `endDate`가 모두 있으면 `type: 'task'`
     - 자기 날짜는 없지만 하위 dated descendant가 있으면 `type: 'summary'`
     - 날짜도 없고 dated descendant도 없는 leaf는 chart에서 제외
     - `id`는 WBS numeric ID를 그대로 사용
     - `text`는 WBS `name`을 그대로 사용
     - `parent`는 WBS `parentId`를 그대로 사용
     - `progress`는 `progressRate`
     - `data` 대신 flat `parent` 관계를 우선 사용해 기존 WBS 정렬/트리 구조와 맞춘다
   - Milestone 매핑 규칙:
     - built-in `type: 'milestone'`만 사용한다
     - `id`는 충돌 방지용 string (`milestone:${id}`)
     - `text`는 milestone `name`을 그대로 사용
     - `start`는 `targetDate`
     - `parent`는 지정하지 않고 root-level row로 append한다
     - custom metadata에 `kind: 'milestone'`, `milestoneId`, `isDelayed`, `linkedWbsItemCount`를 실어 tooltip/스타일에 재사용한다
   - 추가 metadata:
     - WBS task에는 `kind: 'wbs'`, `wbsId`, `original: WbsItem`
     - summary task에는 `kind: 'summary'`, `wbsId`
   - 초기 range는 dated task + milestone 전체 min/max에 7일 padding을 준다.

4. `client/src/components/gantt/gantt-scale-presets.ts`를 새로 만든다.

     - week: year / week

5. `client/src/components/gantt/gantt.css`를 새로 만든다.
