<lifecycle_contract>

Status lifecycle rules to implement exactly:

1. `IssueStatus` values are `REGISTERED`, `IN_PROGRESS`, `DONE`.
2. `POST /issues` never accepts a custom status; new issues are always persisted as `REGISTERED`.
3. `PUT /issues/{issueId}` may include status only in same-state or next-state form:
   - current `REGISTERED` -> allowed target `REGISTERED` or `IN_PROGRESS`
   - current `IN_PROGRESS` -> allowed target `IN_PROGRESS` or `DONE`
   - current `DONE` -> allowed target `DONE` only
4. `PATCH /issues/{issueId}/status` is the lightweight quick-progress endpoint and uses the same validator as the full update path.
5. Any backward transition, skip transition, or unknown enum fails with a business error and 400 response.
6. UI quick actions mirror the lifecycle:
   - `REGISTERED` -> `Start`
   - `IN_PROGRESS` -> `Mark done`
   - `DONE` -> no primary action
7. Edit dialog status choices must never render backward options, even if the request is hand-crafted later on the backend.

</lifecycle_contract>

<filter_and_export_contract>

List/export query rules:

1. Use one shared frontend serializer in `client/src/lib/issues-query.ts`.
2. Use one shared backend parser/value object in `ProjectIssueService`.
3. Supported query dimensions:
   - `status`: omitted or one of `REGISTERED`, `IN_PROGRESS`, `DONE`
   - `priority`: omitted or one of `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`
   - `assignee`: omitted/`all`, `unassigned`, or numeric user id as string
4. The list endpoint and Excel download endpoint must consume the exact same parsed filter object.
5. Default sorting stays server-owned:
   - unfinished before done
   - higher priority before lower priority
   - latest `updatedAt` first
   - latest `id` as deterministic tie-breaker
6. The frontend keeps filter state in React state/query keys and never applies additional local filtering after the server response.
7. `queryKeys.issues.list(teamId, projectId, filters)` is the canonical cache key.
8. Export uses `downloadBlob()` and returns a header-only workbook when the filtered result is empty.

</filter_and_export_contract>
