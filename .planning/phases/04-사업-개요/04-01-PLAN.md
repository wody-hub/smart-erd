### Step 4: Project 엔티티 확장

**추가 필드** (기존 `description` 뒤에 삽입):

```java
@Nullable @Column(name = "client_company", length = 200)
private String clientCompany;

@Nullable @Column(name = "contractor_company", length = 200)
private String contractorCompany;

@Nullable @Column(name = "contract_amount")
private Long contractAmount;

@Nullable @Column(name = "project_start_date")
private LocalDate projectStartDate;

@Nullable @Column(name = "project_end_date")
private LocalDate projectEndDate;

@Nullable @Column(name = "project_scope", columnDefinition = "TEXT")
private String projectScope;
```

**추가 메서드:**

```java
public void updateBusinessOverview(
    @Nullable String clientCompany,
    @Nullable String contractorCompany,
    @Nullable Long contractAmount,
    @Nullable LocalDate startDate,
    @Nullable LocalDate endDate,
    @Nullable String projectScope
) {
    if (startDate != null && endDate != null && startDate.isAfter(endDate)) {
        throw new BusinessException(MessageCode.ERROR_BUSINESS_INVALID_PROJECT_PERIOD.code());
    }
    this.clientCompany = clientCompany;
    this.contractorCompany = contractorCompany;
    this.contractAmount = contractAmount;
    this.projectStartDate = startDate;
    this.projectEndDate = endDate;
    this.projectScope = projectScope;
}
```

**설계 의도:**
- 날짜 쌍 검증은 도메인 불변식 → 엔티티 캡슐화
- 한쪽만 null인 케이스는 DTO `@AssertTrue`로 처리

## 4. 데이터 흐름

### GET

```
JWT → loginId → verifyMembership → findProject → verifyBelongsToTeam
→ countByTeam + countByProjectAndDeletedAtIsNull
→ BusinessOverviewResult(progressRate: null)
→ BusinessOverviewResponse.from()
→ 200 OK
```

### PATCH

```
JWT + @Valid RequestBody → isProjectPeriodPairValid (400)
→ loginId → verifyEditable → findProject → verifyBelongsToTeam
→ project.updateBusinessOverview() (400 if startDate > endDate)
→ JPA Dirty Checking
→ count 쿼리 → BusinessOverviewResult → 200 OK
```
