다음 exact target state로 구현한다.

1. `DESIGN.md`에 Paper / Graphite / Midnight 3-theme 구조를 명시한다.
   - Paper: 현재 warm editorial direction 유지
   - Graphite: cool gray/slate dark theme, accent `#5B8DEF`, background `#272C33`
   - Midnight: current dark shell 계열 유지
   - Monaco mapping은 `paper => vs`, `graphite => vs-dark`, `midnight => vs-dark`로 명시한다

2. `client/src/index.css`의 token selector 구조를 아래로 바꾼다.
   - `:root, .theme-paper { ...Paper tokens... }`
   - `.theme-graphite { ...Graphite tokens... }`
   - `.theme-midnight { ...Midnight tokens... }`
   - 기존 standalone `.dark { ... }` token 블록은 제거한다
   - `.dark` class는 token source selector로 재사용하지 않는다. 토큰 전환은 오직 `.theme-*`가 담당한다

3. Graphite token set은 `02-UI-SPEC.md` 값을 그대로 사용한다. 최소한 아래 값들은 exact match로 반영한다.
   - `--background: 220 14% 18%`
   - `--card: 220 14% 22%`
   - `--primary: 220 80% 62%`
   - `--foreground: 220 15% 94%`
   - `--muted-foreground: 220 8% 62%`
   - `--border: 220 10% 30%`
   - `--header-bg: 220 16% 14%`
   - `--erd-table-header: 220 80% 62%`
   - `--erd-table-supporting: 168 54% 42%`
   - `--erd-table-attention: 38 58% 54%`
   - 그리고 아래 inventory 그룹을 빠짐없이 점검한다.
     - core/surface: `--foreground-secondary`, `--secondary`, `--muted`, `--accent`, `--popover`, `--card-foreground`
     - overlay/shell: `--field-highlight`, `--overlay-scrim`, `--header-foreground`, `--header-muted`
     - ERD: 모든 `--erd-*`
     - validation/composition: 모든 `--erd-validation-*`, `--composition-*`
     - cursor: `--cursor-color-1` ~ `--cursor-color-6`, `--erd-cursor-foreground`
     - shadow/utilities: `--shadow-soft`, `--shadow-strong`, `--shadow-operational`, `--shadow-primary`, `--shadow-primary-hover`, `--shadow-destructive`, `--shadow-field-inset`
   - UI-SPEC에 직접 수치가 없는 shadow token은 Paper 값을 암묵 상속하지 않는다. Graphite와 Midnight 모두 아래 exact dark-theme override를 사용한다.
     - `--shadow-soft: 0 16px 40px rgba(0, 0, 0, 0.24)`
     - `--shadow-strong: 0 20px 48px rgba(0, 0, 0, 0.48)`
     - `--shadow-operational: 0 8px 18px rgba(0, 0, 0, 0.20)`
     - `--shadow-primary: 0 12px 24px hsl(var(--primary) / 0.32)`
     - `--shadow-primary-hover: 0 16px 30px hsl(var(--primary) / 0.40)`
     - `--shadow-destructive: 0 12px 24px hsl(var(--destructive) / 0.28)`
     - `--shadow-field-inset: inset 0 1px 0 hsl(var(--field-highlight))`

4. Midnight token set은 현재 `.dark` 값을 `.theme-midnight`로 이전한다.
   - semantic color / ERD / validation / composition / cursor 계열 값은 현재 `.dark` 값을 그대로 유지한다
   - 단, shadow/utilities (`--shadow-*`, `--shadow-field-inset`)는 step 3의 exact dark-theme override를 사용한다
   - 이 shadow exception은 이 plan의 explicit instruction이며, UI-SPEC의 shorthand "same as current `.dark`" note보다 우선한다

5. Body background gradient도 theme class를 따라가도록 유지한다.
   - 새 `.theme-graphite body`, `.theme-midnight body` selector는 기존 `body` rule과 같은 `@layer base` 블록 안에 둔다
   - 기본 `body`는 Paper의 현재 warm gradient를 유지한다
   - `.theme-graphite body`는 UI-SPEC의 graphite gradient 공식(opacity 포함)을 적용한다
   - `.theme-midnight body`는 현재 dark gradient를 유지한다
   - gradient가 token 기반으로 충분한지 가정하지 말고, selector 단에서 theme별 formula를 명시한다

6. 새 raw hex hard-code를 컴포넌트 레벨에 추가하지 않는다.
   - theme 전개는 `index.css` variable layer에서 끝내고, 기존 Tailwind semantic mapping을 그대로 사용한다

7. 실행 중에는 token inventory parity를 먼저 확인하고 수정한다.
   - 기존 `:root`와 `.dark`에서 사용 중인 token 이름 목록을 추출해 누락 없는지 확인한다
   - Graphite/Midnight 둘 다 소비되는 token이 Paper-only fallback으로 남지 않게 한다

8. build 후 수동 visual spot-check를 수행한다.
   - `Paper`, `Graphite`, `Midnight` 각각에서 header, body background, ERD surface를 확인한다
   - `workspace-shell`, 대표 `surface-display` 카드(teams/projects/documents 중 최소 1개)의 gradient/depth도 함께 확인한다
   - Graphite/Midnight에서 shadow depth가 Paper 대비 지나치게 납작하지 않은지 확인한다
   - Graphite에서 body gradient opacity와 대비가 UI-SPEC과 맞는지 확인한다
   - 결과는 실행 summary에 기록한다
