## Source Audit

This plan covers GOAL truths for authorized project-data grounding, REQ AI-CHAT-02 and AI-READ-01 through AI-READ-04, RESEARCH responsibilities for API/backend-owned context disambiguation and summary-first reads, and CONTEXT decisions D-07 through D-22 plus D-27. It does not implement deferred write/audit-history/provider-management items from D-30.

## Decision Traceability

- D-12: `AiChatContextResolver` resolves by exact IDs or normalized exact names only; ambiguous, misspelled, fuzzy, contains, and route-conflicting names return confirmation candidates before any read.
- D-16: `AiReadContextService` tool selection covers project/business overview, WBS, milestones, issues, TODOs, and WBS work history/comments.
- D-17/D-18/D-22: `AiReadContextService` applies explicit caps before provider context serialization: team project fanout max 20, detailed project fanout max 5 unless the user narrows scope, WBS rows max 50 summary / 25 detail, milestone rows max 30, issue rows max 50 summary / 25 detail, own TODO rows max 30, member TODO summaries max 20 owners, history/comment rows max 25, total fact bullets max 200, and provider context max 12,000 UTF-16 characters.
- D-20: Member-wide TODO summaries are allowed only when the user explicitly asks and authorization permits it; output remains summary-only by member/status/count.

## Must Haves

- Scope input is treated as untrusted and revalidated on the server.
- Multi-project expansion is limited to accessible projects in the current team per D-10 and excludes all-team querying per D-11.
- Ambiguous/misspelled/conflicting project names produce confirmation candidates before provider execution per D-12 and D-26.
- Name matching order is `projectId`/manual ID, normalized exact project name, then confirmation-only candidates for contains or fuzzy matches; no Levenshtein/fuzzy result is ever auto-selected.
- Read tool selection recognizes Korean and SI PM synonyms such as `WBS`, `작업`, `마일스톤`, `일정`, `이슈`, `리스크`, `TODO`, `할 일`, `담당`, `코멘트`, `히스토리`, `지연`, and `미완료`.
- Read context caps are constants in `AiReadContextService` and tests assert cap behavior for project fanout, row counts, history/comment rows, total facts, and provider-context size.
- TODO reads default to current-user TODOs; member-wide TODO status is allowed only when the user explicitly asks for team/project member TODO status and existing team/project authorization permits it, and the response remains summary-only by member/status/count with no private TODO descriptions, documents, or raw item details per D-19 through D-21.
