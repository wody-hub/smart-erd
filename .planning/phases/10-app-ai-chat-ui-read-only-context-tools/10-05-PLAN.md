## Source Audit

This plan covers GOAL chat send/receive plumbing, REQ AI-CHAT-01 and AI-CHAT-02, RESEARCH/API-module constraints, UI-SPEC API and state contract, and CONTEXT decisions D-28 and D-29. It does not implement provider runtime, Electron IPC, server history, or write/action UI.

## Decision Traceability

- D-28: Frontend chat execution goes through `client/src/api/aiChatApi.ts` and typed Spring HTTP APIs only; components/hooks must not call Codex, Electron IPC, or provider runtime directly.

## Must Haves

- `aiChatApi` is the only frontend module that calls `/api/ai/chat`.
- Components and hooks do not call `axiosInstance` directly except inside `client/src/api/aiChatApi.ts`.
- Send stores the request message with send-time context and stores the rendered response sections, not raw backend/provider payloads.
- Send stores backend `confirmationCandidates` as presentation state when the response requires confirmation so `AiChatContextBar` can render the chooser.
- Stop-running uses `AbortController` for the in-flight `/api/ai/chat` HTTP request and never clears the transcript. It does not call `cancelAiExecution` because synchronous chat does not expose a running execution id.
