## Source Audit

This plan covers GOAL answer rendering, REQ AI-CHAT-01, AI-CHAT-02, and read-source visibility for AI-READ-01 through AI-READ-03, UI-SPEC copy/layout/accessibility contract, RESEARCH facts-vs-inference guidance, and CONTEXT decisions D-13, D-14, and D-23 through D-26. It excludes action proposal, approval, and write execution UI per D-30.

## Must Haves

- Card order is conclusion, source chips, confirmed facts, interpretation, needs confirmation.
- Source chips render actual response chips and wrap without overlapping text.
- Context selector option data comes only from existing authorized typed API modules `fetchTeams` and `fetchProjects`; it never fetches AI-visible read-tool data in the browser.
- Backend `AiChatResponse.confirmationCandidates` appear in the context bar chooser and selecting one updates manual context without clearing the conversation.
- UI uses semantic Tailwind tokens and no hardcoded color palette classes.
- No visible text is hardcoded in TSX; use `aiChat.*` i18n keys.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Backend response to visible UI | Structured answer data becomes user-facing content. |
| Context selector to send lifecycle | User-selected scope is a hint sent to backend, not authorization. |
| Runtime error to UI | Backend/provider failures are displayed without raw diagnostic leakage. |
