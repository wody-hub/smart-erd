<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| project TODO data -> AI member aggregate | Private personal TODO rows are reduced to member/status/count summaries only when project-visible. |
| client scope hint -> backend resolver | Untrusted team/project IDs from the chat request are authorized through server-side project context loading. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-09-01 | Information Disclosure | `ProjectTodoService.getMemberTodoSummaries` | mitigate | Aggregate only WBS-linked TODOs using a linked-only repository method and prove unlinked TODO exclusion in tests. |
| T-10-09-02 | Elevation of Privilege | `AiChatContextResolver.authorizeSingleProject` | mitigate | Remove nullable/no-arg resolver path and require `ProjectContextLoader.load` for every single-project scope. |
| T-10-09-03 | Tampering | `ResolveCommand` team/project IDs | mitigate | Keep IDs as untrusted hints and return DENIED on loader access failures before any read context or provider execution. |
| T-10-09-SC | Tampering | package-manager installs | accept | No npm, pip, cargo, or Gradle dependency install is planned. |
</threat_model>
