# 8.1단계 리서치: WBS 작업 히스토리 관리

## 문제 요약

- 현재 WBS는 일정/구조/진척 중심이고, 작업 문서/댓글/태그/개인 TODO 개념이 없다.
- 프로젝트 문서 플랫폼은 이미 존재하지만 작업 객체와의 공식 연결 모델이 없다.
- 프로젝트 이슈는 존재하지만 댓글 스레드 모델은 없다.

## 코드베이스 관찰

### WBS

- `src/main/java/com/smarterd/domain/pm/wbs` 는 CRUD, reorder, progress 계산에 집중한다.
- `client/src/types/wbs.ts` 역시 문서/댓글/태그 관련 필드를 갖지 않는다.

### 문서 플랫폼

- `client/src/components/workspace` 에 문서 허브/생성 다이얼로그가 이미 있다.
- `src/main/java/com/smarterd/domain/markdown/service` 는 markdown 템플릿/descriptor 기반을 제공한다.

### PM 패턴

- `src/main/java/com/smarterd/domain/pm/issue` 는 PM 모듈의 좋은 참조점이지만, 댓글/attachment/thread 는 아직 없다.
- 프로젝트 허브 탭 shell 은 `client/src/pages/diagram/DiagramsPage.tsx` 가 소유한다.

## 결론

- 작업 문서 기능은 WBS에 직접 넣지 말고 기존 프로젝트 문서 플랫폼을 재사용한다.
- 태그 허브는 문서 중심으로 시작한다.
- 댓글/히스토리는 WBS 전용보다 작업 공통 모델로 가는 편이 낫다.
- 개인 TODO는 기본 비공개, WBS 연결 시 공유 투영본으로 다루는 정책이 필요하다.

## 1차 구현 후보

1. WBS <-> 문서 연결
2. 문서 태그 저장/조회
3. `Tags` 탭 read-only MVP
4. WBS 상세 문서 목록

후속:

1. 댓글/활동 로그
2. 개인 TODO
3. Gantt 위험도/요약 표시
