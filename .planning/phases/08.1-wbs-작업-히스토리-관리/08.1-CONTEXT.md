# 8.1단계: WBS 작업 히스토리 관리 - 맥락

**수집일:** 2026-04-28
**상태:** GSD phase kickoff
**방식:** 사용자가 `gsd-new-project` 스타일로 관리 방식을 바꾸라고 요청했으나, 현재 세션에는 해당 스킬이 직접 노출되지 않았다. 대신 저장소의 기존 GSD `.planning` 구조를 공식 관리 경로로 채택해 phase kickoff 아티팩트를 생성한다.

<domain>
## 단계 경계

8.1단계는 기존 WBS/간트/문서/이슈 기능을 한데 묶어, "작업 맥락에서 문서와 히스토리를 관리" 하는 협업 계층을 추가한다. 핵심은 WBS 자체를 거대한 문서 저장소로 바꾸는 것이 아니라, 기존 프로젝트 문서 플랫폼을 재사용하면서 WBS/개인 TODO가 문서를 참조하고 태그/댓글/히스토리로 협업할 수 있게 만드는 것이다.

이 단계는 다음 세 축을 함께 다룬다.

- WBS/Gantt 작업 문맥의 문서화와 댓글/히스토리
- 태그 중심 문서 허브
- 개인 TODO와 공유 WBS의 연결/비공개 경계

</domain>

<decisions>
## 구현 결정

### 문서 경계

- **D-01:** 작업 문서는 WBS 엔터티 내부 필드가 아니라 기존 프로젝트 문서 플랫폼의 독립 문서 엔터티를 재사용한다.
- **D-02:** WBS, TODO, 필요 시 이슈는 문서를 소유하지 않고 참조한다.
- **D-03:** markdown 문서를 1차 작업 문서 기본 타입으로 둔다.

### WBS와 댓글/히스토리

- **D-04:** 작업 단위 댓글은 WBS 전용으로 따로 만들지 않고, 향후 TODO/문서에도 확장 가능한 공통 thread 모델을 목표로 둔다.
- **D-05:** 사용자 댓글과 시스템 활동 로그는 분리한다.
- **D-06:** WBS 목록 행에는 전체 히스토리를 다 노출하지 않고 `문서 수`, `댓글 수`, `연결 TODO 수` 같은 요약만 둔다.

### 태그 허브

- **D-07:** 사용자가 명시한 대로 태그 허브는 통합 검색이 아니라 태그 중심 조회 전용 탭이다.
- **D-08:** 1차 태그 부여 대상은 문서이며, WBS/TODO 직접 태그는 후속 확장으로 미룬다.
- **D-09:** `Tags` 탭은 프로젝트 허브 탭에 추가한다.

### 개인 TODO 공개 경계

- **D-10:** 개인 TODO는 기본적으로 작성자 전용 비공개다.
- **D-11:** 특정 TODO가 WBS에 연결되면 제목, 상태, 진척률, 일정 메타데이터 등 일정 관리에 필요한 최소 정보만 공유 대상으로 승격한다.
- **D-12:** WBS에 연결되지 않은 TODO는 타인에게 노출하지 않는다.

### 구현 순서

- **D-13:** 1차 구현 순서는 `작업-문서 연결 + 태그 기초` → `댓글/히스토리` → `개인 TODO` → `WBS/Gantt 통합 표시` 순서로 진행한다.
- **D-14:** board comment에 따라 이후 관리는 기존 `plan/` 단독 문서가 아니라 `.planning/phases/08.1-*` 를 소스 오브 트루스로 사용한다.

</decisions>

## 구체 포인트

- WBS를 문서 저장소로 비대하게 만들지 않는다.
- `Tags` 탭은 문서 허브와 경쟁하는 탭이 아니라 문서 탐색의 다른 진입점이다.
- 개인 TODO는 독립 작업 공간이지만, WBS에 연결되면 PM/PL의 일정 리스크 관찰 대상이 된다.
