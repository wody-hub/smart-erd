# 13-01-PLAN: Detailed Provider Read Context and Grounding Prompt Guardrails

## Goal

Make AI chat answer detailed project-management questions from authorized backend read rows instead of count-only summaries.

## Tasks

1. Update `AiReadContextService` to serialize capped detailed rows for:
   - WBS items
   - Milestones
   - Project issues
   - Current-user TODOs
   - WBS comments and activities
2. Preserve member TODO aggregate-only behavior.
3. Update provider prompts so read rows are treated as data and missing/capped detail is reported honestly.
4. Add backend tests for detailed rows, caps, and privacy exclusions.
5. Run targeted and broad backend verification.
6. Run code review after implementation.

## Verification

- `./gradlew test --tests "com.smarterd.application.ai.chat.AiReadContextServiceTest"`
- `./gradlew test --tests "com.smarterd.application.ai.*" --tests "com.smarterd.application.ai.chat.*" --tests "com.smarterd.api.ai.*"`
- `./gradlew test`

## Risks

- Provider context can grow too large if row caps are not enforced.
- Detailed rows can accidentally expose login IDs or private TODO data.
- History collection can create extra service calls; cap WBS traversal before fetching history.
