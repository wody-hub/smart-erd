**문제:** 현재 `applySectionUpdate(doc, sectionText, startOffset, endOffset, origin)`는 발신 측의 절대 offset을 그대로 사용한다. 동시 편집 시 앞 section 길이가 변경되면 수신 측의 Y.Text body에서 offset이 밀려 잘못된 범위에 diff가 적용된다.

**수정 1 — `markdown-yjs-document-adapter.ts`의 `applySectionUpdate` 시그니처 변경:**

기존:
```typescript
applySectionUpdate(doc: Y.Doc, sectionText: string, startOffset: number, endOffset: number, origin: unknown): void
```

변경:
```typescript
applySectionUpdate(doc: Y.Doc, sectionId: string, sectionText: string, origin: unknown): void
```

메서드 본문:
1. `import { computeSectionBoundaries } from '@/lib/markdown-section-index';` 추가
2. `const bodyText = this.getBodyText(doc);`
3. `const currentBody = bodyText.toString();`
4. `const boundaries = computeSectionBoundaries(currentBody);`
5. `const target = boundaries.find(b => b.id === sectionId);`
6. `if (!target) return;` — section이 이미 삭제된 경우 무시
7. `const currentSection = currentBody.slice(target.startOffset, target.endOffset);`
8. `if (currentSection === sectionText) return;` — 동일하면 skip
9. diff-match-patch 로직은 기존과 동일하되 `startOffset`을 `target.startOffset`으로 사용

## Review Feedback (Gemini)

### [LOW] Monaco 커서 연동 `activeSectionId`

**우려:** 현재 `activeSectionId`는 `setEditorBuffer` 호출 시점(사용자가 타이핑할 때)에만 갱신된다. 사용자가 타이핑 없이 커서만 이동하면 `activeSectionId`가 업데이트되지 않아, 원격 변경의 자동 수락 판단이 부정확해질 수 있다.

**제안:** Monaco `onDidChangeCursorPosition` 이벤트에도 연동하여 현재 사용자가 보고 있는 섹션을 실시간으로 추적하면 자동 수락 UX가 개선된다.

**판정: Deferred -- 향후 최적화**

이유:
- 현재 구현(편집 시점 기반 activeSectionId)은 핵심 시나리오를 커버한다: 사용자가 특정 섹션을 편집 중일 때 해당 섹션의 원격 변경만 배너를 표시
- 커서만 이동하고 편집하지 않는 상태에서 원격 변경이 오는 경우는 edge case이며, 이 경우 배너가 표시되더라도(false positive) 사용자가 수동 수락할 수 있으므로 기능적으로 문제없음
- Monaco `onDidChangeCursorPosition`은 매우 높은 빈도로 발생하므로, throttle + boundary 계산 비용을 고려해야 함
- Phase 2 이후 UX 개선 항목으로 적합 (성능 프로파일링 후 판단)
