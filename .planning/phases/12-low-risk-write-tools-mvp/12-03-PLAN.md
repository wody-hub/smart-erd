## Tasks

1. Add `TodoCreateActionExecutor` for `todo.create` supporting `title`, `description`, `status`, `priority`, `targetDate`, `progressRate`, and optional `linkedWbsItemId`.
2. Add `TodoUpdateActionExecutor` for `todo.update`; load current owned TODO, check optional stale values, merge allowlisted fields, then call `updateProjectTodo(...)`.
3. Preserve requester ownership by using `ProjectTodoService` only; never accept an owner id from payload.
4. Exclude TODO delete, document linking, WBS link/unlink update, cross-user TODO mutation, bulk update, shell, SQL, arbitrary API, and filesystem actions.
5. Add positive and negative non-mutation tests.

## Acceptance Criteria

- Approving `todo.create` creates a TODO owned by the approving/requesting user.
- Approving `todo.update` can update only the requester-owned TODO.
- Unknown fields, stale fields, invalid dates/enums/progress, wrong target, and access denial do not mutate.

## Threat Model

| Threat | Mitigation | Verification |
|--------|------------|--------------|
| Private TODO access leak | Existing `findOwnedTodo` policy is reused. | executor tests |
| Cross-user mutation | No owner field accepted; login id comes from approval actor. | payload tests |
| Stale mutation | Compare before values against `getProjectTodo(...)`. | stale tests |
| Destructive action | No delete/link/unlink executor registered. | registry/service tests |
