## Tasks

1. Add `AiActionPayloadReader` to parse `sanitizedPayloadJson` into safe domain values.
2. Support canonical field items with `name`, optional `beforeValue`, and optional `afterValue`/`value`.
3. Add allowlist helpers that fail closed on unknown fields, bad enum/date/number values, blank required text, and stale `beforeValue`.
4. Add `AiActionExecutionResultWriter` that emits compact safe JSON with `actionType`, `resourceType`, `resourceId`, `targetLabel`, `status`, and `summary`.
5. Add `AiActionProposalView.Result` and map proposal `resultJson` into API/history DTOs without exposing raw result JSON.
6. Replace the Phase 11 no-executor baseline test with a registry/executable test that still proves unsupported types reject without mutation.

## Acceptance Criteria

- Payload reader tests cover nested sanitized fields, unknown field rejection, enum parsing, date parsing, numeric parsing, and stale mismatch.
- Proposal API responses include a typed `result` object for executed proposals.
- Proposal/history responses never include `resultJson`, `payload`, `sanitizedPayloadJson`, provider output, prompt, stack trace, token, cookie, or env values.

## Threat Model

| Threat | Mitigation | Verification |
|--------|------------|--------------|
| Payload tampering | Parse only persisted sanitized JSON and canonical field names. | `AiActionPayloadReaderTest` |
| Information disclosure | Expose typed result metadata, not raw JSON. | DTO tests and raw-key scan |
| Stale mutation | Shared before/current comparison helper. | stale mismatch tests |
| Repudiation | Keep proposal terminal result available to audit/history. | service/history tests |
