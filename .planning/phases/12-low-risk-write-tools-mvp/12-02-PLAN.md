## Tasks

1. Add `ProjectIssueService.getProjectIssue(...)` for service-bound current-state reads.
2. Add `IssueCreateActionExecutor` for `issue.create` supporting `title`, `description`, `priority`, and `assigneeUserId`.
3. Add `IssueUpdateActionExecutor` for `issue.update`; load current issue, check optional stale `beforeValue`, merge allowlisted fields, then call `updateProjectIssue(...)`.
4. Exclude issue delete, bulk update, status transition, membership, SQL, shell, arbitrary API, and filesystem actions.
5. Add positive create/update tests and negative tests for stale value, unknown field, missing required title, wrong target, and service access denial.

## Acceptance Criteria

- Approving `issue.create` creates exactly one issue through `ProjectIssueService`.
- Approving `issue.update` updates only allowlisted fields and preserves existing values for omitted fields.
- Invalid/stale/unauthorized issue proposals transition terminal without changing issue state.

## Threat Model

| Threat | Mitigation | Verification |
|--------|------------|--------------|
| Authorization bypass | Executor calls `ProjectIssueService` with approver login and proposal team/project ids. | executor tests |
| Stale mutation | Compare optional before values against `getProjectIssue(...)`. | stale test |
| Tampering | Reject unknown fields and wrong target type. | unknown/wrong target tests |
| Destructive action | No delete/status/bulk executor registered. | registry/service tests |
