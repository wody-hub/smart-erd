<objective>
Create the backend AI gateway contract before any local Codex process code is added. The result is a safe Spring HTTP/application/domain skeleton with Noop provider support, provider status, synchronous execute response, execution status lookup, cancel semantics, output validation, action-draft safety checks, and metadata-only audit persistence.

This plan intentionally does not implement `codex exec`, rich read tools, chat UI, approval UI, or real write execution.
</objective>

<threat_model>

| Threat | Mitigation | Verification |
|--------|------------|--------------|
| Cross-project or cross-user AI execution | Use `ProjectContextLoader` before provider invocation; store `requestedBy`, `teamId`, and `projectId` in registry; scope status/cancel lookup | MVC/application tests for invalid team, invalid project, cross-user status lookup, and cross-user cancel denial |
| Credential or prompt leakage | Audit service persists metadata-only fields; response DTOs exclude raw prompt/context/stdout/stderr; provider errors are redacted | Audit service tests assert forbidden fields are absent and redacted error values are stored |
| Invalid provider output becoming trusted | `ProviderOutputValidator` parses JSON and Bean Validation DTOs; no raw text fallback | Validator tests for invalid JSON, missing fields, invalid error object, invalid actions |
| Unsafe future action proposals | `ActionDraftValidator` rejects delete/destructive/bulk destructive actions and enforces approval/risk constraints | Validator tests for destructive, delete, bulk destructive, missing `requiresApproval`, and unknown unsupported draft behavior |
| Lifecycle race creates conflicting terminal state | Registry uses atomic terminal transition; first terminal state wins | Concurrency tests for cancel/timeout/success race and repeated cancel |

</threat_model>
