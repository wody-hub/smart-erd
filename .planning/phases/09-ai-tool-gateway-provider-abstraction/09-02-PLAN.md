<objective>
Add the first real provider implementation: a local Spring backend adapter that invokes `codex exec` non-interactively through a hardened process runner and returns only structured JSON to the already-created gateway.

This plan keeps Codex execution behind the `AiProvider` port and does not add rich read tools, app chat UI, approval UI, hosted providers, or automatic retry.
</objective>

<threat_model>

| Threat | Mitigation | Verification |
|--------|------------|--------------|
| Shell injection or arbitrary command execution | Use `ProcessBuilder(List<String>)` with a fixed executable and fixed subcommand/flags; never `/bin/sh -c` or interpolated command strings | Command builder tests assert argv array content and no shell executable |
| Local file or repository mutation | Run in fresh temp cwd with Codex `workspace-write` scoped to temp directory | Runner tests assert `--cd` temp path and no Smart-ERD repo cwd |
| Interactive approval prompt stalls or grants unintended power | Require approval policy `never` through supported CLI/config; fail closed if unsupported | Runner/config tests verify approval flag/config or unsupported-environment failure |
| Secret leakage through child environment | Build allowlisted env from scratch; exclude request, JWT, datasource, `SMART_ERD_*`, `SPRING_*`, and arbitrary host env | Env filtering tests inject forbidden values and assert child env does not contain them |
| Raw stdout/stderr leak | Only stdout JSON is passed to validator; controller/audit receive redacted metadata and typed provider errors | Provider tests assert raw stderr/stdout are not returned or audited |
| Process leak on timeout/cancel | Track `ProcessHandle`; destroy forcibly after graceful timeout window | Fake process tests cover timeout and cancel kill behavior |

</threat_model>
