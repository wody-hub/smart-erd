# 04. 화면 흐름 및 산출물

## 1. 화면 흐름 정의

### 화면 간 연결

화면기획의 핵심 산출물 중 하나는 **화면 흐름도**다. 사용자가 어떤 동작을 하면 어떤 화면으로 이동하는지를 정의한다.

```text
📄 로그인 화면
  ├─ "로그인 버튼 클릭" ──────► 📄 메인 대시보드
  └─ "회원가입 링크 클릭" ────► 📄 회원가입 화면

📄 메인 대시보드
  ├─ "사용자 메뉴 클릭" ──────► 📄 사용자 관리 화면
  ├─ "주문 메뉴 클릭" ────────► 📄 주문 관리 화면
  └─ "프로필 아이콘 클릭" ────► 📄 프로필 설정 화면

📄 사용자 관리 화면
  ├─ "행 클릭" ───────────────► 📄 사용자 상세 화면
  └─ "추가 버튼 클릭" ────────► 📄 사용자 등록 화면
```

### 흐름도 뷰

화면 흐름을 시각적으로 보여주는 별도 뷰다.

```text
┌──────────┐    로그인 성공    ┌──────────────┐
│  로그인    │ ──────────────► │  메인 대시보드  │
└──────────┘                  └──────┬───────┘
      │                              │
  회원가입 클릭              ┌────────┼────────┐
      │                     │        │        │
      ▼                     ▼        ▼        ▼
┌──────────┐         ┌─────────┐ ┌────────┐ ┌────────┐
│  회원가입  │         │ 사용자   │ │  주문   │ │ 프로필  │
└──────────┘         │  관리    │ │  관리   │ │  설정   │
                     └────┬────┘ └────────┘ └────────┘
                          │
                    ┌─────┴─────┐
                    ▼           ▼
              ┌─────────┐ ┌─────────┐
              │ 사용자   │ │ 사용자   │
              │  상세    │ │  등록    │
              └─────────┘ └─────────┘
```

이 흐름도는 `ScreenLink` 데이터를 기반으로 자동 생성한다. dagre 레이아웃 엔진(ERD에서 이미 사용 중)을 재사용하여 자동 배치한다.

### 흐름도 데이터 모델

```typescript
interface ScreenLink {
  id: string;
  sourceScreenId: string;        // 출발 화면
  targetScreenId: string;        // 도착 화면
  triggerDescription: string;    // "로그인 버튼 클릭"
  sourceAnchor?: Position;       // 출발 화면 내 특정 위치 (선택)
  condition?: string;            // "인증 성공 시" (선택)
  linkStyle: 'default' | 'conditional' | 'error';  // 흐름 유형
}
```

## 2. 주석 시스템

### 기획 메모

화면기획 산출물에서 중요한 것은 **기획 의도와 조건을 전달하는 주석**이다.

```text
┌────────────────────────────────────┐
│ 📄 사용자 관리 화면                  │
│                                    │
│  ◇ GNB                            │
│  ┌──────────────────────┐          │
│  │ ◇ 검색 폼            │          │
│  ├──────────────────────┤          │
│  │ ◇ 목록 테이블         │  ← ─ ─ ─ ┤ 📝 "ADMIN 역할만 삭제 버튼 노출"
│  │                      │          │
│  └──────────────────────┘          │
│                            ← ─ ─ ─ ┤ 📝 "50건 초과 시 페이지네이션 표시"
│                                    │
└────────────────────────────────────┘
```

### 주석 유형

| 색상 | 용도 | 예시 |
|---|---|---|
| 노란색 (yellow) | 기능 설명 | "이 영역은 검색 조건에 따라 필터링됨" |
| 파란색 (blue) | 디자인 참고 | "디자인 시스템의 DataTable 컴포넌트 적용" |
| 빨간색 (red) | 주의사항/제약 | "API 응답 3초 초과 시 타임아웃 에러 처리 필요" |
| 초록색 (green) | 확인 완료 | "PM 확인 완료 — 2026-03-25" |

### 주석과 요소 연결

주석은 특정 인스턴스나 요소에 연결할 수 있다.

```text
연결 없음:
  → 화면 전체에 대한 메모 (자유 위치)

연결 있음:
  → 특정 인스턴스를 가리키는 선 + 메모
  → 연결된 요소가 이동하면 주석도 따라감
  → 연결된 요소가 삭제되면 주석은 유지 (연결만 해제)
```

## 3. 산출물 내보내기

### 내보내기 형식

| 형식 | 용도 | 내용 |
|---|---|---|
| PNG | 개별 화면 캡처 | 화면 단위 이미지 + 주석 포함 |
| PDF | 전체 기획서 문서 | 목차 + 화면 목록 + 흐름도 + 화면별 상세 |
| JSON | 데이터 교환 | 전체 도메인 모델 직렬화 (가져오기/내보내기) |

### PDF 산출물 구조

```text
[표지]
  프로젝트명: Smart-ERD
  문서명: 사용자 관리 화면기획서
  작성일: 2026-03-25
  버전: 1.0

[목차]
  1. 화면 목록
  2. 화면 흐름도
  3. 컴포넌트 라이브러리
  4. 화면별 상세

[1. 화면 목록]
  | # | 화면명 | 설명 | 컴포넌트 수 |
  |---|--------|------|------------|
  | 1 | 로그인 | ... | 3 |
  | 2 | 메인 대시보드 | ... | 7 |
  | ... |

[2. 화면 흐름도]
  (자동 생성된 흐름도 이미지)

[3. 컴포넌트 라이브러리]
  카테고리별 마스터 컴포넌트 목록 + 속성 정의 + 배리언트 미리보기

[4. 화면별 상세]
  각 화면마다:
    - 화면 캡처 이미지
    - 주석 목록
    - 사용된 컴포넌트 인스턴스 목록
    - 화면에서 나가는 흐름 목록
```

### PNG 내보내기 기술 방식

```text
방식: html-to-image (dom-to-image 후속)
  1. 화면의 DOM을 이미지로 변환
  2. 주석 레이어를 포함하여 캡처
  3. 배경색과 크기를 화면 설정에 맞춤
  4. 고해상도 옵션 (2x, 3x)

대안: Canvas API 직접 렌더링
  - DOM 기반보다 정확한 결과
  - 하지만 구현 비용이 높음
  - 1단계는 html-to-image, 품질 이슈 시 Canvas API로 전환
```

### PDF 내보내기 기술 방식

```text
방식: jsPDF + html-to-image 조합
  1. 각 화면을 PNG로 캡처
  2. 흐름도를 PNG로 캡처
  3. jsPDF로 페이지 레이아웃 구성
  4. 이미지 삽입 + 텍스트 메타데이터 추가
  5. 목차 자동 생성

대안: Puppeteer 서버사이드 렌더링
  - 더 정확한 PDF 품질
  - 백엔드 서비스 필요
  - 2단계 이후 고려
```

## 4. 내장 프리셋 컴포넌트

처음부터 빈 라이브러리에서 시작하면 사용성이 낮다. 기본 제공 프리셋 컴포넌트를 포함한다.

### 프리셋 카테고리

```text
📁 레이아웃
  ├─ ◆ GNB (상단 네비게이션)
  ├─ ◆ LNB (좌측 메뉴)
  ├─ ◆ 탭 메뉴
  └─ ◆ 브레드크럼

📁 표
  ├─ ◆ 데이터 테이블 (페이지네이션 포함)
  ├─ ◆ 심플 테이블 (페이지네이션 없음)
  └─ ◆ 카드 리스트

📁 폼
  ├─ ◆ 로그인 폼
  ├─ ◆ 검색 바
  ├─ ◆ 필터 패널
  └─ ◆ 등록/수정 폼

📁 입력
  ├─ ◆ 텍스트 입력
  ├─ ◆ 드롭다운
  ├─ ◆ 체크박스 그룹
  ├─ ◆ 라디오 그룹
  └─ ◆ 날짜 선택기

📁 피드백
  ├─ ◆ 알림 토스트
  ├─ ◆ 확인 다이얼로그
  ├─ ◆ 로딩 스피너
  └─ ◆ 빈 상태 (Empty State)

📁 버튼
  ├─ ◆ 기본 버튼 (배리언트: 주요/보조/위험)
  ├─ ◆ 아이콘 버튼
  └─ ◆ 버튼 그룹
```

프리셋은 문서 생성 시 라이브러리에 자동 포함된다. 사용자는 프리셋을 수정/삭제/추가할 수 있다.

### 프리셋 초기화 메커니즘

```text
프리셋 초기화 시점:
  새 화면기획 문서 생성 시 (DocumentSession 초기 진입)

초기화 주체:
  ScreenSpecPlugin의 MutationPolicy 내부 initializer

초기화 흐름:
  1. DocumentSession이 빈 문서로 최초 진입
  2. DocumentStore의 공유 상태가 비어있음을 감지
  3. MutationPolicy.initializeDocument() 호출
  4. 프리셋 MasterComponent 정의를 ComponentLibrary에 일괄 추가
  5. 기본 카테고리(레이아웃, 표, 폼, 입력, 피드백, 버튼) 생성
  6. GlobalStyleSet에 기본 화면 크기 프리셋과 색상 토큰 설정

프리셋 데이터 소스:
  ScreenSpecPlugin 내부에 정적으로 정의된 preset.ts 모듈
  → 코어에는 프리셋 개념이 존재하지 않음 (플러그인 내부 규칙)

기존 문서 진입 시:
  ComponentLibrary가 이미 존재하면 초기화를 건너뜀
```

## 5. 화면 크기 프리셋

```text
| 프리셋 | 크기 | 용도 |
|--------|------|------|
| 데스크톱 (기본) | 1440 × 900 | 관리자 화면, 대시보드 |
| 데스크톱 (넓은) | 1920 × 1080 | 모니터링, 분석 화면 |
| 태블릿 | 768 × 1024 | 태블릿 화면 |
| 모바일 | 375 × 812 | 모바일 화면 |
| 커스텀 | 사용자 지정 | 특수 용도 |
```

같은 화면을 여러 크기로 복제하여 반응형 기획도 가능하다.
