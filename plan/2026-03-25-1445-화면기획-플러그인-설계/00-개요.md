# 화면기획 플러그인 설계

> 작성일: 2026-03-25
> 상태: 초안

## 이 문서의 목적

협업 문서 플랫폼 코어 위에 올라가는 두 번째 플러그인인 `ScreenSpecPlugin`을 설계한다.

ERD 플러그인이 테이블/컬럼/엣지를 다루듯이, 화면기획 플러그인은 **컴포넌트/인스턴스/화면**을 다룬다. 이 플러그인이 코어 수정 없이 올라갈 수 있어야 협업 플랫폼 아키텍처의 재사용성이 검증된다.

## 핵심 기획 의도

이 도구는 Figma처럼 자유로운 디자인 도구가 아니다. 목표는 아래와 같다.

1. **PPT 산출물용 화면기획 환경** — 기획자가 화면 레이아웃과 흐름을 정의하고, 이를 산출물(PNG/PDF)로 내보낼 수 있다.
2. **컴포넌트 재사용 시스템** — 미리 컴포넌트를 정의하고, 여러 화면에서 인스턴스로 배치한다.
3. **수정 시 전체 반영** — 마스터 컴포넌트를 수정하면 해당 컴포넌트를 사용하는 모든 화면의 인스턴스에 자동 반영된다.
4. **실시간 협업** — ERD와 동일한 코어 인프라(Yjs, ScopeLock, Presence)를 그대로 사용한다.

## Figma 컴포넌트 시스템과의 대응

| Figma 개념 | 우리 용어 | 설명 |
|---|---|---|
| Main Component (◆) | MasterComponent | 원본 컴포넌트 정의 |
| Instance (◇) | ComponentInstance | 화면에 배치된 참조 사본 |
| Override | Override | 인스턴스별 개별 속성 변경 |
| Variant | Variant | 컴포넌트의 상태별 변형 (기본, 비활성, 로딩 등) |
| Instance Swap | Slot | 교체 가능한 자식 영역 |
| Detach | Detach | 인스턴스를 마스터에서 분리 |

## 범위

### 이번 문서가 다루는 범위

- 화면기획 플러그인의 도메인 모델 (컴포넌트, 인스턴스, 화면, 주석)
- Figma 컴포넌트 시스템 매핑 (마스터/인스턴스/오버라이드/배리언트/슬롯/분리)
- 플랫폼 코어와의 통합 계약 (Plugin SPI 구현)
- 화면 간 흐름 정의 구조
- 산출물 내보내기 전략
- 단계별 구현 로드맵

### 이번 문서가 다루지 않는 범위

- 실제 UI 디자인 (Figma 수준의 벡터/이미지 편집)
- 프로토타이핑 / 인터랙션 정의
- 코드 생성 (화면기획 → 프론트엔드 코드)
- 코어 아키텍처 변경 (코어는 이미 설계 완료)

## 설계 원칙

1. **코어 수정 제로** — 이 플러그인은 기존 코어 계약만으로 동작해야 한다. 코어에 화면기획 전용 코드가 들어가면 설계 실패다.
2. **컴포넌트가 핵심 가치** — 단순 도형 배치가 아니라 "컴포넌트 정의 → 인스턴스 재사용 → 수정 시 전체 반영"이 이 도구의 존재 이유다.
3. **산출물 품질 우선** — 실시간 편집보다 최종 산출물(화면 목록 문서)의 가독성과 완성도가 더 중요하다.
4. **점진적 복잡도** — 1단계는 기본 배치만, 2단계에서 컴포넌트 시스템, 3단계에서 내보내기. 한 번에 전부 만들지 않는다.
