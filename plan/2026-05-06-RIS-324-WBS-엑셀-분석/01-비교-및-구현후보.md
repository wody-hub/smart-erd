# RIS-324 엑셀 기능 vs 현재 WBS/간트 비교

## 목적
- 앞서 도출한 엑셀 WBS 기능 목록을 기준으로 현재 저장소의 WBS/간트 구현 범위를 비교한다.
- 차이만 찾는 데서 끝내지 않고, 현재 구조 위에서 실제로 구현 가능한 기능 후보를 추린다.

## 비교 기준
- 엑셀 기준 기능: `00-분석.md`에서 정리한 25개 기능
- 현재 제품 기준 구현 범위:
  - WBS API / 엔티티
  - WBS authoring UI
  - WBS detail panel
  - 간트 시각화 및 dependency 연동

## 현재 제품에서 이미 구현된 기능

### 1. 계층형 WBS 작성/편집
- 구현 상태: `구현됨`
- 근거:
  - 트리 구조 WBS 조회/생성/수정/삭제/재정렬 API 존재
  - drag/drop, indent/outdent, inline create, move dialog 제공
- 해석:
  - 엑셀의 계층형 WBS 작성 기능은 현재 제품에서도 충분히 구현돼 있다.

### 2. 계획 시작일/완료일 관리
- 구현 상태: `구현됨`
- 근거:
  - `WbsItem`에 `startDate`, `endDate` 존재
  - WBS 행 인라인 편집 및 간트 drag 편집 지원
- 해석:
  - 엑셀의 기본 일정 입력/수정 기능은 현재 제품에 있다.

### 3. 담당자 지정
- 구현 상태: `구현됨`
- 근거:
  - `assigneeUserId`, `assigneeName` 필드와 인라인 편집 UI 존재

### 4. 진척률 입력
- 구현 상태: `구현됨`
- 근거:
  - `progressRate` 필드와 인라인 편집 UI 존재
  - 간트 그리드에서도 진행률 표시

### 5. 예상 공수 입력
- 구현 상태: `부분 구현`
- 근거:
  - `estimatedMm` 필드가 존재하고 WBS에서 입력 가능
- 차이:
  - 엑셀은 Man-Day 계산/집계 중심이다.
  - 현재 제품은 `예상 M/M` 입력은 있으나 자동 계산/리포팅은 없다.

### 6. 간트 시각화
- 구현 상태: `구현됨`
- 근거:
  - WBS + 마일스톤 + dependency를 간트 차트로 렌더링
  - 간트에서 일정 drag 편집 후 WBS 날짜 저장 가능

### 7. 의존관계(FS/SS/FF/SF)
- 구현 상태: `구현됨`
- 근거:
  - dependency 타입 4종 지원
  - 생성/수정/삭제 API 존재
  - cycle 검증 존재
  - dependency shift preview/apply 기능 존재

### 8. 문서/산출물 연결
- 구현 상태: `부분 구현`
- 근거:
  - WBS 문서 연결/해제, 태그 조회, linked documents UI 존재
- 차이:
  - 엑셀은 파일 경로/산출물 열기 성격이 강하다.
  - 현재 제품은 내부 문서 링크 중심이고, 범용 산출물 필드나 파일 경로 개념은 없다.

### 9. 템플릿/대량 생성/서브트리 복제
- 구현 상태: `엑셀 대비 확장 구현`
- 근거:
  - subtree duplicate
  - template save / instantiate
  - bulk create
- 해석:
  - 이 부분은 엑셀보다 현재 제품이 더 강하다.

### 10. 활동 로그/댓글
- 구현 상태: `엑셀 대비 확장 구현`
- 근거:
  - comments, activities, document link history 존재
- 해석:
  - 엑셀에는 없는 협업 기능이다.

### 11. 마일스톤 연결 및 rolling-wave 간트 요약
- 구현 상태: `엑셀 대비 확장 구현`
- 근거:
  - WBS item에 milestone 연결
  - 간트 adapter에서 milestone flow 및 wave summary 생성
- 해석:
  - 엑셀 기반 WBS보다 제품 쪽이 PM 운영 기능은 더 앞서 있다.

## 현재 제품에 없는 기능

### 1. 실제 시작일 / 실제 완료일 분리 관리
- 구현 상태: `없음`
- 현재 상태:
  - WBS 엔티티와 API에는 `actualStartDate`, `actualEndDate`가 없다.
- 영향:
  - 계획 일정과 실적 일정을 분리해서 관리할 수 없다.
  - 일정변경 관리, 지연 판단, 계획 대비 편차를 정확히 표시하기 어렵다.

### 2. 계획 진척률 자동 계산
- 구현 상태: `없음`
- 현재 상태:
  - `progressRate`는 수동 입력이다.
  - 기준일 기준 계획상 몇 % 진행되어야 하는지 계산하는 필드/로직이 없다.

### 3. 실제 작업량 / 계획 작업량 자동 계산
- 구현 상태: `없음`
- 현재 상태:
  - `estimatedMm`는 저장만 하고, 일정/담당자/캘린더를 기반으로 자동 계산하지 않는다.

### 4. 공휴일/휴무일 캘린더
- 구현 상태: `없음`
- 현재 상태:
  - 프로젝트별 non-working day, custom calendar, 주 시작요일 같은 개념이 없다.
  - 간트 기간 계산도 단순 시작/종료일 중심이다.

### 5. 주간 누적 진척 분석 리포트
- 구현 상태: `없음`
- 현재 상태:
  - Progress / AnalysisReport 성격의 프로젝트 진척 리포트 시트나 화면이 없다.

### 6. 리소스별 workload 데이터셋 / 부하 리포트
- 구현 상태: `없음`
- 현재 상태:
  - 담당자별 `estimatedMm` 입력은 가능하지만, 주간/월간 workload 뷰는 없다.

### 7. 일정변경 관리(베이스라인 vs 실제)
- 구현 상태: `없음`
- 현재 상태:
  - baseline date, actual date, variance, delay reason 같은 운영 필드가 없다.

### 8. 외부 Excel/XLSM WBS 가져오기
- 구현 상태: `없음`
- 현재 상태:
  - bulk create는 텍스트 outline 입력 기반이다.
  - Excel 업로드/매핑 기반 import는 없다.

### 9. Outlook 일정/작업 연동
- 구현 상태: `없음`
- 현재 상태:
  - 외부 캘린더/업무도구 연동 자체가 없다.

## 기능 비교 요약

### 이미 커버하는 영역
1. WBS 계층 작성
2. 계획 일정 입력
3. 담당자 지정
4. 진척률 입력
5. 간트 시각화
6. 의존관계 관리
7. 문서 연결

### 제품이 더 앞서는 영역
1. 템플릿 저장/적용
2. 대량 생성
3. subtree 복제
4. 댓글/활동 로그
5. 마일스톤 연동
6. dependency shift preview/apply

### 제품이 부족한 영역
1. 계획 vs 실제 일정 분리
2. 자동 계획진척률 계산
3. 캘린더 기반 공수/기간 계산
4. workload/진척 분석 리포트
5. 베이스라인/변경관리
6. Excel import

## 실제 구현 가능한 기능 후보

### 우선순위 높음

#### 1. 실적 시작일 / 실적 종료일 / 일정 편차
- 구현 가능성: `높음`
- 이유:
  - 현재 `WbsItem`에 날짜 필드가 이미 있고, WBS/간트 UI도 날짜 편집 구조가 잡혀 있다.
  - 엔티티/API/폼/간트 표시만 확장하면 된다.
- 기대 효과:
  - 엑셀의 일정변경 관리 핵심을 제품에서도 재현 가능
  - 계획 대비 지연/선행 상태 표시 가능

#### 2. 계획 진척률 자동 계산 + 실적 대비 편차 표시
- 구현 가능성: `높음`
- 이유:
  - 현재도 `startDate`, `endDate`, `progressRate`가 있다.
  - 기준일(`today` 또는 프로젝트 기준일)만 추가하면 계산 가능하다.
- 기대 효과:
  - 엑셀 `계획 진척률(A)` / `실적 진척률(B)` / `차이(B-A)`에 가장 근접한 화면 제공 가능

#### 3. WBS/간트 지연 배지 및 편차 컬럼
- 구현 가능성: `높음`
- 이유:
  - 간트 쪽에 이미 milestone delayed 개념과 스타일링이 있다.
  - 동일 패턴으로 WBS task 지연 상태를 표시할 수 있다.
- 기대 효과:
  - 실무 사용성이 빠르게 올라간다.

#### 4. 담당자별 workload 집계 화면
- 구현 가능성: `높음`
- 이유:
  - 현재 `assigneeUserId`, `estimatedMm`, `startDate`, `endDate`가 있다.
  - 초기 버전은 단순 합계/기간 분산 방식으로도 구현 가능하다.
- 기대 효과:
  - 엑셀 `Workload` 시트의 핵심 가치를 제품에서 일부 대체 가능

### 우선순위 중간

#### 5. 프로젝트 캘린더(휴무일/공휴일) 관리
- 구현 가능성: `중간`
- 이유:
  - 신규 테이블/설정 UI/날짜 계산 로직이 필요하다.
  - 하지만 도메인이 명확하고 WBS 일정 계산과 자연스럽게 연결된다.
- 기대 효과:
  - 계획기간, 계획진척률, workload 계산의 정확도가 올라간다.

#### 6. 주간 진척 분석 리포트
- 구현 가능성: `중간`
- 이유:
  - 실제일정/계획진척률이 먼저 들어오면 계산 모델을 만들기 쉽다.
  - UI는 카드/테이블/차트로 확장 가능하다.
- 기대 효과:
  - 엑셀 `Progress`, `AnalysisReport` 대체 가능

#### 7. 베이스라인 스냅샷 / 일정변경 관리
- 구현 가능성: `중간`
- 이유:
  - 필드 추가 수준이 아니라 baseline snapshot 설계가 필요하다.
  - 그래도 현재 history/activity 구조와 잘 맞는다.
- 기대 효과:
  - “변경 전 계획”과 “현재 계획” 비교 가능

### 우선순위 낮음

#### 8. Excel 업로드 기반 WBS import
- 구현 가능성: `중간`
- 이유:
  - bulk create, template 구조가 있어 import 타겟은 이미 있다.
  - 다만 xlsm 파싱/매핑 UI/에러 처리까지 필요하다.
- 기대 효과:
  - 기존 엑셀 사용 조직의 전환 비용 감소

#### 9. Outlook 일정/작업 연동
- 구현 가능성: `낮음`
- 이유:
  - 외부 연동 범위가 크고 현재 핵심 WBS/간트 gap을 메우는 기능은 아니다.

## 추천 구현 순서
1. 실적 시작일 / 실적 종료일 / 일정 편차
2. 계획 진척률 자동 계산 / 편차 배지
3. 담당자별 workload 집계
4. 프로젝트 캘린더
5. 주간 진척 분석 리포트
6. 베이스라인/변경관리
7. Excel import

## 결론
- 현재 제품은 엑셀 대비 `협업형 WBS 운영`, `마일스톤`, `dependency`, `템플릿`, `문서 연결` 쪽은 이미 더 강하다.
- 반대로 엑셀의 강점이었던 `실적일정`, `캘린더`, `자동 공수/진척 계산`, `분석 리포트`는 아직 비어 있다.
- 따라서 다음 backlog는 새 기능을 무작정 넓히기보다, `계획 vs 실제`, `자동 계산`, `리포트` 3축을 채우는 방향이 가장 현실적이다.
