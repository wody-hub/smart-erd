# 가이드 페이지 QA 체크리스트 및 검증 시나리오

> 작성일: 2026-04-24
> 상태: RIS-208 가이드 페이지 검증 계획
> 대상 버전: v1.0 (가이드 페이지 1차 구현)

## 1. 검증 개요

본 문서는 Smart-ERD의 신규 '가이드 페이지(`/guide`)'의 기능 및 사용자 경험을 검증하기 위한 체크리스트와 시나리오를 정의한다. 가이드 페이지는 단순한 설명서가 아니라, 사용자의 현재 맥락에 맞춰 적절한 행동을 제안하고 작업 화면으로 빠르게 복귀시키는 '네비게이션 허브' 역할을 수행해야 한다.

## 3. 검증 시나리오

### 시나리오 1: 신규 사용자 온보딩 여정
**목적:** 처음 가입한 사용자가 가이드를 통해 첫 프로젝트와 문서를 성공적으로 생성하는지 검증

1. **로그인:** 신규 계정으로 로그인 (팀 0개 또는 프로젝트 0개 상태)
2. **진입:** `TeamsPage` 또는 `ProjectsPage`의 Empty State에서 '가이드 보기' 클릭
3. **확인:** '처음 시작하기' 섹션과 온보딩 체크리스트가 상단에 노출되는지 확인
4. **실행:** 가이드 내 '팀 만들기' 또는 '프로젝트 만들기' CTA 클릭
5. **결과:** 해당 생성 다이얼로그 또는 페이지로 정상 이동하는지 확인

### 시나리오 2: 작업 중 문제 해결 여정 (Deep Link)
**목적:** ERD 편집 중 DSL 문법 오류가 발생했을 때 가이드 페이지를 통해 해결책을 찾고 복귀하는지 검증

1. **작업:** ERD 에디터에서 고의로 DSL 문법 오류 발생
2. **진입:** 오류 가이드 패널 하단의 '상세 가이드에서 해결 방법 찾기' 링크 클릭
3. **확인:** `/guide#erd-dsl` 경로로 이동하며 해당 섹션이 화면 상단에 위치하는지 확인
4. **복귀:** 가이드 상단의 '에디터로 돌아가기' 버튼 클릭
5. **결과:** 이전에 편집 중이던 ERD 에디터 화면으로 상태 유지하며 복귀하는지 확인

### 시나리오 3: 기능 탐색 및 도구 전환 여정
**목적:** 숙련 사용자가 새로운 문서 타입(화면기획 등)을 도입하기 위해 가이드를 활용하는지 검증

1. **진입:** 프로젝트 허브(`DiagramsPage`) 헤더의 '가이드' 버튼 클릭
2. **탐색:** '작업별 가이드' 섹션에서 '화면기획(Screen Spec) 시작하기' 카드 확인
3. **비교:** '문서 타입 선택 가이드'를 통해 ERD와 Screen Spec의 차이점 이해
4. **전환:** 가이드 내 '새 화면기획 문서 만들기' CTA 클릭
5. **결과:** 문서 생성 다이얼로그가 열리며 'Screen Spec' 타입이 기본 선택되어 있는지 확인

## 4. 검증 환경 및 준비 사항

### 4.1 테스트 환경
- **URL:** `http://localhost:3000/guide` (로컬 개발 환경 기준)
- **대상 브라우저:** Chrome, Edge (최신 버전), Safari (macOS)
- **테마:** Paper, Graphite, Midnight (각 테마별 UI 가독성 점검)

### 4.2 테스트 데이터 준비
- **사용자 A:** 팀/프로젝트/문서가 전혀 없는 신규 사용자 (온보딩 검증용)
- **사용자 B:** 다수의 프로젝트와 문서를 보유한 기존 사용자 (맥락 복귀 및 탐색 검증용)
- **사용자 C:** 비인증 상태 (보호 라우트 검증용)

## 5. 결함 보고 양식

가이드 페이지 검증 중 발견된 결함은 아래 양식에 맞춰 이슈 트래커에 등록한다.

- **이슈 제목:** [Guide-QA] {섹션명} - {현상 요약}
- **재현 경로:** 진입 화면 -> 클릭한 버튼 -> 기대 결과 vs 실제 현상
- **심각도:** Block / Critical / Major / Minor
- **환경 정보:** 브라우저, 테마, 사용자 맥락(팀ID/프로젝트ID 유무)
