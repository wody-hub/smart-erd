# 백엔드 설계 — 사전 일괄 엑셀 다운로드

## 1. API 엔드포인트

```text
GET /api/teams/{teamId}/dictionary-sets/{setId}/download/excel
```

| 항목 | 값 |
|------|-----|
| 메서드 | GET |
| 경로 | `/api/teams/{teamId}/dictionary-sets/{setId}/download/excel` |
| 인증 | 필수 (Bearer JWT) |
| 응답 | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` |
| 파일명 | `{사전세트명}-dictionary-all.xlsx` |

> 기존 개별 다운로드(`/domains/download/excel`, `/terms/download/excel`, `/words/download/excel`)는 그대로 유지한다.
> 새 엔드포인트는 사전 세트 레벨(`/dictionary-sets/{setId}`)에 위치하여, 세트 전체를 한 파일로 내보내는 의미를 명확히 한다.

## 2. 컨트롤러 변경

### `DictionarySetController.java` — 엔드포인트 추가

```java
@Operation(summary = "사전 세트 전체 엑셀 다운로드 (단어 + 용어 + 도메인)")
@ApiResponse(
    responseCode = "200",
    description = "엑셀 파일",
    content = @Content(mediaType = "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet")
)
@GetMapping("/{setId}/download/excel")
public void downloadAllDictionary(
    @AuthenticationPrincipal Jwt jwt,
    @Parameter(description = "팀 ID") @PathVariable Long teamId,
    @Parameter(description = "사전 세트 ID") @PathVariable Long setId,
    HttpServletResponse response
) throws IOException {
    final var excelData = dictionarySetExportService.generateAllDictionary(
        jwt.getSubject(), teamId, setId
    );
    ExcelUtils.download(excelData, response);
}
```

의존성 주입:
```java
private final DictionarySetExportService dictionarySetExportService;
```

## 3. 서비스 신규 — `DictionarySetExportService.java`

```text
경로: domain/dictionary/service/DictionarySetExportService.java
```

### 설계 원칙

- 기존 3개 ExportService(`Domain`, `Term`, `Word`)는 **각각 단일 워크북**을 만든다.
- 일괄 다운로드는 **하나의 워크북에 3개 시트**를 넣어야 하므로, 기존 서비스를 그대로 재사용하면 워크북이 3개 생긴다.
- 해결: `DictionaryWorkbookExportSupport.createTemplate()`는 워크북을 인자로 받지 않고 내부에서 새로 만든다. 이를 **오버로드**하여 기존 워크북에 시트를 추가하는 버전을 만든다.

### 구현 방안

#### (1) `DictionaryWorkbookExportSupport` — 오버로드 추가

```java
/**
 * 기존 워크북에 시트를 추가하는 오버로드.
 */
static DictionaryWorkbookTemplate createTemplate(
    XSSFWorkbook workbook,   // ← 기존 워크북 전달
    String sheetName,
    String title,
    List<String> headers,
    int[] columnWidths
) {
    final var sheet = workbook.createSheet(sheetName);
    // 이하 스타일 생성 + 제목행 + 헤더행 + 동결 영역은 기존과 동일
    ...
    return new DictionaryWorkbookTemplate(workbook, sheet, bodyStyle, centeredBodyStyle);
}
```

기존 `createTemplate(sheetName, title, headers, columnWidths)` 메서드는 내부에서 `new XSSFWorkbook()`을 만들어 위 오버로드를 호출하도록 리팩토링한다.

```java
// 기존 시그니처 유지 (하위 호환)
static DictionaryWorkbookTemplate createTemplate(
    String sheetName, String title, List<String> headers, int[] columnWidths
) {
    return createTemplate(new XSSFWorkbook(), sheetName, title, headers, columnWidths);
}
```

#### (2) `DictionarySetExportService.java` — 핵심 로직

```java
@Service
@RequiredArgsConstructor
@Transactional(readOnly = true)
public class DictionarySetExportService {

    private final WordService wordService;

    private final DomainService domainService;
    private final DictionarySetService dictionarySetService;

     *
     * @param loginId 요청 사용자 로그인 ID
     * @param teamId  팀 ID
     * @param setId   사전 세트 ID

     */
    public ExcelData generateAllDictionary(String loginId, Long teamId, Long setId) {
        // 사전 세트명 조회 (파일명용)
        final var setName = dictionarySetService.getDictionarySetName(loginId, teamId, setId);

        writeTermSheet(workbook, loginId, teamId, setId);

        // 시트 3: 도메인 사전
        writeDomainSheet(workbook, loginId, teamId, setId);

        return new ExcelData(
            workbook,
            AppStringUtils.defaultIfBlank(setName, "dictionary-set") + "-dictionary-all"
```

### 시트 순서

| 순서 | 시트명 | 사유 |
|------|--------|------|
| 1 | 단어 사전 | 기본 구성 요소 (단어 → 용어 → 도메인 순으로 상위 개념) |
| 2 | 용어 사전 | 단어를 조합한 용어 |
| 3 | 도메인 사전 | 데이터 타입 정의 |

> 탭 순서(DictionaryWorkspace의 Words → Terms → Domains)와 일치시킨다.

## 4. 기존 ExportService와의 관계

```text
                    ┌─ DomainDictionaryExportService  (도메인 단독 다운로드, 기존 유지)
                    ├─ TermDictionaryExportService    (용어 단독 다운로드, 기존 유지)
                    ├─ WordDictionaryExportService    (단어 단독 다운로드, 기존 유지)
                    └─ DictionarySetExportService     (일괄 다운로드, 신규)
                          ├─ wordService.getWordsForExport()
                          ├─ termService.getTermsForExport()
                          └─ domainService.getDomainsForExport()

공통: DictionaryWorkbookExportSupport (스타일/템플릿)
```

- 기존 3개 ExportService는 건드리지 않는다.
- 신규 `DictionarySetExportService`는 각 도메인 Service의 `getXxxForExport()` 메서드를 직접 호출한다.
- 워크북 스타일/템플릿은 `DictionaryWorkbookExportSupport`를 공유한다.

## 5. 헤더/컬럼 상수 공유

현재 각 ExportService에 `HEADERS`, `COLUMN_WIDTHS` 상수가 private으로 선언되어 있다.
`DictionarySetExportService`에서 동일 상수가 필요하다.

### 방안: 상수를 `DictionaryWorkbookExportSupport`로 이동

```java
// DictionaryWorkbookExportSupport.java에 추가
static final List<String> WORD_HEADERS = List.of("논리명", "물리명", "설명");
static final int[] WORD_COLUMN_WIDTHS = { 28 * 256, 28 * 256, 52 * 256 };

static final List<String> TERM_HEADERS = List.of("논리명", "물리명", "도메인", "설명");
static final int[] TERM_COLUMN_WIDTHS = { 28 * 256, 28 * 256, 24 * 256, 48 * 256 };

static final List<String> DOMAIN_HEADERS = List.of(
    "도메인 그룹", "도메인명", "표준도메인명", "데이터 타입", "데이터 길이", "데이터 소수점 길이", "설명"
);
static final int[] DOMAIN_COLUMN_WIDTHS = {
    22 * 256, 22 * 256, 28 * 256, 18 * 256, 14 * 256, 18 * 256, 52 * 256

```

기존 3개 ExportService도 이 공유 상수를 참조하도록 리팩토링한다 (코드 중복 제거).

## 6. dictionarySetService.getDictionarySetName() 확인

파일명에 사전 세트명이 필요하다. 기존 개별 ExportService들은 각각 `exportResult.dictionarySetName()`에서 이름을 얻는다.
`DictionarySetExportService`에서는 `DictionarySetService`에서 직접 이름을 조회한다.

기존 `DictionarySetService`에 `getDictionarySetName()` 메서드가 없으면 추가한다:

```java
/**
 * 사전 세트 이름을 조회한다.
 *
 * @param loginId 요청 사용자 로그인 ID
 * @param teamId  팀 ID
 * @param setId   사전 세트 ID
 * @return 사전 세트 이름
 */
public String getDictionarySetName(String loginId, Long teamId, Long setId) {
    teamService.verifyMembership(loginId, teamId);
    final var set = dictionarySetRepository.findById(setId)
        .orElseThrow(() -> new EntityNotFoundException(MessageCode.NOT_FOUND_DICTIONARY_SET, setId));
    return set.getName();
}
```

## 7. 에러 처리

| 상황 | 예외 | HTTP |
|------|------|------|
| 팀 미소속 | `DomainAccessDeniedException` | 403 |
| 사전 세트 미존재 | `EntityNotFoundException` | 404 |
| 데이터 0건 | 빈 시트로 정상 응답 | 200 |

빈 데이터일 때는 헤더만 있는 빈 시트를 포함한 엑셀을 반환한다 (에러 아님).

## 8. 성능 고려

- 3개 조회를 순차 실행한다 (같은 트랜잭션 내에서 일관성 보장).
- 대량 데이터(10만건 이상)의 경우 메모리 부담이 있을 수 있으나, 기존 개별 다운로드도 동일 방식이므로 동일 수준의 부하.
- 필요시 향후 SXSSF(스트리밍 워크북)로 전환 가능하나, 현재는 XSSF로 충분.
