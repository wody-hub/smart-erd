# RIS-361 TODO 점검 결과

## 범위

- 현재 `My Tasks` TODO 기능이 일반적인 todo-list 패턴에 부합하는지 점검
- 현재 구현 위에 Kanban board view를 추가할 수 있는지 검토

## 현재 구현 요약

### 도메인 모델

- TODO는 `project_todos`에 저장되는 "프로젝트 컨텍스트 안의 개인 TODO"다.
- 핵심 필드는 `title`, `description`, `status`, `priority`, `targetDate`, `progressRate`, `linkedWbsItem`이다.
- 상태 값은 `TODO`, `IN_PROGRESS`, `DONE` 3단계다.
- TODO는 작성자(owner) 기준으로만 조회된다.

근거:

- `src/main/java/com/smarterd/domain/pm/todo/entity/ProjectTodo.java`
- `src/main/java/com/smarterd/domain/pm/todo/service/ProjectTodoService.java`
- `client/src/types/project-todo.ts`

### 화면 구조

- 좌측은 카드형 목록, 우측은 선택한 TODO 상세/편집 패널이다.
- 목록 카드에는 제목, 상태, 우선순위, 연결 WBS, 진척률, 목표일이 보인다.
- 상세 패널에서 제목/설명/상태/우선순위/목표일/진척률을 수정할 수 있다.
- TODO는 WBS에 연결될 수 있고, 연결된 문서는 `PRIVATE` 또는 `PROJECT_SHARED`로 노출 범위를 제어한다.
- WBS에 연결된 경우 해당 WBS에 연결된 다른 TODO 개수만 요약해서 보여준다.

근거:

- `client/src/components/project/ProjectTodoListSection.tsx`
- `client/src/components/project/ProjectTodoDetailPanel.tsx`
- `client/src/components/project/MyTasksTab.tsx`

## 현재 형태 평가

### 일반적인 todo-list 패턴과 맞는 점

- 최소 핵심 정보가 있다: 제목, 상태, 우선순위, 목표일, 진척률.
- 생성/수정/삭제 흐름이 명확하다.
- 상태가 단순 3단계라 개인 작업 관리용으로 이해하기 쉽다.
- 프로젝트 문서/WBS와 연결되는 점은 이 제품의 PM 컨텍스트와 잘 맞는다.

### 일반적인 todo-list 대비 부족한 점

- 목록 화면에 정렬, 필터, 검색이 없다.
- 상태 변경이 상세 패널 저장 중심이라, "빨리 상태만 바꾸는" 사용성은 약하다.
- 보드형/리스트형 전환이 없어 같은 데이터의 다른 시각화가 없다.
- 목록 자체는 카드 나열에 가깝고, "집중해야 할 작업을 빠르게 훑는" 압축 밀도는 낮다.
- WBS 연결 시 다른 공유 TODO는 개수만 보여주며, 협업 관점의 맥락은 제한적이다.

## Kanban view 가능 여부

결론:

- 구현 가능하다.
- 1차 범위에서는 백엔드 스키마 변경 없이 프런트엔드 중심으로 추가 가능하다.

### 가능한 이유

- 상태 축이 이미 3개(`TODO`, `IN_PROGRESS`, `DONE`)로 고정되어 있어 Kanban column으로 바로 매핑 가능하다.
- TODO 수정 API가 이미 존재하므로 카드 이동 시 `status`만 바꿔 저장하면 된다.
- 프로젝트 TODO 목록 API가 현재 사용자 소유 TODO를 모두 내려주므로, 프런트에서 상태별 그룹핑만 해도 첫 보드 버전이 성립한다.
- 클라이언트에 `@dnd-kit`가 이미 포함되어 있어 드래그 앤 드롭 기반 보드 구현을 새로 도입할 필요가 없다.

근거:

- `client/src/types/project-todo.ts`
- `src/main/java/com/smarterd/domain/pm/todo/service/ProjectTodoService.java`
- `client/src/components/project/MyTasksTab.tsx`
- `client/package.json`

### 1차 구현에서 필요한 일

- `My Tasks` 탭에 `List / Board` view toggle 추가
- 기존 TODO 목록 데이터를 상태별로 그룹핑
- 각 column에 TODO 카드 렌더링
- 카드 드래그 시 `status` 변경 + 기존 update API 호출
- 드래그 없이도 상태 변경 가능한 fallback 유지

### 예상되는 제약

- 현재 TODO에는 보드 내 사용자 정의 순서(order)가 없다.
- 따라서 1차 버전은 각 column 내부를 `createdAt desc` 또는 현재 목록 순서 기반으로 보여주는 수준이 적절하다.
- column 간 이동은 가능하지만, "같은 column 안에서 카드 순서를 사용자가 정해 유지"하는 기능은 별도 필드/저장 로직이 필요하다.
- 현재 update API가 전체 payload를 받으므로, 드래그 시 최신 편집 상태와 충돌하지 않도록 mutation payload 구성 주의가 필요하다.

## 권장 방향

### 제품 판단

- 현재 TODO 기능은 "프로젝트 안의 개인 작업 메모 + WBS/문서 연결"로는 충분히 자연스럽다.
- 다만 사용자가 작업을 한눈에 정리하는 관점에서는 리스트만 있는 현재 형태보다 보드가 더 직관적일 가능성이 높다.
- 따라서 기존 리스트를 제거하지 말고, 같은 데이터의 보조 view로 Kanban board를 추가하는 방향이 적합하다.

### 구현 순서

1. 프런트엔드에 `List / Board` 전환 추가
2. 기존 API 재사용으로 상태 이동 보드 구현
3. QA로 생성/수정/삭제/WBS 연결/문서 연결 회귀 검증
4. 필요 시 2차로 정렬/필터/검색 또는 column 내 순서 저장 검토

## 후속 작업 제안

- Child A: `My Tasks Kanban view 구현`
- Child B: `My Tasks list/board 회귀 QA`
