# 테이블 그룹 — 논리적 묶음 기능 기획서

> **상태**: 기획 완료 → 구현 설계 대기
> **작성일**: 2026-02-25
> **리뷰 반영**: v2 (아키텍처/개발/디자인 삼총사 리뷰 피드백 반영)

## 1. 배경 및 문제 정의

### 현재 상태

현재 "그룹"은 캔버스에 **시각적 사각 박스 영역**으로 표시되는 기능이다.

- `GroupNode` = React Flow 커스텀 노드 (크기 조절, 색상, 드래그 가능)
- 테이블과 그룹 간 **포함 관계 없음** — 순수 시각적 요소
- Yjs CRDT 동기화, 사이드바 표시, i18n 등 기반 인프라 완비

### 문제

사용자가 원하는 "그룹"은 시각적 영역이 아니라 **테이블의 논리적 묶음**이다.

- 수십 개 테이블이 하나의 다이어그램에 존재할 때, 특정 모듈/기능 단위로 **필터링하여 볼 수 없음**
- 관련 테이블만 모아서 보면서 관계를 파악하고 싶은 니즈

## 2. 요구사항 정의

### 핵심 요구사항

| # | 요구사항 | 우선순위 |
|---|---------|---------|
| R1 | 그룹은 테이블의 **논리적 묶음**이다 (캔버스에 사각 박스로 표시하지 않음) | 필수 |
| R2 | 그룹을 선택하면 해당 그룹의 테이블만 ERD 캔버스에 **필터링** 표시 | 필수 |
| R3 | 그룹 뷰에서 캔버스는 **readonly** (편집 불가) | 필수 |
| R4 | 하나의 테이블은 **여러 그룹에 참여** 가능 (N:M 관계) | 필수 |
| R5 | "전체 보기" 모드 유지 — 그룹 미선택 시 모든 테이블 표시 + 편집 가능 | 필수 |

### 부가 요구사항

| # | 요구사항 | 우선순위 |
|---|---------|---------|
| R6 | 그룹 CRUD (생성, 이름 변경, 삭제) | 필수 |
| R7 | 그룹에 테이블 추가/제거 | 필수 |
| R8 | 그룹 뷰에서 관련 엣지(FK)도 함께 필터링 | 필수 |
| R9 | Yjs 실시간 동기화 지원 | 필수 |
| R10 | 기존 시각적 그룹(`GroupNode`)과의 관계 정리 | 중요 |
| R11 | 테이블 삭제 시 모든 그룹에서 해당 테이블 참조 자동 제거 | 필수 |

## 3. 사용자 스토리

### US-1: 그룹 생성

> "ERD 사용자로서, 사이드바에서 논리적 그룹을 생성하여 관련 테이블을 묶고 싶다."

**인수 조건:**
- 사이드바 그룹 섹션에서 "+" 버튼으로 그룹 생성
- 생성 시 기본 이름 부여 ("Group 1", "Group 2", ...)
- 인라인 이름 변경 가능

### US-2: 그룹에 테이블 추가

> "ERD 사용자로서, 그룹에 원하는 테이블을 추가하여 논리적으로 묶고 싶다."

**인수 조건:**
- 그룹 항목을 클릭(또는 확장)하면 "테이블 추가" UI 표시
- 현재 다이어그램의 테이블 목록에서 선택하여 추가
- 이미 추가된 테이블은 체크 표시로 구분
- 하나의 테이블을 여러 그룹에 추가 가능

### US-3: 그룹 뷰 (필터링)

> "ERD 사용자로서, 그룹을 선택하면 해당 그룹의 테이블만 캔버스에서 보고 싶다."

**인수 조건:**
- 사이드바에서 그룹 뷰 버튼(`Eye` 아이콘)을 클릭하면 "그룹 뷰" 활성화
- 캔버스에 해당 그룹의 테이블만 표시
- **엣지 필터링 정책:**
  - 양 끝 테이블이 모두 그룹에 속한 엣지: **정상 표시**
  - 한쪽만 그룹에 속한 엣지: **표시하지 않음** (단순함 우선, 추후 외부 FK 뱃지로 개선 가능)
- 캔버스 상단 또는 사이드바에 "현재 그룹: {이름}" 배너 표시 + "전체 보기" 복귀 버튼
- 그룹 뷰에서는 캔버스가 **readonly** (노드 이동, 추가, 삭제, 편집 불가)
- **readonly 접근성**: 캔버스 영역에 `aria-label`로 "읽기 전용 그룹 뷰" 상태 전달
- 다시 "전체 보기"로 돌아가면 편집 모드 복원
- **그룹 뷰는 각 사용자의 로컬 뷰 상태**이며, 다른 사용자의 편집을 차단하지 않는다 (Yjs로 동기화하지 않음)

### US-4: 그룹에서 테이블 제거

> "ERD 사용자로서, 그룹에서 특정 테이블을 제거하고 싶다."

**인수 조건:**
- 그룹 상세 뷰에서 테이블 옆 제거 버튼 클릭
- 테이블 자체는 삭제되지 않음 (그룹 연결만 해제)

### US-5: 그룹 삭제

> "ERD 사용자로서, 불필요한 그룹을 삭제하고 싶다."

**인수 조건:**
- 그룹 삭제 시 포함된 테이블에는 영향 없음 (연결만 해제)
- 삭제 확인 다이얼로그 표시

### US-6: 테이블 삭제 시 그룹 참조 정리

> "ERD 사용자로서, 테이블을 삭제하면 해당 테이블이 속한 모든 그룹에서 자동으로 제거되어야 한다."

**인수 조건:**
- `deleteTable()` 실행 시 모든 그룹의 `tableIds`에서 삭제된 테이블 ID를 자동 제거
- 그룹 뷰 렌더링 시에도 방어적 필터링 적용: `tableIds.filter(id => 실제_노드_존재)`

## 4. 화면 설계

### 4.1 사이드바 변경

현재 사이드바 구조를 리디자인한다. 그룹 섹션에 **shadcn/ui `Collapsible`** 컴포넌트를 사용하여 확장/축소 UI를 구현한다.

```
┌──────────────────────────────────────┐
│ TABLES                          [+]  │ ← 기존 유지
│  ├ users                             │
│  ├ orders                            │
│  ├ products                          │
│  └ categories                        │
│                                      │
│ GROUPS                          [+]  │ ← 개념 변경
│  ├ [>] 사용자 모듈 [Eye][Pencil][X]  │ ← Lucide 아이콘 사용
│  │   ├ users                   [✕]  │ ← 소속 테이블 (확장 시)
│  │   └ orders                  [✕]  │
│  │   └ [+ 테이블 추가]              │
│  │                                   │
│  └ [>] 상품 모듈   [Eye][Pencil][X]  │
│      ├ products                [✕]  │
│      └ categories              [✕]  │
│      └ [+ 테이블 추가]              │
│                                      │
│ ┌──────────────────────────────────┐ │ ← 그룹 뷰 활성 시
│ │ [Layers] 사용자 모듈       [✕]  │ │   상태 배너
│ │ 읽기 전용 보기                   │ │
│ └──────────────────────────────────┘ │
└──────────────────────────────────────┘
```

**변경점:**
- 그룹 항목은 shadcn/ui `Collapsible`로 **확장/축소** 가능
  - 축소 시: `ChevronRight` 아이콘, 확장 시: `ChevronDown` 아이콘
- 확장 시 소속 테이블 목록 + 제거 버튼 + "테이블 추가" 버튼 표시
- 그룹 이름 옆 **`Eye` 아이콘** (Lucide) = 그룹 뷰 진입 (aria-label 포함)
- 그룹 뷰 활성 시 사이드바 하단에 **상태 배너** 표시 (시맨틱 토큰 사용: `bg-muted` + `text-muted-foreground`)
- 아이콘: 이모지 사용 금지, **Lucide 아이콘**만 사용 (`Eye`, `Pencil`, `X`, `Plus`, `Layers`, `ChevronRight`, `ChevronDown`)
- 그룹에 테이블이 0개일 때 빈 상태 UI: 안내 텍스트(`erd.group.noTables`) + "테이블 추가" 버튼

- **캔버스 접근성**: `aria-label`로 "읽기 전용: {그룹명} 그룹 뷰" 상태 전달
- **DDL 코드 에디터 연동**: 그룹 뷰 활성 시 코드 에디터 전환 **비활성화** (전체 보기로 복귀 후에만 코드 에디터 사용 가능)

### 4.4 디자인 토큰

모든 UI 요소는 기존 시맨틱 토큰 체계를 따른다. 신규 전용 토큰은 추가하지 않고 기존 토큰을 활용한다.

| UI 요소 | 사용 토큰 |
|---------|----------|
| 그룹 뷰 상태 배너 배경 | `bg-muted` |
| 그룹 뷰 상태 배너 텍스트 | `text-muted-foreground` |
| 그룹 뷰 상태 배너 닫기 버튼 | `hover:bg-accent` |
| 사이드바 그룹 항목 | 기존 `SidebarTableItem` 스타일 유지 |
| 소속 테이블 목록 (확장 시) | `text-muted-foreground`, `pl-4` (들여쓰기) |
| 그룹 색상 표시 | 기존 `TABLE_COLORS` + `hsl(var(--erd-color-*))` 활용 |

그룹 색상은 기존 `TableHeaderColor` 시스템을 재활용하며, 사이드바에서 그룹 이름 옆에 작은 색상 도트로 표시한다. 라이트/다크 모드 양쪽에서 CSS Variable을 통해 자동 전환된다.

## 5. 기존 기능과의 관계

### 5.1 시각적 그룹(GroupNode) 처리 방안

**방안 A (권장): 기존 시각적 그룹을 논리적 그룹으로 전환**

- 기존 `GroupNode` (캔버스 사각 박스)를 제거
- 그룹 개념을 논리적 묶음으로 완전히 교체
- Yjs groups Y.Map 구조를 재활용하되 데이터 스키마 변경
  - 기존: `{ label, position, width, height, color }`
  - 변경: `{ label, color, tableIds: Y.Array }`
- `GroupNode.tsx` 컴포넌트 삭제 (캔버스에 렌더링하지 않음)
- `ERDCanvas.tsx`에서 `allNodes = [...groupNodes, ...nodes]` 제거

**방안 B: 두 가지 그룹 공존**

- 시각적 그룹 유지 + 논리적 그룹 추가
- UI 복잡도 증가, 사용자 혼란 가능성

-> **방안 A를 권장** (사용자가 시각적 박스를 원치 않는다고 명확히 표현)

### 5.2 데이터 저장 위치

그룹-테이블 매핑은 **Diagram content JSON** 내에 저장한다 (백엔드 엔티티 추가 불필요).

```json
{
  "nodes": [...],
  "edges": [...],
  "groups": [
    {
      "id": "group-xxx",
      "label": "사용자 모듈",
      "color": "blue",
      "tableIds": ["table-aaa", "table-bbb"]
    }
  ]
}
```

**근거:**
- 그룹은 다이어그램 내부 개념 (다이어그램 간 공유 불필요)
- Yjs 실시간 동기화 자연스럽게 지원
- 백엔드 API 변경 최소화 (content JSON에 이미 groups 포함)
- 기존 `yDocToJson()` / `migrateJsonToYDoc()` 마이그레이션 로직 활용 가능

## 6. 데이터 모델 변경

### 6.1 Yjs Y.Map 구조 변경

**기존 (시각적 그룹):**
```
groups Y.Map
  └── "group-xxx" → Y.Map
        ├── "label": "Group 1"
        ├── "position": Y.Map { "x": 100, "y": 100 }
        ├── "width": 400
        ├── "height": 300
        └── "color": "blue"
```

**변경 (논리적 그룹):**
```
groups Y.Map
  └── "group-xxx" → Y.Map
        ├── "label": "사용자 모듈"
        ├── "color": "blue"           (선택)
        └── "tableIds": Y.Array [ "table-aaa", "table-bbb" ]
```

- `position`, `width`, `height` 제거 (캔버스 렌더링하지 않음)
- `tableIds` 추가 (Y.Array — CRDT 배열, 동시 편집 충돌 해소)

**Y.Array 성능 참고:** `removeTableFromGroup()`에서 특정 tableId를 제거하려면 인덱스를 찾기 위해 O(n) 스캔이 필요하다. 일반적으로 그룹당 테이블 수가 수십 개 이내이므로 성능 문제는 없으나, 대안으로 `Y.Map<true>`(Set 시뮬레이션)도 구현 설계 시 검토한다.

### 6.2 TypeScript 타입 변경

`TableGroup`은 Yjs Y.Map에서 변환된 **직렬화 후 TypeScript 인터페이스**이다. Yjs 내부에서는 Y.Map/Y.Array로 관리되며, 스토어 상태로 노출될 때 이 인터페이스로 변환된다.

```typescript
// 기존 (삭제)
export interface GroupNodeData extends Record<string, unknown> {
  label: string;
  color?: TableHeaderColor;
}
export type GroupNode = Node<GroupNodeData, 'group'>;

// 변경 (새로 정의)
/** 논리적 테이블 그룹. Yjs Y.Map에서 변환된 직렬화 후 인터페이스. */
export interface TableGroup {
  /** 그룹 고유 식별자 */
  id: string;
  /** 그룹 이름 */
  label: string;
  /** 그룹 색상 (선택) */
  color?: TableHeaderColor;
  /** 소속 테이블 ID 목록 (N:M — 하나의 테이블이 여러 그룹에 참여 가능) */
  tableIds: string[];
}
```

```typescript
  groups: TableGroup[];                    // 그룹 목록

  addGroup(label?: string): void;
  deleteGroup(groupId: string): void;
  renameGroup(groupId: string, newName: string): void;
  updateGroupColor(groupId: string, color: TableHeaderColor): void;
  addTableToGroup(groupId: string, tableId: string): void;
  removeTableFromGroup(groupId: string, tableId: string): void;
}
```

**`activeGroupId` 배치 — 로컬 뷰 상태 분리:**

`activeGroupId`는 Yjs로 동기화하지 않는 **각 사용자의 로컬 UI 상태**이다. `CanvasState`(Yjs 동기화 대상)와 혼재하지 않도록, 다음 중 하나로 관리한다:

- **(A) DiagramPage 내 `useState`**: 가장 단순. 페이지 컴포넌트에서 관리하고 prop/context로 하위 전달
- **(B) 별도 Zustand 슬라이스**: 여러 컴포넌트에서 접근해야 할 경우

-> 구현 설계 시 확정하되, **Yjs 동기화 상태와 로컬 UI 상태를 반드시 분리**한다.

### 6.4 테이블 삭제 시 참조 정리 (dangling reference 방지)

`deleteTable(nodeId)` 액션 내에서 테이블 삭제와 동시에 모든 그룹의 `tableIds`에서 해당 ID를 제거한다.

```
deleteTable(nodeId):
  1. Yjs tables Y.Map에서 nodeId 제거 (기존 로직)
  2. Yjs edges Y.Map에서 관련 엣지 제거 (기존 로직)
  3. [신규] Yjs groups Y.Map을 순회하며 각 그룹의 tableIds Y.Array에서 nodeId 제거
```

추가로 그룹 뷰 렌더링 시에도 **방어적 필터링**을 적용한다:
```typescript
const validTableIds = group.tableIds.filter(id => nodes.some(n => n.id === id));
```

## 8. 협업 시 동작 정의

### 8.1 그룹 데이터 동기화

그룹 데이터(`groups` Y.Map — 그룹 목록, 소속 테이블 등)는 **Yjs를 통해 모든 사용자에게 실시간 동기화**된다. 한 사용자가 그룹을 생성/삭제/수정하면 다른 사용자에게도 즉시 반영.

### 8.2 그룹 뷰 상태 (로컬)

`activeGroupId`는 **각 사용자의 로컬 UI 상태**이며, Yjs로 동기화하지 않는다.

- 사용자 A가 그룹 뷰(readonly)에 진입해도 사용자 B는 전체 보기에서 계속 편집 가능
- 사용자 A의 readonly 상태가 사용자 B에게 전파되지 않음
- 협업 중 누군가의 편집이 그룹 뷰 사용자에게도 실시간 반영됨 (필터링된 테이블의 변경 사항은 보임)

## 9. 마이그레이션 전략

기존 시각적 그룹 데이터가 있는 다이어그램에 대한 하위 호환:

1. `migrateJsonToYDoc()` 수정: 기존 groups 배열에 `position`/`width`/`height`가 있으면 논리적 그룹으로 변환
   - `tableIds: []` (빈 배열) 로 초기화 — 기존 시각적 그룹은 어떤 테이블도 포함하지 않았으므로
   - `position`, `width`, `height` 필드 무시
   - `label`, `color` 필드 유지
2. `yDocToJson()` 수정: 새 포맷으로 직렬화

## 10. DDL 코드 에디터 연동

그룹 뷰 활성 시 DDL 코드 에디터와의 상호작용:

- **그룹 뷰 중 코드 에디터 전환 비활성화**: 사이드바/코드 에디터 토글 버튼을 비활성화하거나 숨김
- 코드 에디터를 사용하려면 먼저 "전체 보기로 돌아가기"로 그룹 뷰를 해제해야 함
- 근거: 코드 에디터는 전체 다이어그램의 DDL을 다루므로, 필터링된 부분만 보여주면 혼란을 야기
