# TODO WBS 계층형 선택 UX 개선 설계

## 배경

- 현재 개인 TODO의 `연결 WBS` 필드는 생성 다이얼로그와 상세 패널 모두 단순 `Select` 하나로 제공된다.
- 옵션 라벨은 `item.name`만 노출되어 같은 이름이 여러 branch에 있을 때 구분이 어렵다.
- WBS는 계층형 구조인데 선택 경험은 평면 목록이라, 사용자는 현재 위치 문맥을 읽을 수 없고 검색도 할 수 없다.
- 보드 요청은 `텍스트 필터링 가능` + `하이라키를 직관적으로 읽을 수 있는 선택 UX`를 TODO 영역에 추가하라는 것이다.

## 문제 정의

현재 flat select는 아래 세 가지 문제를 만든다.

1. 같은 이름 충돌
- 예: `설계`, `개발`, `QA` 같은 일반 명칭이 여러 상위 WBS 아래에 반복될 수 있다.
- 현재는 branch 정보가 없어 잘못 연결할 가능성이 높다.

2. 검색 불가
- 옵션 수가 늘어나면 스크롤 비용이 급증한다.
- 사용자는 원하는 WBS를 이름 일부로 바로 좁혀 들어갈 수 없다.

3. 계층 문맥 손실
- WBS의 핵심 정보는 "어느 상위 작업 아래 있는가"인데, 현재 선택 UI는 그 정보를 숨긴다.

## 설계 목표

- TODO에서 WBS를 고를 때 텍스트 입력으로 빠르게 필터링할 수 있어야 한다.
- 검색 결과와 기본 목록 모두에서 WBS 계층을 읽을 수 있어야 한다.
- 생성 다이얼로그와 상세 패널이 같은 선택 컴포넌트를 사용해야 한다.
- 기존 link/unlink API와 캐시 invalidation 흐름은 유지한다.
- 모바일 폭과 다이얼로그 내부에서도 깨지지 않아야 한다.

## 제안 UX

### 1. 공용 `WbsHierarchySelect` 도입

`Select`를 `Popover + Command` 기반 검색형 선택기로 교체한다.

기본 구조:

- trigger button: 현재 선택된 WBS 경로 요약 또는 `연결 안 함`
- popover header: 검색 input
- result list:
  - 첫 항목 `연결 안 함`
  - 이후 WBS 항목들

적용 위치:

- TODO 생성 다이얼로그
- TODO 상세 패널

### 2. 라벨은 `이름`이 아니라 `계층 경로 + depth affordance`

선택기 내부 각 항목은 아래 두 층으로 보여 준다.

- 1행: 현재 WBS 이름
- 2행: 상위 경로 breadcrumb

예시:

```text
API 구현
함안프로젝트 / 개발 / 백엔드
```

또는 compact variation:

```text
API 구현
레벨 3 · 함안프로젝트 / 개발
```

추가 규칙:

- 목록 좌측에는 depth 기반 들여쓰기 또는 tree guide를 준다.
- trigger에는 너무 긴 전체 경로를 그대로 넣지 말고 `현재 이름 + 상위 path 일부`로 truncate 한다.
- 선택 후 상세 패널 상단 meta의 `linkedWbsItemName`도 가능하면 path-aware 문구로 보강하는 것이 좋다.

### 3. 검색은 `이름 + 전체 조상 경로` 기준으로 동작

필터 입력은 아래 토큰을 모두 검색 대상으로 삼는다.

- 현재 item 이름
- 조상 이름 전체
- 조합된 full path

예:

- `개발 api`
- `백엔드`
- `함안 설계`

같은 검색어로도 원하는 branch를 좁힐 수 있어야 한다.

### 4. 검색 결과에서도 계층 맥락 유지

검색이 걸리면 단순히 매칭 항목만 이름 한 줄로 보여 주지 않는다.

- 매칭된 개별 item만 남기되
- 각 item의 breadcrumb를 유지해서
- "어느 트리 아래 결과인지"를 즉시 알 수 있게 한다.

즉, tree 전체를 펼쳐 재렌더링하는 방식보다 `검색 가능한 path-aware flat projection`이 1차 구현에 더 적합하다.

## 데이터 가공 정책

### 선택기용 read model

WBS API 응답은 그대로 쓰고, 프론트에서 선택기 전용 projection을 만든다.

필드 초안:

```ts
interface WbsSelectOption {
  id: number;
  name: string;
  depth: number;
  parentId: number | null;
  pathLabel: string;
  searchText: string;
}
```

생성 규칙:

- 기존 `sortOrder` 기준 visible order 유지
- `pathLabel`은 조상 이름을 `/` 로 이어 붙인다
- `searchText`는 `name + ancestors + full path`를 normalize해서 만든다

### 정렬 정책

- 기본 목록은 현재 WBS tree 정렬을 그대로 따른다.
- 검색 결과도 relevance 정렬보다 원래 tree 순서를 유지하는 쪽이 문맥 파악에 유리하다.
