# TODO WBS 계층형 선택 UX 개선 QA 체크리스트

## 대상

- parent issue: [RIS-295](/RIS/issues/RIS-295)

## 사전 조건

- 구현 이슈에서 `WbsHierarchySelect` 또는 동등한 공용 picker 도입이 완료되어 있어야 한다.
- WBS가 비어 있는 프로젝트와 계층이 3단계 이상인 프로젝트를 각각 준비한다.
- 같은 이름의 WBS가 서로 다른 branch에 존재하는 테스트 데이터가 있어야 한다.

## 기본 동작

- TODO 생성 다이얼로그에서 `연결 WBS` 필드가 기존 select가 아니라 검색 가능한 picker로 열린다.
- TODO 상세 패널에서도 동일한 picker가 열린다.
- `연결 안 함` 선택이 여전히 가능하다.
- 선택 후 popover가 닫히고 값이 즉시 반영된다.

## 검색 동작

- 현재 WBS 이름 일부로 검색된다.
- 상위 경로 이름으로도 검색된다.
- 복합 키워드로도 원하는 WBS를 좁혀 찾을 수 있다.
- 검색 결과가 없을 때 empty message가 노출된다.

## 계층 가독성

- 기본 목록에서 depth에 따른 들여쓰기 또는 동등한 계층 표시가 보인다.
- 각 항목에서 현재 이름과 상위 경로를 구분해 읽을 수 있다.
- 같은 이름의 WBS 두 개 이상이 있을 때 어떤 branch인지 구분 가능하다.
- trigger에 선택 결과가 지나치게 모호하지 않게 표시된다.

## 저장 연동

- 생성 다이얼로그에서 선택한 WBS가 TODO 생성 payload에 정상 반영된다.
- 상세 패널에서 WBS를 바꾸면 기존 link/unlink mutation이 정상 동작한다.
- `연결 안 함`으로 변경 시 unlink가 정상 동작한다.
- TODO를 다시 열었을 때 저장된 WBS가 올바르게 보인다.

## 예외 / 회귀

- WBS가 하나도 없는 프로젝트에서도 오류 없이 `연결 안 함`만 노출된다.
- 긴 경로/긴 이름이 layout을 깨지 않는다.
- 다이얼로그 내부에서 popover가 잘리지 않는다.
- 기존 TODO 생성/수정/삭제와 문서 연결 기능이 깨지지 않는다.

## 결과 기록 형식

- 테스트 환경
- 사용한 프로젝트 / WBS 데이터
- 검색어별 기대 결과 / 실제 결과
- 계층 구분이 어려운 케이스 유무
- 회귀 여부
