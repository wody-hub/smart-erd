# ERD 빠른 용어등록 단어사전 강제 및 빠른 단어등록 계획

작성일: 2026-03-13
상태: 진행 전

## 목표

ERD 다이어그램 영역에서 신규 용어를 등록할 때:

- 용어는 반드시 기존 단어사전의 단어 조합으로만 생성되도록 강제한다.
- 필요한 단어가 없으면 같은 흐름 안에서 즉시 단어를 등록할 수 있게 한다.
- 다이어그램 엔진, 노드/엣지, Yjs 동기화 로직은 건드리지 않는다.

## 범위

- 포함
  - `QuickTermDialog` 기반 UX 개편
  - ERD 내부 빠른 단어 등록 UI 추가
  - 단어 생성 후 사전 캐시 즉시 갱신
  - 단어 조합 결과만으로 용어 저장되도록 규칙 강제
  - i18n/접근성 반영
- 제외
  - 다이어그램 모델 변경
  - 컬럼/테이블 데이터 구조 변경
  - 협업/Yjs/undo-redo 로직 변경
  - 사전 관리 페이지 구조 변경

## 구현 단위

### 1. QuickTermDialog 저장 경계 정리

- 현재 `QuickTermDialog`에서 실제 저장에 쓰는 값과 화면 표시용 상태를 다시 정리한다.
- 논리명/물리명 자유 입력 상태를 유지할지 제거할지 결정하고, 최종 저장 payload는 단어 조합 결과만 사용하도록 경계를 분명히 한다.
- `selectedWordIds`가 비어 있으면 저장이 불가능하도록 기본 조건을 정의한다.

### 2. 빠른 단어 등록 UI 추가

- ERD 내부에서 사용할 경량 단어 등록 UI를 추가한다.
- 후보 방식
  - `QuickCreateWordDialog`
  - 또는 `QuickTermDialog` 내부 인라인 폼
- 우선순위는 책임 분리다. `WordComposer`는 선택/조합 전용으로 두고, 생성은 별도 컴포넌트가 맡는다.

### 3. 단어 생성 API 연결

- 기존 `createWord` API를 재사용한다.
- 생성 시 현재 다이어그램이 참조하는 동일 `teamId`, `dictionarySetId`를 사용한다.
- 생성 성공 시:
  - `words` query invalidate
  - ERD dictionary cache 최신화
  - 방금 생성한 단어를 자동 선택 후보에 반영

### 4. 용어 생성 규칙 강제

- `QuickTermDialog`의 최종 저장은 선택된 단어 시퀀스로부터 계산된 값만 사용한다.
- 권장 규칙
  - 논리명: 단어 논리명 공백 결합
  - 물리명: 단어 물리명 `_` 결합
- 필요 시 입력 필드는 read-only preview로 바꾸고, 사용자가 직접 수정하지 못하게 한다.
- 단어가 하나도 선택되지 않으면 저장 버튼을 비활성화하고 이유를 안내한다.

### 5. 도메인/추천 UX 재정리

- 현재 Suggest API 기반 자동 추천과 단어 조합 기반 이름 생성이 충돌하지 않도록 상태를 정리한다.
- 이름은 단어 조합이 소유하고, 도메인 추천은 보조 기능으로 남긴다.
- 빠른 도메인 생성은 기존 흐름을 유지하되, 단어 조합 완료 후에도 자연스럽게 이어지도록 상태 전이를 정리한다.

### 6. 캐시 및 적용 흐름 정리

- 용어 생성 성공 시 기존처럼 `terms` invalidate 후 `buildColumnUpdatesFromTerm(...)`로 컬럼에 반영한다.
- 단어 생성 직후 용어 생성까지 한 번에 이어질 때 stale cache가 남지 않도록 `words` invalidate 시점과 선택 반영 순서를 명확히 한다.
- 필요하면 로컬 optimistic append 대신 invalidate + 최신 데이터 반영 방식을 우선 사용한다.

### 7. i18n 및 접근성 반영

- 신규 버튼, 안내 문구, 빈 상태 메시지, 저장 불가 사유를 한/영 번역 키로 추가한다.
- 새 단어 생성 버튼, 닫기 버튼, 제거 버튼, 저장 버튼의 `aria-label`과 설명 문구를 함께 반영한다.

### 8. 검증

- 정적 검증
  - `./gradlew compileJava`
  - `cd client && npm run build`
- 수동 점검 포인트
  - ERD에서 없는 용어 등록 시 단어 조합 없이는 저장이 막히는지
  - 없는 단어를 즉시 생성하고 바로 조합에 넣을 수 있는지
  - 단어 생성 후 같은 `dictionary set` 기준으로 목록이 갱신되는지
  - 용어 생성 후 컬럼 logical/physical/domain 반영이 기존처럼 동작하는지
  - 빠른 도메인 생성과 충돌하지 않는지

## 설계 메모

- 이번 작업의 핵심은 “ERD 안에서의 용어 등록 UX”를 바꾸는 것이지, 다이어그램 도메인 모델을 바꾸는 것이 아니다.
- 규칙을 진짜 강제하려면 논리명/물리명 자유 입력은 남기지 않는 편이 안전하다.
- `WordComposer`에 생성 책임까지 넣으면 컴포넌트가 비대해지므로, 조합과 생성은 분리하는 쪽이 유지보수에 유리하다.
