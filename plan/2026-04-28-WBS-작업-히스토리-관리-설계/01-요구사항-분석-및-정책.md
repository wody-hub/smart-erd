# WBS 작업 히스토리 관리 요구사항 분석 및 정책

## 대상 이슈

- parent issue: [RIS-247](/RIS/issues/RIS-247)

## 범위 정의

이 이슈는 단순히 WBS 편집 UX를 늘리는 작업이 아니다. 아래 네 개의 제품 축을 동시에 다룬다.

1. 작업 객체와 문서 객체의 연결
2. 댓글/히스토리 축적
3. 태그 기반 문서 탐색
4. 개인 TODO와 공유 WBS의 경계 관리

## 정책 결정

### 정책 1. 문서는 독립 엔터티로 유지한다

- 작업 문서는 WBS 항목 내부의 긴 텍스트 필드로 저장하지 않는다.
- 기존 프로젝트 문서 플랫폼을 기반으로 독립 문서 엔터티로 관리한다.
- WBS/TODO/이슈는 문서를 "소유" 하기보다 "참조" 한다.

이유:

- 문서 허브 재사용
- 태그 인덱스 재사용
- 향후 화면기획/기술명세와 같은 문서와 통합 탐색 가능

### 정책 2. WBS 항목은 공유 작업의 기준 엔터티다

- WBS 항목은 프로젝트 공유 객체다.
- WBS 항목에 연결된 문서/댓글/상태 이력은 프로젝트 참여자가 공통으로 열람 가능해야 한다.
- 단, 권한은 기존 프로젝트 편집/읽기 권한을 따른다.

### 정책 3. 개인 TODO는 기본 비공개다

- 개인 TODO는 작성자 본인만 기본 열람/수정 가능하다.
- 개인 TODO가 WBS에 연결되기 전까지는 다른 사용자에게 노출되지 않는다.
- 개인 TODO가 WBS에 연결되면 아래 정보만 공유 대상으로 전환한다.
  - 제목
  - 상태
  - 진척률
  - 일정 관련 메타데이터
  - 연결된 문서 중 공유로 지정된 문서

### 정책 4. WBS 연결 TODO는 "개인 작업의 공유 투영본" 으로 본다

- TODO 자체의 원 소유권은 개인에게 있다.
- 하지만 특정 TODO가 WBS에 연결되면 프로젝트 일정 관리 관점의 공유 객체로 일부 승격된다.
- 이때 WBS는 TODO를 복제하지 않고 참조한다.
- WBS 진척률 계산에는 연결 TODO의 상태/진척을 반영할 수 있어야 한다.

### 정책 5. 댓글은 문서/작업 공통 스레드 모델로 설계한다

- 댓글은 WBS 전용 구조로 만들지 않는다.
- 최소한 아래 대상에 붙을 수 있는 공통 thread 모델이 필요하다.
  - WBS 항목
  - 개인 TODO
  - 프로젝트 문서
- 시스템 활동 로그와 사용자 댓글은 분리한다.
  - 활동 로그: 상태 변경, 링크 추가, 태그 변경
  - 사용자 댓글: 사람이 남기는 메모/논의

### 정책 6. 태그는 "오직 태그 탭" 중심으로 운영한다

- 사용자가 명시한 대로 태그 탭은 통합 검색이 아니라 태그 중심 조회 전용이다.
- 태그는 문서 기준으로 우선 붙인다.
- WBS/TODO는 직접 태그를 갖기보다 연결 문서를 통해 태그 맥락에 들어가는 것을 기본안으로 둔다.

보조 규칙:

- 필요하면 추후 `작업 자체 태그` 를 확장할 수 있으나, 1차에서는 문서 태그만 우선 지원한다.

### 정책 7. 문서 공개 범위는 명시적으로 가진다

- 문서는 최소 두 가지 공개 범위를 가져야 한다.
  - `project-shared`
  - `private`
- WBS에 연결되는 문서는 기본적으로 `project-shared` 여야 한다.
- 개인 TODO에 연결된 문서는 작성자가 `private` 또는 `project-shared` 를 선택할 수 있다.

## 제품 규칙

### WBS 문서화 규칙

- 하나의 WBS 항목은 여러 문서를 참조할 수 있다.
- 문서는 markdown 기반을 기본으로 한다.
- WBS 상세 패널 또는 우측 drawer에서 연결 문서 목록, 최근 댓글, 최근 활동 로그를 보여준다.
- WBS row 자체에는 과한 메타데이터를 싣지 않고, `문서 수`, `댓글 수`, `연결 TODO 수` 같은 요약 배지만 표시한다.

### 태그 탭 규칙

- 태그 탭은 프로젝트 허브의 별도 탭으로 추가한다.
- 기본 화면은 태그 목록이다.
- 태그 클릭 시 해당 태그가 붙은 문서 목록만 보여준다.
- 1차 범위에서는 "문서 목록 + 연결 작업 요약" 까지만 제공한다.
- 태그 탭에서 문서 생성/수정 진입이 가능해야 한다.

### 개인 TODO 규칙

- 개인 TODO 탭은 프로젝트 허브가 아니라 사용자 개인 워크스페이스 성격에 가깝다.
- 다만 현재 제품 구조상 프로젝트 문맥 안에서 우선 제공해도 된다.
- 필수 필드:
  - 제목
  - 상태
  - 우선순위
  - 목표일
  - 진척률
  - 연결 WBS
  - 연결 문서
