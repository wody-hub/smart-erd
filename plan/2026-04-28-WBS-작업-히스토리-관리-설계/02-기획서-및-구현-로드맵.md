# WBS 작업 히스토리 관리 기획서 및 구현 로드맵

## 대상 이슈

- parent issue: [RIS-247](/RIS/issues/RIS-247)

## 목표

- WBS를 "일정 트리" 에서 "작업 맥락 허브" 로 확장한다.
- 개인 TODO와 프로젝트 공유 WBS를 안전하게 연결한다.
- 문서와 태그를 통해 작업 히스토리와 지식 축적이 가능한 구조를 만든다.

## 정보 구조

### 프로젝트 허브 탭 구조 제안

현행:

- Documents
- Overview
- WBS
- Gantt
- Staffing
- Issues

제안:

- Documents
- Tags
- WBS
- Gantt
- Issues
- Staffing
- My Tasks

설명:

- `Tags` 는 문서 탐색의 별도 허브다.
- `My Tasks` 는 개인 TODO 공간이다.
- `Overview` 는 유지 여부를 별도 판단할 수 있으나 본 이슈 핵심은 아니다.

## 화면 기획

### 1. WBS 상세 확장

핵심 화면:

- 기존 WBS row/트리 유지
- row 선택 시 우측 상세 패널 또는 drawer 표시

상세 패널 섹션:

- 기본 정보
- 연결 문서 목록
- 연결 TODO 목록
- 활동 로그
- 댓글

핵심 액션:

- 문서 새로 만들기
- 기존 문서 연결
- TODO 연결
- 댓글 작성

### 2. Tags 탭

좌측:

- 태그 목록
- 태그별 문서 수

우측:

- 선택 태그의 문서 목록
- 각 문서가 연결된 WBS/TODO 요약

### 3. My Tasks 탭

목록 컬럼:

- 제목
- 상태
- 우선순위
- 목표일
- 진척률
- 연결 WBS
- 문서 수
- 공개 상태

행동:

- 새 TODO 생성
- WBS 연결/해제
- 문서 연결
- 공유 상태 확인

## 데이터 모델 초안

### 신규 개념

- `TaskDocumentLink`
  - targetType: `WBS` | `TODO` | `ISSUE`
  - targetId
  - documentId
  - visibility

- `ProjectTag`
  - projectId
  - name
  - color or token

- `DocumentTagLink`
  - documentId
  - tagId

- `PersonalTask`
  - ownerUserId
  - projectId
  - title
  - status
  - priority
  - dueDate
  - progressRate
  - visibilityMode

- `TaskCommentThread` / `TaskComment`
  - targetType
  - targetId
  - author
  - body

- `TaskActivityLog`
  - targetType
  - targetId
  - eventType
  - actor
  - payload

### 재사용 대상

- 문서 본문은 기존 `diagram` / `markdown` 문서 플랫폼 재사용
- 프로젝트 컨텍스트 로딩과 팀 멤버 권한은 기존 PM 모듈 재사용
- WBS/Gantt 일정 렌더링은 기존 WBS 엔터티 재사용

## 단계별 구현

### Phase 1. 작업-문서 연결과 태그 기초

범위:

- 문서와 WBS 연결 모델 추가
- markdown 문서에 태그 메타데이터 추가
- Tags 탭 read-only MVP
- WBS 상세에서 연결 문서 목록 표시

완료 기준:

- 특정 WBS에서 문서를 생성/연결할 수 있다.
- 태그 탭에서 태그별 문서 목록을 볼 수 있다.

### Phase 2. 댓글/활동 로그

범위:

- 작업 공통 comment thread 추가
- WBS 상세 댓글 UI
- 활동 로그 자동 적재

완료 기준:

- WBS 항목별 논의 히스토리를 누적할 수 있다.
- 상태 변경과 문서 연결 이력이 로그에 남는다.

### Phase 3. 개인 TODO

범위:

- My Tasks 탭 추가
- 개인 TODO CRUD
- TODO와 문서 연결
- TODO와 WBS 연결/해제

완료 기준:

- 개인 작업을 WBS와 독립적으로 관리할 수 있다.
- 필요한 TODO만 WBS 일정 리스크 대상으로 공유할 수 있다.

### Phase 4. WBS/Gantt 통합 표시

범위:

- WBS에서 연결 TODO 요약 배지 표시
- Gantt에서 연결 TODO 기반 위험도/추적 표시
- 진행률 집계 규칙 정교화

완료 기준:

- PM/PL이 WBS 일정과 연결 작업 위험을 함께 볼 수 있다.

## 리스크

- 문서 플랫폼과 PM 도메인의 경계를 성급하게 합치면 모델 복잡도가 급증한다.
- 댓글을 작업별로 따로 만들면 중복 구현이 된다.
- 개인 TODO 공개 규칙이 모호하면 개인정보/업무노출 충돌이 생긴다.

## 선행 검증 포인트

- markdown 문서 메타데이터 확장 방식
- 문서-작업 연결을 `diagram` 기준으로 둘지 별도 테이블로 둘지
- 개인 TODO가 프로젝트 컨텍스트 안에만 존재하는지, 향후 사용자 전역 공간으로 확장할지
