## 권장 child issue 분할

### Child A. 도메인/백엔드

제목 초안:

- `WBS 문서 연결 및 태그 MVP 백엔드`

범위:

- `TaskDocumentLink` 성격의 연결 모델 추가
- WBS 기준 문서 연결/해제 API 추가
- 문서 태그 목록/태그별 문서 조회 API 추가
- 프로젝트 권한 범위 검증

완료 기준:

- 특정 WBS 항목에 문서를 연결/해제할 수 있다.
- 태그 기준으로 프로젝트 문서 목록을 조회할 수 있다.

주의:

- 문서 본문 저장소는 기존 프로젝트 문서 플랫폼 재사용
- WBS 엔터티에 긴 본문/태그 직접 내장 금지

### Child B. 프런트엔드/정보구조

제목 초안:

- `WBS 상세 문서 연결 UI 및 Tags 탭 MVP`

범위:

- 프로젝트 허브에 `Tags` 탭 추가
- WBS 상세 패널 또는 drawer에 연결 문서 목록 UI 추가
- 문서 연결/해제 액션 UI 추가
- 태그 목록 및 태그별 문서 목록 read-only 화면 추가

완료 기준:

- WBS에서 연결 문서를 볼 수 있다.
- 태그 탭에서 태그별 문서 목록을 볼 수 있다.
- 문서 클릭 시 기존 문서 상세 진입 흐름과 충돌하지 않는다.

주의:

- row에 과한 메타데이터를 넣지 말고 요약 배지 중심으로 유지
- 현재 `Documents / WBS / Gantt / Issues` 허브 구조와 시각 계약을 깨지 말 것

### Child C. QA

제목 초안:

- `WBS 문서 연결 및 Tags 탭 MVP QA`

범위:

- 연결/해제 플로우
- 태그별 조회 정확성
- 권한/노출 경계
- 기존 문서 허브/WBS 회귀

완료 기준:

- 연결된 문서가 WBS에서 일관되게 보인다.
- 태그 탭 결과가 문서 메타데이터와 일치한다.
- 기존 문서 생성/조회/WBS 편집 흐름이 깨지지 않는다.

## 순서 제안

1. Child A 백엔드
2. Child B 프런트엔드
3. Child C QA

이유:

- 프런트가 임시 계약을 추정하지 않게 한다.
- 태그 조회와 연결 모델의 응답 shape를 먼저 고정해야 QA 시나리오도 안정된다.
