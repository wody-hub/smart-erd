# RIS-317 2차 QA - WBS 운영형 planning workspace 검증 체크리스트

- 작성일: 2026-05-06
- 대상 이슈: RIS-323
- 선행 구현: RIS-321 (BE), RIS-322 (FE)

## 1. QA 시작 조건 (Entry Criteria)

- RIS-321 상태가 `done` 또는 QA 요청 코멘트와 함께 `in_review`.
- RIS-322 상태가 `done` 또는 QA 요청 코멘트와 함께 `in_review`.
- 테스트 가능한 실행 환경/브랜치와 샘플 프로젝트 ID가 코멘트로 공유됨.

## 2. 검증 범위

- WBS 운영형 planning workspace의 템플릿 적용 흐름
- WBS 대량 생성(Bulk create) 흐름
- WBS 시프트(Shift) 조정 흐름
- FE/BE 계약 정합성(요청 payload, 응답 반영, 오류 표시)
- 기존 06.1 기능(전용 workspace 진입/inline append/assignee) 회귀 여부

## 3. 테스트 시나리오

1. 템플릿 목록/선택/적용
- 템플릿 목록 조회가 정상 동작한다.
- 특정 템플릿 적용 시 WBS 트리 구조가 의도한 계층으로 생성된다.
- 템플릿 적용 실패 시 사용자에게 실패 원인/재시도 동선이 제공된다.

2. 대량 생성(Bulk create)
- 대량 입력/생성 실행 시 노드가 중복 없이 생성된다.
- 생성 직후 정렬/계층/기본값(progressRate 등) 계약이 유지된다.
- 일부 실패 케이스에서 성공/실패 결과가 분리 표시된다(전체 무응답 금지).

3. 시프트(Shift)
- 날짜/기간 시프트 적용 시 대상 범위만 정확히 이동한다.
- 시프트 미리보기 또는 확인 단계와 실제 반영 결과가 일치한다.
- 시프트 불가 조건(권한/유효성)에서 오류 메시지가 명확하다.

4. 회귀 확인 (06.1)
- `/teams/:teamId/projects/:projectId/wbs` 직접 진입/새로고침이 유지된다.
- 전용 workspace에서 inline root/child append 동작이 유지된다.
- assignee 선택/해제 후 테이블 반영이 유지된다.

## 4. 최소 증빙 아티팩트

- 단위/통합 테스트 실행 로그 (추가/변경 테스트 중심)
- 수동 QA 캡처(각 핵심 플로우 1개 이상)
- 실패 케이스 캡처(오류 메시지/상태)
- 최종 QA 판정 코멘트 (`PASS` 또는 `FAIL` + 재현 단계)

## 5. 판정 기준

- PASS
- 핵심 시나리오(템플릿/대량생성/시프트/회귀) 모두 통과
- 치명/높음 결함 0건

- FAIL
- 핵심 시나리오 중 1개라도 재현 가능한 기능 결함 존재
- 데이터 무결성 또는 사용자 진행 불가 결함 존재
