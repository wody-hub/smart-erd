# 아키텍처 및 디자인 시스템 점검 보고서

본 문서는 시니어 개발자 및 퍼블리셔 관점에서 진행된 Smart ERD 프로젝트의 구조적 설계, 보안, 디자인 시스템 준수 여부 점검 결과와 조치 사항을 기록합니다.

## 1. 백엔드 아키텍처 점검 및 개선

### 1.1 WebSocket 패키지 리팩토링
- **조치**: 기존 `websocket` 패키지에 밀집되어 있던 클래스들을 역할에 따라 `relay`, `room`, `ticket`, `transport` 서브패키지로 분리하여 응집도를 높임.
- **상태**: 완료

### 1.2 데이터 무결성 및 동시성 제어
- **문제**: `DiagramUpdateBuffer`에서 카운터 업데이트와 리스트 삽입 사이의 레이스 컨디션 발견 (OOM 위험).
- **조치**: `synchronized(updates)` 블록을 사용하여 크기 체크와 데이터 삽입을 원자적 작업으로 통합.
- **설계 우수 사례**: `DiagramPresenceManager`에서 `Thread.holdsLock`을 통한 런타임 락 계약 검증 적용.
- **상태**: 완료

### 1.3 컴팩션(Compaction) 최적화 및 메모리 누수 방지
- **문제**: 동일 사용자 멀티 탭 접속 시 중복 컴팩션 요청으로 인한 리소스 낭비 및 로그 노이즈.
- **조치**:
    - 성공 시 1분, 거부(멀티 세션) 시 30초의 **차등 쿨다운** 도입.
    - `DiagramRoomManager.leave` 시점에 쿨다운 정보를 즉시 제거하여 메모리 누수 원천 차단.
- **상태**: 완료 (테스트 코드 보완 포함)

### 1.4 로깅 컨벤션 준수
- **조치**: 총 17개 파일의 수동 `Logger` 선언을 Lombok `@Slf4j` 어노테이션으로 교체하여 코드 표준 준수.
- **상태**: 완료

## 2. 프론트엔드 아키텍처 점검 및 개선

### 2.1 Zustand 스토어 안정화 (HMR 대응)
- **문제**: 스토어 외부 클로저 변수 사용으로 인해 HMR 발생 시 상태 유실 및 메모리 누수 위험.
- **조치**: `useCanvasStore.ts`의 모든 클로저 변수를 스토어 내부의 `internal` 객체로 이동하여 라이프사이클을 스토어에 귀속시킴.
- **상태**: 완료

### 2.2 컴팩션 무한 재시도 가드
- **문제**: 특정 사유로 컴팩션 실패 시 5초마다 대용량 데이터를 반복 전송하는 문제.
- **조치**: 세션당 최대 시도 횟수(3회) 제한을 추가하고, 다이어그램 전환 시 시도 횟수를 초기화하도록 구현.
- **상태**: 완료

### 2.3 Axios 응답 인터셉터 큐 패턴
- **문제**: 동시 다발적 401 에러 시 토큰 갱신 요청이 중복 발생하여 Refresh Token 로테이션 정책과 충돌 위험.
- **조치**: `isRefreshing` 플래그와 `failedQueue`를 도입하여 갱신 요청을 단일화하고 성공 후 일괄 재시도 처리.
- **상태**: 완료

## 3. 프론트엔드 디자인 시스템 점검

### 3.1 디자인 토큰 최적화
- **조치**: `CollaboratorsPopover.tsx` 등에서 발견된 하드코딩 색상(`bg-emerald-500`)을 시맨틱 토큰(`bg-success`)으로 교체.
- **상태**: 완료

### 3.2 테마 확장 (Arbitrary Values 제거)
- **문제**: `text-[10px]`, `text-[11px]` 등 임의의 수치가 코드 곳곳에 산재함.
- **조치**: `tailwind.config.js`에 `2xs` (10px) 폰트 크기 토큰을 등록하고 관련 코드를 `text-2xs`로 일괄 전환.
- **상태**: 완료

### 3.3 접근성 (a11y) 강화
- **점검 결과**: 사이드바 리사이즈 핸들의 `role="separator"`, `aria-valuenow` 적용 및 키보드 조작 지원 등 수준 높은 접근성 처리가 확인됨.
- **상태**: 양호
