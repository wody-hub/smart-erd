- 로딩/동기화 대기 상태를 캔버스 중앙 오버레이로 명확히 안내한다.

- 오버레이 적용 범위는 **첫 진입 초기 렌더 지연 구간**으로 한정한다.
- feature flag ON/OFF 무관하게 동작한다.
- 기존 데이터 동기화 로직(REST preview, Y.Doc/WS handoff)에는 부작용 없이 UI 가드만 추가한다.

## 전제 조건
- `syncStage === 'boot'` 동안(= API `isLoading` 중)은 `DiagramPage`가 전체 화면 `Spinner`를 렌더링하므로 ERDCanvas/오버레이가 마운트되지 않는다.
- feature flag OFF일 때 `syncStage`는 항상 `'yjs-live'`이지만, Y.Doc 데이터가 store에 반영되기까지 빈 캔버스 구간이 존재한다. **오버레이는 이 구간을 커버해야 한다.**

## 설계 가드레일 (기조 고정)
1. 오버레이는 **첫 진입 초기 렌더 지연** 가시화 목적만 가진다.
2. API/WS/DB 계약, 저장 정책, 동기화 순서, 권한 정책은 변경하지 않는다.
3. 오버레이 상태는 UI 로컬 상태로만 관리하며, 서버 호출/저장 트리거를 추가하지 않는다.
4. 오버레이가 사라진 뒤에는 동일 다이어그램 세션에서 다시 나타나지 않는다(래치).
5. 다이어그램 식별자(`diagramId`)가 바뀌면 래치를 초기화해 다음 진입을 독립 처리한다.

## UX 정책

### 오버레이 표시/해제 조건 (핵심)

오버레이 표시 조건은 `syncStage`가 아닌 **실제 캔버스 렌더 가능 여부** 기준이다:

```
showOverlay = diagramHasContent && !initialLoadComplete
```

- `diagramHasContent`: `!!diagram?.content` — content가 null인 빈 다이어그램은 오버레이 불필요
- `initialLoadComplete`: **래치(latch)** — 한 번 `true`가 되면 다시 `false`로 돌아가지 않음. 다이어그램 전환 시(`latchKey` 변경) ref 가드로 리셋 후 1프레임 대기하여 store 잔존 데이터에 의한 조기 해제를 방지한다.

래치 전환 조건 (`initialLoadComplete` → `true`):
1. `hasRenderableGraph === true` — preview 또는 store에 노드/엣지가 존재
2. `!diagramHasContent` — 빈 다이어그램이면 즉시 complete
3. 단, `latchKey` 변경 직후 첫 이펙트 실행에서는 store 잔존 데이터를 무시하고 리셋만 수행 (ref 가드)

`hasRenderableGraph` 계산:
1. `previewHasRenderableGraph = previewNodes.length > 0 || previewEdges.length > 0` (DiagramPage에 이미 존재)
2. `storeHasRenderableGraph = (store.nodes.length > 0 || store.edges.length > 0)` (DiagramPage boolean selector)
3. `hasRenderableGraph = previewHasRenderableGraph || storeHasRenderableGraph`

**왜 래치인가:** 데이터가 한 번 캔버스에 나타난 뒤, 그룹 뷰 전환 등으로 일시적으로 빈 상태가 되어도 오버레이가 다시 뜨지 않아야 한다.

### 상태별 문구/행동 (오버레이 표시 시)
오버레이가 표시 조건을 만족할 때, `syncStage`에 따라 문구를 분기한다.

1. `api-preview`, `api-preview-empty` (feature flag ON)
- 문구: "다이어그램을 준비하고 있습니다."
- UI: spinner + 부가 설명

2. `yjs-timeout-degraded` (feature flag ON)
- 문구: "연결이 지연되고 있습니다. 자동 재시도 중입니다. (n/m)"
- UI: spinner + 재시도 카운트

3. `yjs-failed-readonly` (feature flag ON)
- 문구: "연결에 실패했습니다. 다시 시도해 주세요."
- UI: 경고 아이콘/텍스트 + `다시 시도` 버튼(`manualRetry`)

4. `yjs-live` (feature flag OFF이면 항상 이 상태)
- 문구: "다이어그램을 불러오는 중입니다."
- UI: spinner
- **feature flag OFF에서 빈 캔버스 대기 구간을 커버하는 범용 문구**

### 기존 `opacity-70`과의 통합
- `ERDCanvas.tsx:399`에 `isPreview && 'opacity-70'` 처리가 존재한다.
- **오버레이 표시 시** (빈 캔버스): 빈 캔버스에 opacity를 적용해도 의미가 없으므로 `opacity-70` 제거. 오버레이가 전체 피드백을 담당.
- **오버레이 미표시 시** (preview 데이터 있음): 기존 `opacity-70` 유지. preview 데이터가 "임시 상태"임을 시각적으로 전달.
- 변경: `ERDCanvas`의 className 조건을 `isPreview && displayNodes.length > 0 && 'opacity-70'`으로 수정.

### `CollabSyncBanner`와의 역할 분리
- **오버레이 표시 중**: `CollabSyncBanner`는 숨긴다. 캔버스 중앙의 오버레이가 상태 + 액션을 모두 제공하므로 배너까지 보여줄 필요가 없다.
- **오버레이 미표시 + preview 중**: `CollabSyncBanner`가 상단에 한 줄 상태 요약을 표시한다 (기존 동작 유지).
- **구현**: `DiagramPage`에서 `showOverlay ? null : <CollabSyncBanner ... />` 조건부 렌더링으로 처리한다. (`CollabSyncBanner` props 변경 없음)

**DiagramPage에 추가할 코드:**

선언 순서는 Page Component Ordering 규칙을 따른다 (그룹 4 → 5 → 6 → 10).

```typescript
// --- 그룹 4: useState / useRef ---
/** 래치: 한 번 true가 되면 다시 false로 돌아가지 않음 */
const [initialLoadComplete, setInitialLoadComplete] = useState(false);
/** 래치 키: 다이어그램 전환 시 래치 초기화 기준 (useRef 초기화에 필요하므로 그룹 4에 배치) */
const latchKey = `${projectId}:${diagramId}`;
/** 래치 ref 가드: latchKey 변경 감지용 */
const prevLatchKeyRef = useRef(latchKey);

// --- 그룹 5: store selector ---
/** store에 렌더 가능한 노드/엣지가 존재하는지 (boolean selector로 리렌더 최소화) */
const storeHasRenderableGraph = useCanvasStore(
  (s) => s.nodes.length > 0 || s.edges.length > 0,
);

// --- 그룹 6: 파생값 ---
/** 렌더 가능 그래프 판정 (preview + store) */
const hasRenderableGraph = previewHasRenderableGraph || storeHasRenderableGraph;
/** 빈 다이어그램 여부 */
const diagramHasContent = !!diagram?.content;
/** 오버레이 표시 조건 */
const showOverlay = diagramHasContent && !initialLoadComplete;

// --- 그룹 10: useEffect ---
/**
 * 래치 관리 (단일 이펙트 + ref 가드).
 *
 * latchKey 변경 직후에는 store에 이전 다이어그램 노드/엣지가 잔존할 수 있다.
 * ref 가드로 변경 직후 첫 호출에서는 리셋만 수행하고 early return하여
 * 잔존 데이터에 의한 래치 조기 설정을 방지한다.
 */
useEffect(() => {
  if (prevLatchKeyRef.current !== latchKey) {
    prevLatchKeyRef.current = latchKey;
    setInitialLoadComplete(false);
    return; // store 잔존 데이터 무시 — 다음 렌더에서 재평가
  }
  if (hasRenderableGraph || !diagramHasContent) {
    setInitialLoadComplete(true);
  }
}, [latchKey, hasRenderableGraph, diagramHasContent]);
```

## 시나리오별 동작 정리

### Feature flag OFF (현재 환경)
```
1. 진입 → isLoading → 전체 화면 Spinner
2. API 완료 → ERDCanvas 마운트
   - content 있음 → showOverlay=true, 오버레이 표시 ("불러오는 중")
   - content 없음(빈 다이어그램) → showOverlay=false, 빈 캔버스 표시
3. Y.Doc WS 연결 → snapshot/sync 완료 → store 갱신 → hasRenderableGraph=true
4. 래치 전환 → showOverlay=false → 오버레이 해제, 다이어그램 표시
```

### Feature flag ON
```
1. 진입 → isLoading (boot) → 전체 화면 Spinner
2. API 완료 → syncStage=api-preview
   - content 파싱 성공 → previewHasRenderableGraph=true → showOverlay=false
     → preview 표시 (opacity-70) + CollabSyncBanner 표시
   - content 파싱 실패/없음 → showOverlay=true → 오버레이 표시 ("준비 중")
3. WS handoff 완료 → syncStage=yjs-live → store 갱신 → 래치 전환
   → 오버레이/배너 해제, 다이어그램 표시
4. WS 타임아웃 → syncStage=yjs-timeout-degraded → 오버레이 문구 변경 ("지연 중")
5. 재시도 실패 → syncStage=yjs-failed-readonly → 오버레이 문구 변경 ("실패") + 재시도 버튼
```

### 빈 다이어그램 (content === null)
```
1. 진입 → 전체 화면 Spinner
2. API 완료 → diagramHasContent=false → initialLoadComplete=true 즉시 전환
3. showOverlay=false → 빈 캔버스 표시 (오버레이 없음)
```

### 다이어그램 A→B 전환 (ref 가드 동작)
```
1. URL 변경 → latchKey 변경 → 리렌더
   - prevLatchKeyRef.current !== latchKey 감지
2. 래치 이펙트 실행 (첫 호출):
   - prevLatchKeyRef 갱신 + setInitialLoadComplete(false) + early return
   - store에 A의 잔존 데이터가 있어도 무시
3. useYjsCollaboration cleanup → destroyYDoc() → nodes: [], edges: []
4. 리렌더 → storeHasRenderableGraph=false
5. 래치 이펙트 실행 (두 번째 호출):
   - prevLatchKeyRef === latchKey → 정상 분기
   - hasRenderableGraph=false, diagramHasContent=true → no-op
   - showOverlay=true → 오버레이 표시
6. WS 동기화 완료 → store 갱신 → hasRenderableGraph=true
7. 래치 전환 → showOverlay=false → 오버레이 해제
```

  - `syncStage=api-preview` + 빈 그래프 → 오버레이 표시 ("준비 중"), `CollabSyncBanner` 숨김
  - `syncStage=api-preview` + preview 데이터 존재 → 오버레이 미표시, 배너 표시, `opacity-70` 적용
  - `syncStage=yjs-failed-readonly` → retry 버튼 표시 및 핸들러 호출
- **공통:**
  - `syncStage=yjs-live` + 그래프 존재 → 오버레이 미표시, 배너 미표시
  - 래치 검증: 데이터 도착 후 그룹 뷰 전환으로 빈 상태 → 오버레이 재출현 없음

2. 시나리오 확인 (수동)
- 로그인 → 다이어그램 진입 직후 오버레이 노출 확인
- 데이터 도착 후 오버레이 자동 제거 확인
- 네트워크 지연 시 degraded 메시지/카운트 노출 (feature flag ON)
- 실패 상태에서 다시 시도 버튼 동작 (feature flag ON)
- 오버레이 표시 중 캔버스 팬/줌 동작 유지, retry 버튼만 클릭 가능한지 확인 (pointer-events 정책)
- 신규(빈) 다이어그램: boot Spinner → 오버레이 없이 빈 캔버스 표시
- 다이어그램 A에서 B로 이동 시: 래치가 초기화되어 B 진입 로딩 구간에서 오버레이 정책이 동일하게 재적용되는지 확인
- 다이어그램 A에서 B로 이동 직후: A의 노드/엣지가 B의 오버레이 해제 판정에 잔존 영향을 주지 않는지 확인

3. 회귀 확인
- 편집 권한/자동백업/저장 동작 기존과 동일
- 그룹 뷰/코드 편집 패널 전환 시 오버레이 재출현 없음
- feature flag ON/OFF 전환 시 양쪽 모두 정상 동작

## 리스크 및 대응
1. 리스크: 그래프 존재 판정 타이밍과 오버레이 해제 타이밍 경합
- 대응: DiagramPage에서 `hasRenderableGraph(preview + store)` 단일 조건 + 래치 패턴으로 판정. 한 번 해제되면 다시 뜨지 않음.

2. 리스크: 상단 배너와 중앙 오버레이 메시지 중복
- 대응: 오버레이 표시 중에는 `CollabSyncBanner`를 숨긴다. 오버레이 미표시 시에만 배너 노출.

3. 리스크: 상태 전환 잦을 때 깜빡임
- 대응: 래치 패턴으로 한 방향 전환만 허용 (overlay → hidden 전환은 다이어그램 세션당 1회). 조건부 렌더링(마운트/언마운트)을 사용하므로 CSS transition은 적용하지 않는다. 래치 해제 시점에 캔버스에 노드가 동시에 그려지므로 자연스러운 전환이 이루어진다.

4. 리스크: 기존 `opacity-70`과의 이중 처리
- 대응: 오버레이 표시 시 `opacity-70` 비활성화. ERDCanvas 조건을 `isPreview && displayNodes.length > 0`으로 변경.

5. 리스크: `storeNodes/storeEdges` selector가 매 렌더마다 리렌더 유발
- 대응: 본 설계에서 boolean selector(`useCanvasStore((s) => s.nodes.length > 0 || s.edges.length > 0)`)를 기본 적용한다. 배열 참조 변경에 의한 불필요한 리렌더를 방지.

6. 리스크: 다이어그램 전환 시 이전 store 데이터가 잠시 남아 오버레이 조기 해제 가능
- 원인: `useYjsCollaboration`의 cleanup(`destroyYDoc()` → `nodes: []`)이 래치 이펙트보다 늦게 실행되어, 래치 리셋 직후 잔존 데이터로 래치가 즉시 재설정됨
- 대응: **ref 가드 패턴**으로 해결. `prevLatchKeyRef`로 `latchKey` 변경을 감지하여 변경 직후 첫 이펙트 호출에서는 리셋만 수행하고 early return. 다음 렌더 사이클에서 `destroyYDoc()` 완료 후 store가 클리어된 상태에서 래치를 재평가한다. 저장/동기화 로직은 변경하지 않는다.

## 완료 기준 (DoD)
1. content가 있는 다이어그램 진입 시, 캔버스에 노드가 그려질 때까지 오버레이가 표시된다.
2. 빈 다이어그램(content === null)에는 오버레이가 표시되지 않는다.
3. preview 데이터가 있으면 오버레이 없이 `opacity-70` + 배너로 상태를 전달한다.
4. 렌더 가능 데이터 도착 시 오버레이가 즉시 사라지고, 다시 나타나지 않는다.
5. `yjs-failed-readonly`에서 재시도 버튼이 동작한다.
6. 오버레이와 배너가 동시에 표시되지 않는다.
7. feature flag ON/OFF 모두에서 정상 동작한다.
8. `npm run build` 통과.
9. 기존 저장/조회/동기화 플로우의 계약(API/WS/DB)은 변경되지 않는다. (UI 가시화 레이어만 변경)
