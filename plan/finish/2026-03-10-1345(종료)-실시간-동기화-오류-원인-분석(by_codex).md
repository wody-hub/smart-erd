# 실시간 동기화 오류 및 캔버스 상단 버튼 누락 원인 분석

작성일: 2026-03-10

## 상황 요약

- 최근 수정 이후 다이어그램 편집 화면에서 실시간 동기화 오류가 발생한다.
- 동시에 캔버스 상단 버튼(FK Connect, 코드 에디터, 자동 배치, DDL 가져오기 등)이 많이 사라진다.
- 프런트 빌드는 통과하므로 문법/번들링 문제가 아니라 런타임 상태 전이 회귀로 판단된다.

## 핵심 결론

이번 이슈의 1차 원인은 `useDiagramSyncStage`의 상태 전이 회귀다.

- `api-preview` 단계에서만 snapshot/sync 완료 콜백을 등록한다.
- 한 번 타임아웃이 발생해 `yjs-timeout-degraded`로 내려가면 effect cleanup으로 콜백이 해제된다.
- 이후 재시도에서 snapshot 응답이 와도 `yjs-live`로 복구시킬 코드가 실행되지 않는다.

이 구조 때문에 동기화 오류가 한 번 발생하면 세션이 사실상 readonly 상태로 고착될 수 있다.

상단 버튼 누락은 별도 독립 버그라기보다 이 상태 전이 실패의 2차 증상이다.

## 상세 원인

### 1. degraded 이후 복구 루프 단절

관련 파일:

- `client/src/hooks/useDiagramSyncStage.ts`
- `client/src/pages/diagram/DiagramPage.tsx`

문제 지점:

- `scheduleRetry()`는 snapshot 재요청만 수행한다.
- 하지만 `provider.onSnapshotReceived`, `provider.onSyncCompleted` 콜백은 `api-preview` 또는 `api-preview-empty` 단계에서만 등록된다.
- `syncStage`가 `yjs-timeout-degraded`로 바뀌면 effect가 정리되면서 콜백이 원복된다.
- 그 상태에서는 재시도 응답이 도착해도 live 전환 로직이 동작하지 않는다.

영향:

- preview 또는 degraded 상태가 길게 유지된다.
- 사용자 입장에서는 실시간 동기화가 계속 실패하는 것처럼 보인다.
- 저장/편집 관련 기능이 다시 풀리지 않는다.

핵심 코드 포인트:

- `client/src/hooks/useDiagramSyncStage.ts:133`
- `client/src/hooks/useDiagramSyncStage.ts:224`
- `client/src/hooks/useDiagramSyncStage.ts:336`

### 2. stale snapshot 복구가 프레임 단위로 중복 실행될 가능성

관련 파일:

- `client/src/hooks/useDiagramSyncStage.ts`
- `client/src/collaboration/YjsProvider.ts`
- `src/main/java/com/smarterd/domain/diagram/websocket/relay/handler/SnapshotRequestMessageHandler.java`

문제 지점:

- 서버는 snapshot을 여러 update frame으로 분해해 순차 전송한다.
- 클라이언트는 `SNAPSHOT_RESPONSE`를 받을 때마다 `onSnapshotReceived`를 호출한다.
- stale revision이 감지되면 클라이언트가 즉시 `replaceJsonInYDoc()` 후 `pushFullDocumentUpdate()`를 수행한다.
- 이때 snapshot 전송이 아직 끝나지 않았다면 남은 stale frame이 계속 도착할 수 있다.

영향:

- 전체 문서 덮어쓰기와 전체 update 재전송이 여러 번 반복될 수 있다.
- 캔버스가 튀거나 상태가 다시 꼬일 수 있다.
- 원격 피어에게 과도한 update가 전파될 수 있다.

핵심 코드 포인트:

- `client/src/collaboration/YjsProvider.ts:321`
- `client/src/hooks/useDiagramSyncStage.ts:267`
- `src/main/java/com/smarterd/domain/diagram/websocket/relay/handler/SnapshotRequestMessageHandler.java:109`

### 3. 상단 버튼 누락은 sync stage 기반 편집 잠금의 결과

관련 파일:

- `client/src/pages/diagram/DiagramPage.tsx`
- `client/src/components/erd/ERDCanvas.tsx`
- `client/src/components/erd/CanvasToolbar.tsx`

문제 지점:

- `DiagramPage`는 `syncStage === 'yjs-live'`일 때만 `syncCanEdit`를 true로 둔다.
- `ERDCanvas`는 preview/degraded/failed 상태를 모두 편집 불가 상태로 간주한다.
- `CanvasToolbar`는 `canEdit`가 false이면 여러 상단 버튼을 아예 렌더하지 않는다.

영향:

- 사용자에게는 버튼이 "사라진 것"처럼 보인다.
- 실제로는 동기화가 live에 도달하지 못해 UI가 숨겨진 것이다.

핵심 코드 포인트:

- `client/src/pages/diagram/DiagramPage.tsx:198`
- `client/src/components/erd/ERDCanvas.tsx:191`
- `client/src/components/erd/CanvasToolbar.tsx:86`

## 결론적으로 가장 가능성 높은 직접 원인

우선순위 기준으로 보면 다음 순서다.

1. `useDiagramSyncStage`의 degraded 복구 경로 단절
2. stale snapshot 복구를 프레임 단위로 수행하는 설계
3. 그 결과로 발생한 편집 잠금 및 툴바 버튼 숨김

## 권장 수정 방향

### 우선 조치 1

`useDiagramSyncStage`가 `yjs-timeout-degraded` 상태에서도 snapshot/sync 완료 콜백을 유지하도록 수정한다.

목표:

- degraded 이후 재시도 응답도 정상적으로 받아 `yjs-live`로 복귀
- 상태 전이와 콜백 생명주기를 분리

### 우선 조치 2

stale snapshot 복구는 snapshot frame마다 즉시 수행하지 말고, snapshot 수신이 완료되었음을 확인한 뒤 1회만 수행하도록 바꾼다.

가능한 방향:

- 서버가 snapshot 완료 메시지를 별도로 보내게 하거나
- 클라이언트가 sync 완료 이후 보정하도록 변경하거나
- 동일 reconnect cycle에서 stale 복구를 1회로 제한하는 가드를 추가

### 우선 조치 3

UI 차원에서는 sync 실패 중에도 꼭 필요한 툴바 버튼을 유지할지 정책을 정리한다.

예시:

- Export, Validation은 readonly 상태에서도 유지 가능
- 편집 기능만 비활성화하고 버튼은 숨기지 않고 disabled 처리하는 방안 검토

## 메모

- 이번 이슈는 빌드 오류가 아니라 런타임 상태머신 회귀다.
- 프런트와 백엔드 snapshot 전달 방식이 동시에 얽혀 있어 한쪽만 부분 수정하면 재발 가능성이 높다.
