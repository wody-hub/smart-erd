# 협업 플랫폼 다음 작업 정리

상태: 종료, 다이어그램 동기화 아키텍처 재설계 계획으로 전환

종료 메모:
- 이 문서는 협업 플랫폼 1차 리팩터링 이후 남은 과제를 정리하던 handoff 문서였지만, 이후 작업은 별도 차수의 다이어그램 동기화 아키텍처 재설계로 흡수한다.
- durability 강화와 저장 모델 재정리는 개별 hotfix/후속 보강으로 이어가지 않고, 별도 다이어그램 동기화 아키텍처 재설계 문서군에서 다시 판단한다.
- 따라서 본 문서는 상태 판정 기록으로만 보존하고, active plan에서는 제외한다.

## 문서 목적

이 문서는 협업 플랫폼 리팩터링 관련 항목을 아래 3가지로 다시 구분한다.

1. 현재 저장소에 **실제로 구현 완료된 내용**
2. 설계 의도 대비 **부분 구현으로 남아 있는 내용**
3. 아직 구현되지 않았거나 저장소 밖 후속으로 남아 있는 내용

즉, 기존의 포괄적인 handoff 메모를 현재 코드 상태 기준의 **상태 판정 문서**로 다시 정리한 버전이다.

## 2. 계획 대비 부분 구현

아래 항목은 "완료"라고 쓰기에는 이르지만, 그렇다고 미구현도 아닌 상태다.  
즉 **1차 구조 분리는 들어갔지만, 설계 문서가 상정한 최종 일반화 수준에는 아직 도달하지 못한 항목**이다.

### 2.1 프론트 공통 collaboration core는 부분 구현 상태

- 상태 머신과 일부 공통 타입은 도입됐지만, 설계 문서에서 상정한 완전한 generic runtime hook은 아직 없다.
- 현재 구조는 `useCollaborationRuntime.ts` 같은 단일 공통 runtime 대신:
  - `useDiagramCollaborationRuntime`
  - `useDiagramCollaborationProvider`
  - `diagram/*`
  조합으로 동작한다.
- 즉 프론트는 **공통 의미 분리까지는 완료**, **완전한 채널 플러그인형 일반화는 아직 미완**이다.

현재 없는 축:
- `client/src/collaboration/core/useCollaborationRuntime.ts`
- `client/src/collaboration/channel/collaboration-channel-plugin.ts`
- `client/src/collaboration/channel/collaboration-handoff.ts`
- `client/src/collaboration/transport/websocket-collaboration-transport.ts`

### 2.2 백엔드 런타임 공통화도 부분 구현 상태

- 채널 등록, ticket, handoff, snapshot 저장소 추상화는 도입됐지만,
  room/presence/relay/runtime 전체가 공통 collaboration core로 완전히 이동한 상태는 아니다.
- 아래 클래스는 여전히 diagram 전용 runtime에 남아 있다.
  - `domain/diagram/websocket/room/DiagramRoomManager.java`
  - `domain/diagram/websocket/room/DiagramSessionRegistry.java`
  - `domain/diagram/websocket/room/DiagramPresenceManager.java`
  - `domain/diagram/websocket/relay/DiagramMessageSender.java`
  - `domain/diagram/websocket/relay/DiagramPresenceNotifier.java`
  - 각종 `relay/handler/*`
- 저장 후 정렬/reconcile도 완전 공통 유스케이스 하나로 수렴한 것은 아니다.
  - 현재는 `SaveDiagramAuthoritativeContentUseCase`
  - `FlushDiagramDrainedUpdatesUseCase`
  - `DiagramSnapshotService`
  조합으로 동작한다.

정리:
- 백엔드는 **채널/진입점/유스케이스 경계는 공통화 완료**
- 하지만 **실시간 room runtime 전체 공통화는 아직 미완**

## 3. 아직 구현 안 된 내용

### 3.1 code mode snapshot durability 강화

이 항목은 아직 구현되지 않았다.

현재 상태:
- `client/src/pages/diagram/DiagramPage.tsx`에 code mode snapshot persist가 존재한다.
- 하지만 이 경로는 여전히 debounce + keepalive 기반이다.
- 파일 내부에 아래 취지의 TODO가 남아 있다.
  - 마지막 입력 직후 서버가 내려가면 최신 draft가 snapshot에 반영되기 전에 유실될 수 있음

즉 현재는:
- 기능은 있음
- 기본 복구 경로도 있음
- 그러나 **마지막 입력 직후 장애까지 강하게 막는 durability 수준은 아직 아님**

### 3.2 authoritative source를 `ydocSnapshot` 중심으로 정리하는 장기 마이그레이션

이 항목도 아직 구현되지 않았다.

현재 상태:
- `content`와 `ydocSnapshot` 경계는 이전보다 명확해졌지만,
- 단일 authoritative source로 완전히 정리된 상태는 아니다.

정리:
- 지금 당장 blocking은 아님
- 하지만 협업 저장 모델을 더 단순하게 만들려면 별도 차수 설계가 필요하다.

## 4. 이번 재정리 기준에서 사실상 닫아도 되는 항목

기존 문서에서 "남아 있다"고 적혀 있었지만, 현재 저장소 기준으로는 대부분 정리된 항목은 아래다.

- `4511` 임시 검증 포트를 문서 표준에서 제거하는 일

즉 문서/실행 기준 정리는 **완전 미착수 항목이 아니라 대부분 반영 완료된 상태**다.  
남아 있더라도 대규모 구현 작업이 아니라 소규모 문서 보정 수준으로 보는 게 맞다.
