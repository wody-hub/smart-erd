## 1. Phase 0 목표

Phase 0의 목표는 현재 협업 기능의 외부 동작을 고정하는 것이다.

목표 기준:
- 3계정 협업 smoke
- save / reload / reconnect
- preview fallback
- warm handoff

주의:
- Phase 0는 모든 시나리오를 초록으로 만드는 단계가 아니다.
- 현재 상태를 정확히 기록하고, 이후 리팩터링에서 같은 시나리오를 다시 비교할 수 있도록 기준선을 확보하는 단계다.

## 4. 브라우저 기준선 검증 결과

실행 명령:

```bash
cd client
SMART_ERD_E2E_LOGIN='wody@riskzero.kr' \
SMART_ERD_E2E_PASSWORD='$%dnel86!R' \
npx playwright test \
  client/e2e/smoke/diagram-work-mode-three-account-collaboration.spec.ts \
  client/e2e/smoke/diagram-preview-lock.spec.ts \
  client/e2e/recovery/diagram-restart-recovery.spec.ts \
  --workers=1 --retries=0 --reporter=line
```

결과 요약:
- `1 passed`
- `2 failed`

### 4.1 통과

#### `diagram-work-mode-three-account-collaboration.spec.ts`

목적:
- 3계정 협업
- code / sync / erd-only 모드 동시 검증
- 수정 전파, reload 이후 shared draft 반영 검증

결과:
- 통과

의미:
- 현재 기준으로 핵심 협업 경로와 cross-mode 전파는 살아 있다.

### 4.2 실패

#### `diagram-restart-recovery.spec.ts`

실패 지점:
- backend restart 직후 persisted 위치 검증은 통과했지만,
  그 이후 원위치로 다시 이동하고 backup한 뒤 최종 복원 검증에서 오차가 허용치 `<= 5`를 초과
- 실제 측정:
  - `Expected <= 5`
  - `Received 8`

실패 위치:
- `client/e2e/recovery/diagram-restart-recovery.spec.ts:62`

해석:
- graceful restart 자체가 즉시 크게 망가진 것은 아니지만,
  `restart 이후 재이동 + 재저장 + 재복원` 경로의 위치 안정성은 현재 기준선에서 완전 green이 아니다.
- 리팩터링 이후 이 오차가 더 커지지 않는지 반드시 다시 비교해야 한다.

#### `diagram-preview-lock.spec.ts`

실패 지점:
- 현재 직접적인 실패 원인은 Playwright locator strict mode 충돌
- 잠금 문구가 2개 동시에 노출돼 아래 assertion이 깨짐:

```ts
page.getByText(
  /미리보기를 먼저 표시했습니다|preview is already visible|편집 잠금|editing locked until sync completes/i,
)
```

실패 위치:
- `client/e2e/smoke/diagram-preview-lock.spec.ts:38`

해석:
- 실제 화면상 preview/lock 관련 문구는 노출되었으나,
  스펙이 단일 element를 기대하는 strict locator로 작성돼 깨졌다.
- 다만 잠금 문구 2개가 동시에 보이는 것이 의도된 UI인지 여부는 이번 기준선 검증만으로 확정하지 않는다.
- 따라서 현재 기준선에서는 `직접 원인은 테스트 안정성 문제, UI 중복 노출 의도 여부는 미확정`으로 기록한다.

## 5. Phase 0 기준선 결론

현재 기준선은 아래처럼 정리한다.

### green
- backend compile
- frontend build
- frontend unit (`176 passed`)
- 3계정 협업 smoke

### yellow
- preview fallback / lock smoke:
  - 실제 문구는 보이나 locator strict mode로 실패
- restart recovery:
  - 위치 복원 오차가 허용치보다 약간 큼 (`8px`)

### 아직 별도 보강 필요
- warm handoff 전용 브라우저 기준선은 현재 별도 스펙으로 독립돼 있지 않음
- 현재는 아래 시나리오를 handoff 근접 기준으로 사용
  - 3계정 협업 smoke의 reload 구간
  - restart recovery 시나리오
- 즉 이번 Phase 0에서 warm handoff는 `직접 검증 완료`가 아니라 `간접 기준선만 확보`된 상태다.

## 6. 리팩터링 전 고정할 원칙

Phase 1 이후에도 아래는 회귀 비교 기준으로 유지한다.

1. `diagram-work-mode-three-account-collaboration.spec.ts`는 계속 green 이어야 한다.
2. `diagram-preview-lock.spec.ts`는 구현 회귀와 테스트 문제를 분리해서 봐야 한다.
3. `diagram-restart-recovery.spec.ts`는 현재 `8px` 오차를 기준선으로 기록하고, 리팩터링 후 더 악화되면 회귀로 본다.
4. `authoritative content / persisted snapshot / warm room state / frontend state machine` 분리는 위 기준선 위에서만 진행한다.
