# 03. 플러그인 통합

## 이 문서의 목적

`MarkdownPlugin`이 협업 문서 플랫폼 코어의 SPI(Service Provider Interface)를 어떻게 구현하는지 매핑한다. 코어 수정 없이 플러그인만으로 동작해야 한다.

## MarkdownPlugin 등록

```typescript
const markdownPlugin: RegisteredDocumentPlugin = {
  pluginId: 'markdown',
  schemaVersion: 1,
  supportedEngineIds: ['yjs'],

  createInputAdapters(context: PluginContext): InputAdapters { ... },
  createMutationPolicy(context: PluginContext): MutationPolicy { ... },
  createProjectors(context: PluginContext): Projector[] { ... },
  createScopeResolver(context: PluginContext): ScopeResolver { ... },
};
```

마크다운 플러그인은 `BaseDocumentPlugin`을 기본으로 구현하고, 이번 구현 범위에서는 4개 capability interface를 구현한다.

```text
MarkdownPlugin
  implements BaseDocumentPlugin              (필수)
  implements TextInputCapablePlugin          (텍스트 편집이 주 입력 경로)
  implements PresenceCapablePlugin           (텍스트 커서, 선택 영역)
  implements ArtifactFallbackCapablePlugin   (마크다운 원문 내보내기/복원)
```

`AssetCapablePlugin`과 이미지 업로드/`asset://` 흐름은 후속 phase에서 추가한다.

현재 범위에서는 4개 capability만 구현하고, 이미지/asset 도메인이 들어오면 5번째 capability로 확장한다.

| Capability | ERD | 화면기획 | 마크다운 |
|---|---|---|---|
| BaseDocumentPlugin | O | O | O |
| TextInputCapablePlugin | O (DSL 보조) | X | **O (주 경로)** |
| AssetCapablePlugin | X | O | **후속 phase** |
| PresenceCapablePlugin | O | O | **O** |
| ArtifactFallbackCapablePlugin | O (content) | X (1단계) | **O** |

### PluginContext 사용 패턴

```text
플러그인이 PluginContext를 사용하는 시점:

  TextInputPipeline → readExecutor로 이전 상태 읽기 → 새 텍스트와 비교
  MutationPolicy    → mutationPort로 Y.Text/Y.Map 변경
  Projector         → readExecutor.execute(query)로 Y.Text 읽기 → AST 파싱 → 뷰 모델
  ScopeResolver     → command 분석만 (PluginContext 불필요, 순수 함수)
  PresenceMapper    → 순수 매핑 함수 (PluginContext 불필요)
  ArtifactSerializer → readExecutor로 Y.Text + Y.Map 읽기 → artifact 생성
  ArtifactCodec     → artifact에서 Y.Text/Y.Map 복원
```

`AssetBinding`은 후속 phase에서만 PluginContext를 사용한다.

## SPI 구현 매핑

### 1. Input Adapters

마크다운의 입력 경로는 텍스트 편집기가 primary이고, 나머지는 보조다.

| Adapter | 입력 | 생성하는 Command Key |
|---|---|---|
| TextEditorAdapter | Monaco 텍스트 입력 | `markdown:body-replace` (1차), `markdown:section-update` (section-aware diff 이후) |
| ToolbarAdapter | 포맷팅 버튼 (Bold, Italic 등) | `markdown:format-apply` |
| FrontmatterFormAdapter | frontmatter 폼 편집 | `markdown:frontmatter-update` |

아웃라인 rail은 1차에서 command source가 아니다. 클릭/하이라이트/scroll-sync는 projector와 local UI state로 처리하고, 섹션 재정렬은 후속 phase로 미룬다.


### 2. TextInputPipeline 구현

이 플러그인의 star — 전체 편집 흐름의 핵심이다.

```typescript
class MarkdownTextInputPipeline implements TextInputPipeline {

  parse(input: string): ParseResult {
    // 1. frontmatter 추출
    const { frontmatter, body } = extractFrontmatter(input);

    // 2. remark 파싱 (GFM 플러그인 포함)
    const ast = unified()
      .use(remarkParse)
      .use(remarkGfm)
      .parse(body);

    // 3. heading 기반 Section 트리 구축
    const sections = buildSectionTree(ast);

    // 4. diagnostics 수집
    const diagnostics = collectParseDiagnostics(ast, frontmatter);

    return { ast, sections, frontmatter, diagnostics };
  }

  validate(result: ParseResult): ValidationResult {
    const diagnostics: Diagnostic[] = [];

    // 1. 중복 heading anchor 검사
    diagnostics.push(...checkDuplicateAnchors(result.sections));

    // 2. 깨진 내부 링크 검사
    diagnostics.push(...checkBrokenInternalLinks(result.ast, result.sections));

    // 3. frontmatter 스키마 검사
    diagnostics.push(...validateFrontmatterSchema(result.frontmatter));

    return {
      valid: diagnostics.every(d => d.severity !== 'error'),
      diagnostics: [...result.diagnostics, ...diagnostics],
    };
  }

  buildCommands(result: ParseResult): DocumentCommand[] {
    // 02-편집-모델에서 정의한 buildCommands 로직
    // 1단계: markdown:body-replace
    // 2단계: markdown:section-update
  }
}
```

### 3. Mutation Policy

```typescript
class MarkdownMutationPolicy implements MutationPolicy {

  toMutation(command: DocumentCommand): DocumentMutation {
    switch (command.key) {
      case 'markdown:body-replace':
        // Y.Text("body")를 새 텍스트로 교체
        // Y.Text.delete + Y.Text.insert를 사용하여 CRDT diff 보존
        break;

      case 'markdown:section-update':
        // 특정 섹션의 텍스트 범위만 교체
        // sectionIndex에서 offset 조회 → Y.Text 부분 교체
        break;

      case 'markdown:frontmatter-update':
        // Y.Map("frontmatter")의 특정 필드 갱신
        break;

      case 'markdown:format-apply':
        // 선택 영역을 마크다운 구문으로 감싸기
        // bold: **text** , italic: *text*, code: `text`
        break;
    }
  }
}
```

### markdown:body-replace의 Y.Text 최적화

```text
전체 교체를 Y.Text에 적용할 때 단순 delete + insert는 CRDT 이점을 상실한다.
대신 텍스트 diff를 계산하여 변경된 부분만 Y.Text에 적용한다.

최적화 흐름:
  1. 이전 Y.Text 값과 새 텍스트를 diff (diff-match-patch 또는 자체 구현)
  2. diff 결과를 Y.Text 연산으로 변환
     - retain(n): n문자 유지
     - delete(n): n문자 삭제
     - insert(text): 텍스트 삽입
  3. Y.Text.applyDelta(operations)로 적용
  4. CRDT가 변경된 부분만 원격 전파
```

### 4. Projectors

```typescript
class MarkdownProjector implements Projector {

  project(readExecutor: DocumentReadExecutor): MarkdownViewModel {
    return readExecutor.execute({
      run(context: DocumentReadContext): MarkdownViewModel {
        const rawText = getRawText(context);
        const frontmatter = getFrontmatter(context);
        const parseResult = parseMarkdown(rawText);
        const previewHtml = renderToHtml(parseResult.ast);
        const toc = buildTableOfContents(parseResult.sections);

        return {
          rawText,
          ast: parseResult.ast,
          sections: parseResult.sections,
          frontmatter,
          previewHtml,
          toc,
          diagnostics: parseResult.diagnostics,
        };
      }
    });
  }
}

interface MarkdownViewModel {
  rawText: string;               // 마크다운 원문
  ast: MdastRoot;                // 파싱된 AST
  sections: Section[];           // 섹션 트리
  frontmatter: Frontmatter;      // 메타데이터
  previewHtml: string;           // HTML 프리뷰
  toc: TableOfContents;          // 목차
  diagnostics: Diagnostic[];     // 경고/에러
}
```

#### Projector 내부에서 DocumentReadContext 사용

```typescript
function getRawText(context: DocumentReadContext): string {
  const contentRef = context.findByKind('content')[0];
  const entity = context.getEntity(contentRef);
  return entity?.props.text as string ?? '';
}

function getFrontmatter(context: DocumentReadContext): Frontmatter {
  const fmRef = context.findByKind('frontmatter')[0];
  const entity = context.getEntity(fmRef);
  return entity?.props as Frontmatter ?? {};
}
```

#### HTML 프리뷰 생성

```text
remark AST → rehype AST → HTML 문자열

변환 파이프라인:
  unified()
    .use(remarkParse)
    .use(remarkGfm)
    .use(remarkRehype)          // mdast → hast 변환
    .use(rehypeStringify)       // hast → HTML 문자열
    .use(rehypeHighlight)       // 코드 블록 구문 하이라이팅
    .processSync(rawText)
```

#### ChangeBus 이벤트 활용

```text
마크다운 플러그인의 ChangeBus 구독 패턴:

  Projector:
    → origin.cause === 'remote'인 이벤트 수신 시
    → Y.Text("body") 최신 값 읽기
    → 재파싱 → previewHtml, toc, sectionIndex 갱신
    → dirty draft 보호 중이면 에디터 본문 overwrite 금지

  TextEditorAdapter:
    → origin.cause === 'remote'인 이벤트 수신 시
    → 현재 DraftState 확인
    → clean이면 에디터 텍스트 즉시 갱신
    → dirty면 remote-pending 전이

  루프 방지 규칙 (코어 04-Command-Event-설계 준수):
    → CollaborationRuntime: remote 이벤트 재전송 금지
    → Projector: dirty draft 보호 중이면 overwrite 금지
    → UndoManager: 원격 변경은 undo 스택 제외
```

### 5. Scope Resolver

마크다운의 락 범위는 **heading 기반 섹션**이다.

```typescript
class MarkdownScopeResolver implements ScopeResolver {

  resolve(command: DocumentCommand): ScopeRef[] {
    switch (command.key) {
      // 특정 섹션 편집 → 섹션 단위 락
      case 'markdown:section-update':
        return [{
          pluginId: 'markdown',
          scopeType: 'section',
          scopeId: command.payload.sectionId,
        }];

      // frontmatter 편집 → 문서 전체 락
      case 'markdown:frontmatter-update':
        return [{
          pluginId: 'markdown',
          scopeType: 'document',
          scopeId: 'root',
        }];

      // 전체 본문 교체 → 변경된 섹션들의 scope
      case 'markdown:body-replace':
        return [{
          pluginId: 'markdown',
          scopeType: 'document',
          scopeId: 'root',
        }];

      // 포맷 적용 → 해당 범위가 속한 섹션
      case 'markdown:format-apply':
        return [{
          pluginId: 'markdown',
          scopeType: 'section',
          scopeId: findSectionByOffset(command.payload.range.start),
        }];

      default:
        return [];
    }
  }

  resolveFocusScope(context: FocusContext): ScopeRef | null {
    // 에디터에서 커서가 위치한 섹션
    if (context.cursorOffset != null) {
      const sectionId = findSectionByOffset(context.cursorOffset);
      if (sectionId) {
        return {
          pluginId: 'markdown',
          scopeType: 'section',
          scopeId: sectionId,
        };
      }
    }

    // frontmatter 편집 중
    if (context.editingFrontmatter) {
      return {
        pluginId: 'markdown',
        scopeType: 'document',
        scopeId: 'root',
      };
    }

    return null;
  }
}
```

| scope type | scope id 예시 | 의미 |
|---|---|---|
| `section` | `section-api-설계` | "API 설계" heading 아래 섹션 편집 중 |
| `section` | `section-root` | heading 이전의 최상위 영역 편집 중 |
| `document` | `root` | frontmatter 또는 문서 구조 변경 중 |

ERD에서 `table/주문`으로 테이블을 잠그듯이, 마크다운에서는 `section/api-설계`로 특정 섹션을 잠근다.

다만 1차 배포의 주 입력 경로는 `markdown:body-replace`이므로, 실제 락 충돌은 우선 `document/root` 기준으로 시작한다. `markdown:section-update`는 section-aware diff가 안정된 뒤 활성화한다.

### 6. Asset Binding (후속 phase)

```typescript
class MarkdownAssetBinding implements AssetBinding {

  collectReferencedAssets(read: DocumentReadExecutor): AssetRef[] {
    return read.execute({
      run(context: DocumentReadContext): AssetRef[] {
        const rawText = getRawText(context);
        const assetRefs: AssetRef[] = [];

        // 후속 phase에서 ![alt](asset://assetId) 패턴에서 asset 참조 수집
        const assetPattern = /!\[([^\]]*)\]\(asset:\/\/([^)]+)\)/g;
        let match;
        while ((match = assetPattern.exec(rawText)) !== null) {
          assetRefs.push({
            assetId: match[2],
            kind: 'image',
          });
        }

        return assetRefs;
      }
    });
  }

  // 코어 AssetBinding에서 optional이지만, 마크다운도 구현함
  buildPreloadHints(assets: AssetRef[]): AssetPreloadHint[] {
    // 마크다운은 스크롤 위치 기반 lazy loading이 유의미
    // 상단 이미지 → eager, 하단 이미지 → lazy
    return assets.map((asset, index) => ({
      assetId: asset.assetId,
      priority: index < 3 ? 'eager' : 'lazy',
    }));
  }
}
```

### 7. Presence Mapper (PresenceCapablePlugin)

```typescript
class MarkdownPresenceMapper implements PresenceMapper {

  toPresencePayload(state: LocalPresenceState): GenericPresencePayload {
    return {
      pointer: state.pointer,
      selection: state.selection,
      pluginPayload: {
        cursorLine: state.pluginState?.cursorLine,
        cursorColumn: state.pluginState?.cursorColumn,
        cursorOffset: state.pluginState?.cursorOffset,
        selectionRange: state.pluginState?.selectionRange,
        editingSectionId: state.pluginState?.editingSectionId,
      },
    };
  }

  applyRemotePresence(payload: GenericPresencePayload, adapter: PresenceAdapter): void {
    const pluginState = payload.pluginPayload as MarkdownPresencePayload;

    // 같은 문서를 편집 중인 참여자의 커서 위치 표시
    adapter.updateRemoteCursor(payload.pointer);
    adapter.updateRemoteSelection(payload.selection);
    adapter.updatePluginPresence({
      cursorLine: pluginState?.cursorLine,
      cursorColumn: pluginState?.cursorColumn,
      editingSectionId: pluginState?.editingSectionId,
    });
  }
}

interface MarkdownPresencePayload {
  cursorLine: number;
  cursorColumn: number;
  cursorOffset: number;
  selectionRange?: { startOffset: number; endOffset: number };
  editingSectionId?: string;
}
```

```typescript
class MarkdownArtifactSerializer implements CompatibilityArtifactSerializer {
  artifactVersion = 1;

  build(readExecutor: DocumentReadExecutor): ArtifactData | null {
    return readExecutor.execute({
      run(context: DocumentReadContext): ArtifactData {
        const rawText = getRawText(context);
        const frontmatter = getFrontmatter(context);

        return {
          version: 1,
          markdown: rawText,
          frontmatter,
        };
      }
    });
  }
}

class MarkdownArtifactCodec implements CompatibilityArtifactCodec {
  restoreFromArtifact(artifact: ArtifactData): RestoreResult {
    // artifact의 마크다운 원문에서 Y.Text 복원
    // artifact의 frontmatter에서 Y.Map 복원
    return {
      contentText: artifact.markdown,
      frontmatter: artifact.frontmatter,
    };
  }
}
```

## DocumentReadContext 매핑

### Entity Kind 정의

| kind | 대응 타입 | 예시 |
|---|---|---|
| `content` | Y.Text 본문 | `{kind: 'content', id: 'main'}` |
| `frontmatter` | Frontmatter | `{kind: 'frontmatter', id: 'main'}` |
| `section` | Section | `{kind: 'section', id: 'section-api-설계'}` |
| `section-index` | SectionIndex | `{kind: 'section-index', id: 'main'}` |
| `metadata` | 문서 설정 | `{kind: 'metadata', id: 'main'}` |

### Relation 정의

| 출발 kind | relation | 결과 kind |
|---|---|---|
| `content` | `sections` | `section` |
| `section` | `blocks` | (AST에서 파생, ReadContext에서 직접 제공하지 않음) |
| `section` | `subsections` | `section` (재귀) |

마크다운은 화면기획과 달리 대부분의 데이터가 Y.Text에서 **파싱으로 파생**된다. ReadContext의 entity/relation 구조가 비교적 단순한 이유다.

### 조회 예시

```typescript
// 본문 텍스트 조회
const contentRef = readContext.findByKind('content')[0];

const subsections = readContext.listRelated(

  'subsections'

```

## 3-플러그인 비교 테이블

| 구성요소 | ERD Plugin | ScreenSpec Plugin | Markdown Plugin |
|---|---|---|---|
| Input Adapter | Canvas(드래그) + Text(DSL) | Canvas(인스턴스 배치) + PropertyPanel | **Text(Monaco 주) + Toolbar + Outline** |
| TextInputPipeline | DSL 파서 + 검증 | 없음 | **remark 파서 + 검증 (핵심)** |
| Mutation Policy | 테이블/컬럼/엣지 CRUD | 컴포넌트/인스턴스/화면 CRUD | **Y.Text 교체 + Y.Map 갱신** |
| Projector | ReactFlow 노드/엣지 뷰 모델 | 화면별 렌더 노드 트리 | **rawText + AST + HTML + TOC** |
| Scope Resolver | `table/{tableId}` | `component/{id}`, `screen/{id}` | **`section/{id}`, `document/root`** |
| Asset Binding | 없음 | ImagePlaceholder → 이미지 | **후속 phase에서 `asset://` URI 패턴** |
| Presence Mapper | 테이블 위 커서 | 캔버스 커서 + 활성 화면 | **텍스트 커서(line/col) + 섹션** |
| Artifact Serializer | content JSON (호환) | 미구현 (1단계) | **마크다운 원문 + frontmatter** |
| Primary CRDT | Y.Map | Y.Map | **Y.Text** |
| DraftState | 코드 편집기 한정 | 미사용 | **모든 편집에 적용** |

## 코어가 그대로 재사용되는 부분

| 코어 모듈 | 마크다운에서의 역할 |
|---|---|
| DocumentSession | 마크다운 문서 진입/나가기/reconnect |
| DocumentStore | Y.Text + Y.Map의 공유 상태 관리 |
| SharedDocumentEngine | Y.Doc 기반 CRDT 동기화 |
| ChangeBus | 텍스트 변경 → 프리뷰 갱신 이벤트 전파 |
| CollaborationRuntime | 원격 delta 송수신 |
| ScopeLockRuntime | 섹션/문서 단위 편집 락 |
| PresenceRuntime | 텍스트 커서, 선택 영역, 편집 중 섹션 공유 |
| PersistenceCoordinator | 스냅샷 저장/복구 |

현재 구현 범위에서는 AssetRuntime을 제외한 코어 모듈을 수정 없이 재사용한다. 이미지 도메인이 추가되면 AssetRuntime까지 같은 방식으로 연결한다.
