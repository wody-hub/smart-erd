# 01. 도메인 모델

## 전체 엔티티 관계

```text
[Project]
  └─< [MarkdownDocument]
        ├─ [Frontmatter]              (YAML 메타데이터)
        ├─ [TableOfContents]          (heading 기반 자동 생성)
        └─< [Section]                 (heading 기반 구역)
              └─< [Block]             (블록 레벨 요소)
                    └─< [Inline]      (인라인 레벨 요소)
```

## 1. 최상위 문서

```typescript
interface MarkdownDocument {
  documentId: string;
  name: string;
  frontmatter: Frontmatter;
  sections: Section[];
  toc: TableOfContents;
}
```

마크다운 문서는 하나의 프로젝트 내에서 독립된 문서 단위다. ERD 다이어그램이 `Diagram` 엔티티에 `pluginId: 'erd'`로 매핑되듯이, 마크다운 문서는 동일한 `Document` 엔티티에 `pluginId: 'markdown'`으로 매핑된다.

## 2. Frontmatter (YAML 메타데이터)

```typescript
interface Frontmatter {
  title?: string;
  author?: string;
  date?: string;
  tags?: string[];
  status?: 'draft' | 'review' | 'approved' | 'published';
  custom: Record<string, string | number | boolean | string[]>;
}
```

Frontmatter는 문서 상단의 YAML 메타데이터 블록이다.

```markdown
---
title: API 설계 문서
author: 홍길동
date: 2026-03-26
tags: [api, rest, design]
status: draft
---
```

Frontmatter는 문서 본문과 별도로 관리한다. 본문이 Y.Text인 것과 달리 frontmatter는 Y.Map으로 저장하여 개별 필드 단위 CRDT 병합을 지원한다.

## 3. 목차 (Table of Contents)

```typescript
interface TableOfContents {
  entries: TocEntry[];
}

interface TocEntry {
  sectionId: string;
  level: number;        // 1~6 (h1~h6)
  text: string;         // heading 텍스트
  anchor: string;       // 자동 생성 anchor (kebab-case)
  children: TocEntry[];
}
```

목차는 heading 기반으로 **자동 생성**되는 파생 데이터다. 공유 상태에 직접 저장하지 않고, Projector가 AST에서 heading을 추출하여 생성한다.

```text
TOC 생성 규칙:
  1. 모든 Heading 블록을 순서대로 수집
  2. level에 따라 트리 구조 생성 (h1 > h2 > h3 ...)
  3. anchor는 텍스트를 kebab-case로 변환 (중복 시 -1, -2 접미사)
  4. 클릭 시 해당 섹션으로 스크롤
```

## 4. 섹션

```typescript
interface Section {
  id: string;
  headingLevel: number;     // 1~6
  headingText: string;      // heading 원문
  anchor: string;           // kebab-case anchor
  blocks: Block[];          // 이 섹션에 속하는 블록들
  subsections: Section[];   // 하위 섹션 (재귀)
}
```

섹션은 마크다운 문서를 **heading 기반으로 분할한 논리적 구역**이다. 이 구역이 scope lock의 기본 단위가 된다.

```text
섹션 분할 규칙:
  1. heading이 나타나면 새 섹션 시작
  2. 같거나 상위 level의 heading이 나타나면 현재 섹션 종료
  3. heading 이전의 블록은 "root" 섹션에 속함
  4. heading이 없는 문서는 단일 "root" 섹션

예시:
  # 제목              → Section(level=1, id="제목")
  본문 텍스트          →   blocks에 포함
  ## 하위 제목 1       → Section(level=2, id="하위-제목-1") — subsection
  본문 텍스트          →   blocks에 포함
  ## 하위 제목 2       → Section(level=2, id="하위-제목-2") — subsection
  ### 더 하위 제목     → Section(level=3, id="더-하위-제목") — sub-subsection
```

## 5. 블록 (Block)

블록은 마크다운의 블록 레벨 요소다.

```typescript
type Block =
  | Paragraph
  | Heading
  | CodeBlock
  | Blockquote
  | ListBlock
  | TableBlock
  | ThematicBreak
  | ImageBlock
  | HtmlBlock;

interface BlockBase {
  id: string;
  type: string;
  position: SourcePosition;
}

interface SourcePosition {
  startLine: number;
  startColumn: number;
  endLine: number;
  endColumn: number;
  startOffset: number;
  endOffset: number;
}
```

### 5-1. Paragraph

```typescript
interface Paragraph extends BlockBase {
  type: 'paragraph';
  children: Inline[];
}
```

### 5-2. Heading

```typescript
interface Heading extends BlockBase {
  type: 'heading';
  depth: 1 | 2 | 3 | 4 | 5 | 6;
  children: Inline[];
}
```

### 5-3. CodeBlock

```typescript
interface CodeBlock extends BlockBase {
  type: 'code';
  lang?: string;      // "typescript", "java", "sql" 등
  meta?: string;       // 코드 블록 메타 (예: 파일명)
  value: string;       // 코드 본문
}
```

### 5-4. Blockquote

```typescript
interface Blockquote extends BlockBase {
  type: 'blockquote';
  children: Block[];   // 블록 레벨 중첩 가능
}
```

### 5-5. List

```typescript
interface ListBlock extends BlockBase {
  type: 'list';
  ordered: boolean;
  start?: number;      // 순서 목록의 시작 번호
  spread: boolean;     // 느슨한 목록 여부
  children: ListItem[];
}

interface ListItem {
  id: string;
  checked?: boolean;   // 체크리스트 (null이면 일반 항목)
  spread: boolean;
  children: Block[];   // 블록 레벨 중첩 가능
}
```

### 5-6. Table

```typescript
interface TableBlock extends BlockBase {
  type: 'table';
  align: Array<'left' | 'center' | 'right' | null>;
  children: TableRow[];
}

interface TableRow {
  id: string;
  children: TableCell[];
}

interface TableCell {
  id: string;
  children: Inline[];
}
```

### 5-7. ThematicBreak

```typescript
interface ThematicBreak extends BlockBase {
  type: 'thematicBreak';
}
```

### 5-8. ImageBlock

```typescript
interface ImageBlock extends BlockBase {
  type: 'image';
  url: string;          // 이미지 URL 또는 asset://xxx 참조
  alt: string;
  title?: string;
}
```

### 5-9. HtmlBlock

```typescript
interface HtmlBlock extends BlockBase {
  type: 'html';
  value: string;        // raw HTML
}
```

## 6. 인라인 (Inline)

인라인은 블록 내부의 텍스트 레벨 요소다.

```typescript
type Inline =
  | TextNode
  | BoldNode
  | ItalicNode
  | InlineCodeNode
  | LinkNode
  | InlineImageNode
  | StrikethroughNode
  | LineBreakNode;

interface TextNode {
  type: 'text';
  value: string;
}

interface BoldNode {
  type: 'strong';
  children: Inline[];
}

interface ItalicNode {
  type: 'emphasis';
  children: Inline[];
}

interface InlineCodeNode {
  type: 'inlineCode';
  value: string;
}

interface LinkNode {
  type: 'link';
  url: string;
  title?: string;
  children: Inline[];
}

interface InlineImageNode {
  type: 'image';
  url: string;
  alt: string;
  title?: string;
}

interface StrikethroughNode {
  type: 'delete';
  children: Inline[];
}

interface LineBreakNode {
  type: 'break';
}
```

## 7. mdast 표준과의 매핑

이 도메인 모델은 [mdast (Markdown Abstract Syntax Tree)](https://github.com/syntax-tree/mdast) 표준을 따른다. remark 파서가 생성하는 AST와 1:1 대응한다.

| 우리 타입 | mdast 타입 | 비고 |
|---|---|---|
| Paragraph | `paragraph` | 동일 |
| Heading | `heading` | `depth` 필드 동일 |
| CodeBlock | `code` | `lang`, `meta`, `value` 동일 |
| Blockquote | `blockquote` | 동일 |
| ListBlock | `list` | `ordered`, `start`, `spread` 동일 |
| ListItem | `listItem` | `checked`, `spread` 동일 |
| TableBlock | `table` | GFM 확장 |
| TableRow | `tableRow` | GFM 확장 |
| TableCell | `tableCell` | GFM 확장 |
| ThematicBreak | `thematicBreak` | 동일 |
| ImageBlock | `image` | 블록/인라인 컨텍스트에 따라 구분 |
| HtmlBlock | `html` | 동일 |
| TextNode | `text` | 동일 |
| BoldNode | `strong` | 동일 |
| ItalicNode | `emphasis` | 동일 |
| InlineCodeNode | `inlineCode` | 동일 |
| LinkNode | `link` | 동일 |
| StrikethroughNode | `delete` | GFM 확장 |
| LineBreakNode | `break` | 동일 |

mdast 표준을 따르는 이유:

1. remark 파서가 직접 생성하는 AST 구조와 동일하여 변환 비용 없음
2. rehype(HTML 변환), remark-stringify(MD 재생성) 등 unified 생태계 재사용
3. GFM(GitHub Flavored Markdown) 확장이 표준화되어 있음

## 8. Y.Doc 매핑

화면기획 플러그인이 Y.Map 위주로 구조화된 데이터를 저장하는 것과 달리, 마크다운 플러그인은 **Y.Text가 primary**다.

```text
Y.Doc root
├─ Y.Text("content")           ← Primary: 마크다운 원문 텍스트
├─ Y.Map("frontmatter")        ← 메타데이터 (개별 필드 단위 병합)
├─ Y.Map("sectionIndex")       ← 섹션 ID → offset 인덱스 (lock 범위 매핑)
└─ Y.Map("metadata")           ← 문서 설정 (프리뷰 모드, 템플릿 등)
```

### Y.Text("content")

마크다운 본문 전체를 하나의 Y.Text에 저장한다.

```text
Y.Text 선택 근거:
  1. 마크다운은 순수 텍스트 — 문자 단위 CRDT 병합이 자연스러움
  2. Y.Text는 문자 삽입/삭제를 자동으로 병합
  3. 두 사용자가 다른 위치에 동시 타이핑해도 CRDT가 자동 해결
  4. Y.Map으로 블록별 분리하면 블록 경계 편집(Enter, Backspace)에서 복잡한 동기화 필요
```

### Y.Map("frontmatter")

```text
Y.Map 구조:
  "title" → string
  "author" → string
  "date" → string
  "tags" → Y.Array<string>
  "status" → string
  "custom" → Y.Map<string, unknown>
```

frontmatter를 Y.Map으로 분리하는 이유:

1. frontmatter는 구조화된 키-값 데이터 — Y.Map이 적합
2. 두 사용자가 다른 필드를 동시에 편집해도 충돌 없음 (키 단위 병합)
3. 본문 Y.Text와 독립적으로 변경 가능

### Y.Map("sectionIndex")

```text
Y.Map 구조:
  "section-제목" → { startOffset: number, endOffset: number }
  "section-하위-제목-1" → { startOffset: number, endOffset: number }
  ...
```

sectionIndex는 Projector가 AST 파싱 후 갱신하는 **파생 인덱스**다. ScopeLockRuntime이 lock 범위를 텍스트 offset과 매핑할 때 사용한다.

### 화면기획(Y.Map 위주)과의 핵심 차이

| 비교 항목 | 화면기획 | 마크다운 |
|---|---|---|
| Primary 공유 타입 | Y.Map (컴포넌트, 화면, 인스턴스) | Y.Text (본문 텍스트) |
| 보조 공유 타입 | Y.Array (순서, 목록) | Y.Map (frontmatter, 인덱스) |
| 병합 단위 | 엔티티 필드 | 문자 |
| 구조 변경 | Y.Map 키 추가/삭제 | 텍스트 내 heading 추가/삭제 |
| 충돌 유형 | 같은 필드 동시 수정 | 같은 줄 동시 편집 |
| 충돌 해결 | Y.Map last-writer-wins | Y.Text 문자 단위 CRDT 병합 |

## 9. 엔티티 수준 요약

| 엔티티 | 단위 | 저장 위치 |
|---|---|---|
| MarkdownDocument | 문서 | 엔티티 메타 (pluginId, engineId) |
| Frontmatter | 문서 내 1개 | Y.Map("frontmatter") |
| 본문 텍스트 | 문서 내 1개 | Y.Text("content") |
| Section | heading 기반 N개 | AST 파싱 결과 (파생) |
| Block | 섹션 내 N개 | AST 파싱 결과 (파생) |
| Inline | 블록 내 N개 | AST 파싱 결과 (파생) |
| TableOfContents | 문서 내 1개 | heading 기반 자동 생성 (파생) |
| SectionIndex | 문서 내 1개 | Y.Map("sectionIndex") (파생 인덱스) |

핵심 관찰: Section, Block, Inline, TOC는 모두 **Y.Text("content")에서 파싱하여 파생되는 데이터**다. 화면기획에서 모든 엔티티가 Y.Map에 직접 저장되는 것과 근본적으로 다르다. 마크다운의 source of truth는 텍스트 원문이다.
