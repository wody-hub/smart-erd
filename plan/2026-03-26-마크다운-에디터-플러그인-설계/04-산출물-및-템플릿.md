# 04. 산출물 및 템플릿

## 1. 목차 (TOC) 네비게이션

### TOC 자동 생성

```text
TOC 생성 흐름:
  1. Projector가 AST 파싱 시 모든 Heading 블록 수집
  2. heading level에 따라 트리 구조 생성
  3. 각 heading에 kebab-case anchor 할당
  4. 중복 anchor는 -1, -2 접미사 추가
  5. UI의 아웃라인 패널에 트리 렌더링
```

### TOC 예시

```text
마크다운 원문:
  # API 설계 문서
  ## 개요
  ## 엔드포인트
  ### 사용자 API
  ### 주문 API
  ## 인증
  ### JWT 토큰
  ### OAuth2

TOC 트리:
  ├─ API 설계 문서 (#api-설계-문서)
  │  ├─ 개요 (#개요)
  │  ├─ 엔드포인트 (#엔드포인트)
  │  │  ├─ 사용자 API (#사용자-api)
  │  │  └─ 주문 API (#주문-api)
  │  └─ 인증 (#인증)
  │     ├─ JWT 토큰 (#jwt-토큰)
  │     └─ OAuth2 (#oauth2)
```

### TOC 인터랙션

| 동작 | 결과 |
|---|---|
| 항목 클릭 | 에디터에서 해당 heading 줄로 스크롤 + 프리뷰에서 해당 섹션으로 스크롤 |
| 항목 드래그 | 섹션 순서 변경 (section.move 커맨드 생성) |
| 항목 우클릭 | 컨텍스트 메뉴: 삭제, 접기/펼치기 |
| 에디터 커서 이동 | 현재 커서가 위치한 섹션에 해당하는 TOC 항목 하이라이트 |

### 드래그로 섹션 순서 변경

```text
아웃라인 패널에서 "주문 API"를 "사용자 API" 위로 드래그:

  변경 전 에디터:                      변경 후 에디터:
  ## 엔드포인트                        ## 엔드포인트
  ### 사용자 API                       ### 주문 API       ← 이동됨
  사용자 관련 API...                   주문 관련 API...
  ### 주문 API                         ### 사용자 API
  주문 관련 API...                     사용자 관련 API...

  → section.move 커맨드 생성
  → MutationPolicy가 Y.Text에서 섹션 텍스트 블록을 이동
```

## 2. 내보내기 형식

| 형식 | 용도 | 내용 |
|---|---|---|
| HTML | 웹 공유 | 스타일 포함 단일 HTML 파일 |
| PDF | 인쇄/배포 | 목차 + 본문 + 코드 하이라이팅 |
| 원문 MD | 백업/외부 편집기 | 마크다운 원문 + frontmatter |

### HTML 내보내기

```text
변환 파이프라인:
  1. Y.Text("content")에서 마크다운 원문 추출
  2. remark → rehype 변환
  3. rehype-highlight로 코드 블록 구문 하이라이팅
  4. 내장 CSS 스타일 삽입 (GitHub 스타일 기반)
  5. TOC를 HTML 사이드바로 포함 (선택)
  6. 단일 HTML 파일로 출력

기술 스택:
  unified + remark-parse + remark-gfm + remark-rehype + rehype-stringify + rehype-highlight
```

### PDF 내보내기

```text
생성 흐름:
  1. HTML 내보내기 파이프라인으로 HTML 생성
  2. jsPDF에 HTML 렌더링
  3. 페이지 레이아웃 구성
     - 표지: 문서 제목, 작성자, 날짜 (frontmatter 기반)
     - 목차: TOC 트리를 페이지 번호와 함께 렌더링
     - 본문: 마크다운 본문 (페이지 나누기 포함)
  4. 코드 블록 스타일 보존
  5. 이미지 포함 (asset:// → 실제 이미지 URL 변환)

대안 (향후):
  - Puppeteer 서버사이드 렌더링 → 더 정확한 PDF 품질
  - 백엔드 서비스 필요
```

### PDF 산출물 구조

```text
[표지]
  문서명: API 설계 문서
  작성자: 홍길동
  작성일: 2026-03-26
  상태: 검토 중

[목차]
  1. 개요 ...................... 2
  2. 엔드포인트 ................ 3
    2.1 사용자 API ............. 3
    2.2 주문 API ............... 5
  3. 인증 ...................... 7
    3.1 JWT 토큰 ............... 7
    3.2 OAuth2 ................. 8

[본문]
  각 섹션의 마크다운 렌더링 결과
  코드 블록은 구문 하이라이팅 포함
  이미지는 인라인 포함
  테이블은 스타일 적용
```

### 원문 MD 내보내기

```text
가장 단순한 내보내기:
  1. Y.Text("content")에서 마크다운 원문 추출
  2. Y.Map("frontmatter")에서 YAML 메타데이터 추출
  3. --- frontmatter --- + 본문을 하나의 .md 파일로 출력

용도:
  - 외부 마크다운 에디터에서 편집
  - Git 리포지토리에 보관
  - 백업
```

## 3. 내장 문서 템플릿

처음부터 빈 문서에서 시작하면 사용성이 낮다. 주요 기술 문서 형식에 맞는 내장 템플릿을 제공한다.

### 템플릿 목록

| 템플릿 | 용도 | 포함 섹션 |
|---|---|---|
| 빈 문서 | 자유 작성 | 제목 + frontmatter만 |
| 회의록 | 정기/비정기 회의 | 참석자, 안건, 논의 내용, 결정 사항, 액션 아이템 |
| 기술 설계 문서 (RFC) | 설계 제안 | 배경, 목표, 제안, 대안, 결정, 구현 계획 |
| API 문서 | REST API 명세 | 개요, 인증, 엔드포인트 목록, 에러 코드 |
| README | 프로젝트 소개 | 프로젝트 소개, 시작하기, 사용법, 기여 방법, 라이선스 |
| 릴리스 노트 | 버전 출시 기록 | 버전, 날짜, 신규 기능, 개선, 버그 수정, 참고 사항 |

### 템플릿 예시: 기술 설계 문서 (RFC)

```markdown
---
title: [제목]
author: [작성자]
date: 2026-03-26
status: draft
tags: [design, rfc]
---

# [제목]

## 1. 배경

이 문서를 작성하게 된 배경과 현재 문제를 설명한다.

## 2. 목표

이 설계가 달성하려는 목표를 명확하게 정의한다.

### 2.1 이번 범위

- ...

### 2.2 이번 범위에서 제외

- ...

## 3. 제안

### 3.1 전체 구조

제안하는 아키텍처 또는 설계를 설명한다.

### 3.2 상세 설계

구현 수준의 상세 설계를 기술한다.

## 4. 대안 검토

고려했으나 채택하지 않은 대안을 기록한다.

| 대안 | 장점 | 단점 | 미채택 사유 |
|------|------|------|-------------|
| ... | ... | ... | ... |

## 5. 결정

최종 결정 사항과 근거를 명시한다.

## 6. 구현 계획

### 6.1 단계별 계획

1. ...
2. ...

### 6.2 검증 기준

- [ ] ...
- [ ] ...

## 7. 참고 자료

- ...
```

### 템플릿 예시: 회의록

```markdown
---
title: [회의 제목]
author: [작성자]
date: 2026-03-26
status: draft
tags: [meeting]
---

# [회의 제목]

## 회의 정보

- **일시**: 2026-03-26 14:00~15:00
- **장소**: ...
- **참석자**: ...

## 안건

1. ...
2. ...

## 논의 내용

### 안건 1: ...

- ...

### 안건 2: ...

- ...

## 결정 사항

| # | 결정 | 담당자 | 기한 |
|---|------|--------|------|
| 1 | ... | ... | ... |

## 액션 아이템

- [ ] ...
- [ ] ...

## 다음 회의

- **일시**: ...
- **안건**: ...
```

### 템플릿 초기화 메커니즘

```text
템플릿 적용 시점:
  새 마크다운 문서 생성 시 (사용자가 템플릿 선택)

초기화 흐름:
  1. 문서 생성 다이얼로그에서 템플릿 선택
  2. DocumentSession이 빈 문서로 최초 진입
  3. MutationPolicy.initializeDocument(templateId) 호출
  4. 선택된 템플릿의 마크다운 텍스트를 Y.Text("content")에 삽입
  5. 템플릿의 기본 frontmatter를 Y.Map("frontmatter")에 설정

템플릿 데이터 소스:
  MarkdownPlugin 내부에 정적으로 정의된 templates.ts 모듈
  → 코어에는 템플릿 개념이 존재하지 않음 (플러그인 내부 규칙)

기존 문서 진입 시:
  Y.Text("content")가 이미 존재하면 초기화를 건너뜀
```

## 4. 향후 확장

### GFM (GitHub Flavored Markdown)

```text
1단계에서 기본 지원:
  - 테이블 (remark-gfm)
  - 취소선 (remark-gfm)
  - 체크리스트 (remark-gfm)
  - 자동 링크 (remark-gfm)
```

### Mermaid 다이어그램 (향후)

```text
확장 방향:
  - 코드 블록 내 ```mermaid 구문 감지
  - mermaid.js로 SVG 렌더링
  - 프리뷰 패널에 다이어그램 표시

주의:
  - 에디터는 텍스트 그대로 표시 (구문 하이라이팅만)
  - 다이어그램 렌더링은 프리뷰 패널에서만
```

### KaTeX 수식 (향후)

```text
확장 방향:
  - 인라인 수식: $E = mc^2$
  - 블록 수식: $$ ... $$
  - remark-math + rehype-katex 플러그인
```

### 커스텀 확장 포인트

```text
remark/rehype 플러그인 체계를 활용하면 향후 확장이 용이하다:
  - remark 플러그인: AST 변환 (파싱 확장)
  - rehype 플러그인: HTML 변환 (프리뷰 확장)
  - 플러그인 추가 시 코어 수정 불필요
```
