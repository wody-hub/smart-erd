# 04. 산출물 및 템플릿

## 1. 목차 (TOC) 네비게이션

### TOC 자동 생성

```text
TOC 생성 흐름:
  1. Projector가 AST 파싱 시 모든 Heading 블록 수집
  2. heading level에 따라 트리 구조 생성
  3. 각 heading에 kebab-case anchor 할당
  4. 중복 anchor는 -1, -2 접미사 추가
  5. UI의 아웃라인 패널에 트리 렌더링
```

### TOC 예시

```text
마크다운 원문:
  # API 설계 문서
  ## 개요
  ## 엔드포인트
  ### 사용자 API
  ### 주문 API
  ## 인증
  ### JWT 토큰
  ### OAuth2

TOC 트리:
  ├─ API 설계 문서 (#api-설계-문서)
  │  ├─ 개요 (#개요)
  │  ├─ 엔드포인트 (#엔드포인트)
  │  │  ├─ 사용자 API (#사용자-api)
  │  │  └─ 주문 API (#주문-api)
  │  └─ 인증 (#인증)
  │     ├─ JWT 토큰 (#jwt-토큰)
  │     └─ OAuth2 (#oauth2)
```

### TOC 인터랙션

| 동작 | 결과 |
|---|---|
| 항목 클릭 | 에디터에서 해당 heading 줄로 스크롤 + 프리뷰에서 해당 섹션으로 스크롤 |
| 항목 우클릭 | 컨텍스트 메뉴: 삭제, 접기/펼치기 |
| 에디터 커서 이동 | 현재 커서가 위치한 섹션에 해당하는 TOC 항목 하이라이트 |

1차 릴리즈의 TOC는 navigation과 현재 위치 가시화에 집중한다. 아웃라인 드래그를 통한 섹션 재정렬은 후속 phase에서 다시 검토한다.

### 1차 범위의 TOC 제약

```text
초기 릴리즈의 아웃라인 rail은 아래만 책임진다.

  - heading 트리 렌더링
  - 현재 커서 위치 섹션 하이라이트
  - 에디터/프리뷰 scroll sync
  - 잠긴 섹션, 참여자 상태 표시

섹션 구조 변경은 Monaco 본문 편집을 source of truth로 유지하고,
rail에서의 drag reorder는 후속 phase로 미룬다.
```

## 2. 내보내기 형식

| 형식 | 용도 | 내용 |
|---|---|---|
| HTML | 웹 공유 | 스타일 포함 단일 HTML 파일 |
| 원문 MD | 백업/외부 편집기 | 마크다운 원문 + frontmatter |

### HTML 내보내기

```text
변환 파이프라인:
  1. Y.Map("frontmatter") + Y.Text("body")에서 canonical buffer 구성
  2. body 영역만 remark → rehype 변환
  3. rehype-highlight로 코드 블록 구문 하이라이팅
  4. 내장 CSS 스타일 삽입 (GitHub 스타일 기반)
  5. TOC를 HTML 사이드바로 포함 (선택)
  6. 단일 HTML 파일로 출력

기술 스택:
  unified + remark-parse + remark-gfm + remark-rehype + rehype-stringify + rehype-highlight
```

### PDF 내보내기

```text
PDF는 이번 범위에서 제외한다.

이유:
  1. 현재 저장소 의존성 기준으로는 서버/클라이언트 어느 쪽도 PDF를 안정적으로 생산하는 계약이 잠기지 않았다
  2. 1차 목표는 협업 문서 작성 흐름과 preview/export sanitize 일관성 검증이다
  3. HTML/원문 MD 내보내기만으로도 문서 플랫폼의 핵심 가치는 검증된다

후속 phase에서 별도 export 전략과 렌더러를 확정한 뒤 다시 설계한다.
```

### 원문 MD 내보내기

```text
가장 단순한 내보내기:
  1. Y.Text("body")에서 마크다운 본문 추출
  2. Y.Map("frontmatter")에서 YAML 메타데이터 추출
  3. --- frontmatter --- + 본문을 하나의 .md 파일로 출력

용도:
  - 외부 마크다운 에디터에서 편집
  - Git 리포지토리에 보관
  - 백업
```

## 3. 내장 문서 템플릿

처음부터 빈 문서에서 시작하면 사용성이 낮다. 주요 기술 문서 형식에 맞는 내장 템플릿을 제공한다.

### 템플릿 목록

| 템플릿 | 용도 | 포함 섹션 |
|---|---|---|
| 빈 문서 | 자유 작성 | 제목 + frontmatter만 |
| 회의록 | 정기/비정기 회의 | 참석자, 안건, 논의 내용, 결정 사항, 액션 아이템 |
| 기술 설계 문서 (RFC) | 설계 제안 | 배경, 목표, 제안, 대안, 결정, 구현 계획 |
| API 문서 | REST API 명세 | 개요, 인증, 엔드포인트 목록, 에러 코드 |
| README | 프로젝트 소개 | 프로젝트 소개, 시작하기, 사용법, 기여 방법, 라이선스 |
| 릴리스 노트 | 버전 출시 기록 | 버전, 날짜, 신규 기능, 개선, 버그 수정, 참고 사항 |

### 템플릿 예시: 기술 설계 문서 (RFC)

```markdown
---
title: [제목]
author: [작성자]
date: 2026-03-26
status: draft
tags: [design, rfc]
---

# [제목]

## 1. 배경

이 문서를 작성하게 된 배경과 현재 문제를 설명한다.

## 2. 목표

이 설계가 달성하려는 목표를 명확하게 정의한다.

### 2.1 이번 범위

- ...

### 2.2 이번 범위에서 제외

- ...

## 3. 제안

### 3.1 전체 구조

제안하는 아키텍처 또는 설계를 설명한다.

### 3.2 상세 설계

구현 수준의 상세 설계를 기술한다.

## 4. 대안 검토

고려했으나 채택하지 않은 대안을 기록한다.

| 대안 | 장점 | 단점 | 미채택 사유 |
|------|------|------|-------------|
| ... | ... | ... | ... |

## 5. 결정

최종 결정 사항과 근거를 명시한다.

## 6. 구현 계획

### 6.1 단계별 계획

1. ...
2. ...

### 6.2 검증 기준

- [ ] ...
- [ ] ...

## 7. 참고 자료

- ...
```

### 템플릿 예시: 회의록

```markdown
---
title: [회의 제목]
author: [작성자]
date: 2026-03-26
status: draft
tags: [meeting]
---

# [회의 제목]

## 회의 정보

- **일시**: 2026-03-26 14:00~15:00
- **장소**: ...
- **참석자**: ...

## 안건

1. ...
2. ...

## 논의 내용

### 안건 1: ...

- ...

### 안건 2: ...

- ...

## 결정 사항

| # | 결정 | 담당자 | 기한 |
|---|------|--------|------|
| 1 | ... | ... | ... |

## 액션 아이템

- [ ] ...
- [ ] ...

## 다음 회의

- **일시**: ...
- **안건**: ...
```

### 템플릿 초기화 메커니즘

```text
템플릿 적용 시점:
  새 마크다운 문서 생성 시 (사용자가 템플릿 선택)

초기화 흐름:
  1. 문서 생성 다이얼로그에서 템플릿 선택
  2. DocumentSession이 빈 문서로 최초 진입
  3. MutationPolicy.initializeDocument(templateId) 호출
  4. 선택된 템플릿 문자열을 frontmatter/body로 분리
  5. 템플릿의 본문을 Y.Text("body")에 삽입
  6. 템플릿의 기본 frontmatter를 Y.Map("frontmatter")에 설정

템플릿 데이터 소스:
  MarkdownPlugin 내부에 정적으로 정의된 templates.ts 모듈
  → 코어에는 템플릿 개념이 존재하지 않음 (플러그인 내부 규칙)

기존 문서 진입 시:
  Y.Text("body")가 이미 존재하면 초기화를 건너뜀
```

## 4. 향후 확장

### GFM (GitHub Flavored Markdown)

```text
1단계에서 기본 지원:
  - 테이블 (remark-gfm)
  - 취소선 (remark-gfm)
  - 체크리스트 (remark-gfm)
  - 자동 링크 (remark-gfm)
```

### Mermaid 다이어그램 (향후)

```text
확장 방향:
  - 코드 블록 내 ```mermaid 구문 감지
  - mermaid.js로 SVG 렌더링
  - 프리뷰 패널에 다이어그램 표시

주의:
  - 에디터는 텍스트 그대로 표시 (구문 하이라이팅만)
  - 다이어그램 렌더링은 프리뷰 패널에서만
```

### KaTeX 수식 (향후)

```text
확장 방향:
  - 인라인 수식: $E = mc^2$
  - 블록 수식: $$ ... $$
  - remark-math + rehype-katex 플러그인
```

### 커스텀 확장 포인트

```text
remark/rehype 플러그인 체계를 활용하면 향후 확장이 용이하다:
  - remark 플러그인: AST 변환 (파싱 확장)
  - rehype 플러그인: HTML 변환 (프리뷰 확장)
  - 플러그인 추가 시 코어 수정 불필요
```
