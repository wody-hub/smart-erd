# WBS 전속성 편집 QA 체크리스트

## 대상

- parent issue: [RIS-239](/RIS/issues/RIS-239)
- 구현 issue: [RIS-240](/RIS/issues/RIS-240)
- QA issue: [RIS-241](/RIS/issues/RIS-241)

## 사전 조건

- [RIS-240](/RIS/issues/RIS-240) 에서 구현 완료 코멘트와 검증 포인트가 남아 있어야 한다.
- 테스트 대상 브랜치/커밋과 로컬 검증 절차가 공유되어 있어야 한다.
- WBS 항목이 없는 프로젝트와 루트/자식 항목이 섞인 프로젝트를 각각 준비한다.

## 편집 기능 체크

- 이름 인라인 편집이 기존과 동일하게 저장/취소된다.
- 진척률 인라인 편집이 기존과 동일하게 저장/취소된다.
- 담당자 셀에서 사용자 지정/해제가 가능하다.
- 기간 셀에서 시작일만 입력, 종료일만 입력, 시작일+종료일 입력이 각각 저장된다.
- 예상 M/M 셀에서 값 입력/수정/삭제가 가능하다.
- 마일스톤 셀에서 지정/해제가 가능하다.

## 구조 편집 체크

- `이동` 액션으로 루트 항목을 다른 루트 위치로 옮길 수 있다.
- `이동` 액션으로 자식 항목을 같은 부모 내 다른 위치로 옮길 수 있다.
- `이동` 액션으로 항목을 다른 부모 아래로 옮길 수 있다.
- 자기 자신 또는 자기 하위 항목 아래로 이동하려 하면 차단된다.
- depth limit 초과 이동은 차단된다.

## 검증/예외 체크

- 잘못된 기간 범위(`startDate > endDate`)는 저장되지 않는다.
- 예상 M/M 음수 입력은 차단된다.
- 비어 있는 값(`미지정`, `기간 없음`, `마일스톤 없음`)도 편집 진입이 가능하다.
- 편집 취소(`Esc`)와 포커스 이탈(`blur`) 동작이 필드별로 기대대로 작동한다.

## 화면 일관성 체크

- compact tab에서 편집 결과가 dedicated page와 동일하게 반영된다.
- dedicated page에서 편집한 결과가 compact tab에도 즉시 반영된다.
- quick-add 후 같은 row에서 후속 편집이 가능한지 확인한다.

## 회귀 체크

- 기존 drag-and-drop reorder가 여전히 동작한다.
- 수정 다이얼로그 fallback이 남아 있다면 기존 필드 저장이 깨지지 않는다.
- WBS 데이터 갱신 후 milestone 패널/관련 조회가 깨지지 않는다.

## 결과 기록 형식

- 테스트 환경
- 재현 절차
- 기대 결과 / 실제 결과
- 실패 케이스
- 회귀 통과 여부
