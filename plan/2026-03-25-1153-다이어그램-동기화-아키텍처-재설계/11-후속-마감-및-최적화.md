# 11. 후속 마감 및 최적화

## 목적

이 문서는 Phase 1 완료 후 남아 있는 마감 작업과 최적화 작업을 관리한다.  
즉시 구조를 다시 뒤엎는 것이 아니라, 이미 완료된 협업 코어/ERD plugin 경계 위에서
사용자 경험, page/runtime 마감, 성능 hot path, Phase 2 준비를 순서대로 정리하는 것이 목적이다.

## 현재 상태

- Phase 1 완료 조건은 충족된 상태로 본다.
- broad smoke 묶음과 targeted smoke는 최신 기준으로 통과했다.
- shared-draft 묶음 실행 종료 지연은 현재 비재현이라 deferred 관측 항목으로 둔다.
- `save/reload/stale UX` 와 `DiagramPage/runtime` 정리는 1차 마감이 끝난 상태로 본다.
- large diagram 초기 협업 지연은 2차 최적화 단계까지 진행됐고, 추가 성능 마감만 남아 있다.
- WebSocket 연결 수 초과(`4408`/`4409`)는 사용자 배너와 수동 재연결 UX까지 반영된 상태다.

## 작업 묶음

### 완료된 항목

1. save/reload / stale UX 검증 및 보완
- `content`와 `ydocSnapshot` 저장 시점 정합성 추가 확인
- 409/stale 처리 후 UX와 재동기화 정책 점검
- stale snapshot persist는 footer 상태뿐 아니라 사용자에게 명확히 보이도록 유지

2. `DiagramPage` / runtime 오케스트레이션 축소
- `DiagramPage` 와 diagram channel 훅들에 남아 있는 overlay / dialog / work-mode 주변 조합 책임을 더 얇게 만든다
- page는 화면 상태와 wiring만, runtime은 조립만, channel/session은 행위만 갖도록 재정리한다
- `use-diagram-page-runtime-state.ts` 가 새 orchestration 덩어리가 되지 않도록 경계도 같이 점검한다

3. large diagram 초기 협업 지연 1차 해소
- full shared draft overlay가 persisted canvas를 사실상 두 벌 렌더하던 경로를 large diagram에서 숨겼다
- handle DOM 렌더 수와 `TableNode` 초기 internals update를 줄여 startup long task를 크게 낮췄다
- `first ws-ticket`, `final ws-connected` hard target은 달성했고, `max long task <= 500ms` 는 아직 후속 과제로 남아 있다

4. WebSocket 연결 수 초과 UX/진단 보강
- 같은 사용자 동시 협업 연결 수가 제한을 넘을 때 서버가 앱 전용 close code(`4408`, `4409`)로 명확히 닫도록 정리했다
- 프런트는 일반 `policy-violation` 대신 `연결 수 초과` / `방 세션 수 초과` 배너를 띄우고 자동 재연결 루프를 멈춘다
- 다른 탭을 닫은 뒤 수동 재연결로 복구되는 smoke를 고정했다

### 남은 항목

1. large diagram 성능 2차 최적화
- 남아 있는 `~600ms`대 startup long task를 더 줄인다
- 렌더 후 pan/zoom/frame gap을 추가로 낮춘다
- 우선 후보는 `TableNode` / `PreviewTableNodes` 잔여 row DOM 비용과 viewport 기준 추가 축약 렌더 여부다

2. read authority 추가 정리
- apply/code/read 전 경로가 문서 read를 일관되게 우선하는지 추가 점검
- 남아 있는 full graph 의존은 `groups` 가 필요한 경로와 일부 on-demand read 쪽이라, targeted query를 더 내릴지 판단한다

3. projector/read model 고도화
- 현재 scope-aware refresh는 들어갔지만, 일부 경로는 여전히 full refresh fallback을 사용한다
- large diagram 기준 incremental projector/read model로 더 좁힐지 판단한다

4. deferred 관측 항목 관리
- shared-draft 묶음 실행 종료 이슈는 다시 터질 때만 artifact를 보존해 재조사한다
- broad regression은 유지하되, 비재현 이슈는 수정 대상이 아니라 관측 대상으로만 관리한다

5. code path 2차 전환 준비
- `DraftState` / reconcile state machine을 실제 code editor 경로에 더 강하게 연결한다
- `dirty-invalid`, `remote-pending`, overwrite guard를 새 경계에 맞춰 재구성한다
- text input pipeline / Phase 2 code path 확장 전 준비 작업으로 본다

## 권장 순서

1. large diagram 성능 2차 최적화
2. `read authority / projector` 추가 최적화
3. `code path 2차 전환` 준비
4. deferred 관측 유지

## 진행 메모 (2026-03-30)

- Phase 1 완료 문서와 후속 backlog 문서를 분리했다.
- stale snapshot persist는 `dirty`로 뭉개지 않고 실제 `stale` 상태를 보존하도록 정리했다.
- `diagram-code-mode-stale-persist.spec.ts` 를 추가해 `peer persisted save -> owner stale 전이 -> Apply/Finalize 차단 -> reload 후 stale 해제` 흐름을 smoke로 고정했다.
- `workMode / workModeHydrated` 소유권은 `use-diagram-work-mode-state.ts` 로 이동했다.
- `DiagramPage` 에 남아 있던 code-first preview / code draft persist / dictionary dialog 정책 분기를 `use-diagram-page-runtime-state.ts` 쪽으로 더 이동했다.
- non-projector Y.Doc observer도 changed id 기준 partial refresh를 우선 사용하게 정리했다.
- projection bridge / deferred queue는 `scopeHints`가 비어도 `targets + nodeIds/edgeIds/groupIds`를 보존해 unnecessary full refresh widening을 줄이도록 정리했다.
- remote delete/update projector refresh는 affected entity가 이미 사라진 경우에도 `scopeHints -> id 기반 partial refresh`를 유지해서 delete 계열 remote 변경이 불필요한 full refresh로 넓어지지 않게 정리했다.
- code editor refresh overwrite guard는 `텍스트가 비어 있는지`가 아니라 `DraftState.dirty` 기준으로 바꿨고, `diagram-code-editor-refresh-guard.spec.ts` 로 `clean refresh 즉시 실행 / dirty refresh confirm` 흐름을 smoke로 고정했다.
- refresh overwrite guard 공통 정책은 `code-editor-draft-policy.ts` 로 올려서 DDL/DSL이 같은 contract를 쓰게 정리했다.
- refresh confirm 문구도 `remote-pending / invalid / stale / local dirty` reason 기준으로 분기해 footer와 overwrite guard가 같은 상태 계약을 쓰게 정리했다.
- `useCodeEditorRefresh` 도 단순 boolean 대신 `refreshConfirmReason` 을 직접 받도록 바꿔서, DDL/DSL이 refresh 확인 필요 여부와 확인 문구를 같은 reason source에서 공유하게 정리했다.
- `stale` shared draft toast에 즉시 reload 액션을 붙여 `stale -> 안내 -> reload -> 해제` 동선을 바로 밟을 수 있게 보완했다.
- `DiagramPage` 에 남아 있던 group view 진입 전 clear/highlight 해제와 code panel toggle gating도 `use-diagram-page-runtime-state.ts` 경계로 옮겨 page의 UI policy glue를 더 줄였다.
- `DiagramDocumentPersistenceSession.saveContent()` 같은 mixed-source 저장 escape hatch를 제거해, published save는 `preparePublishedBackup()` 이 만든 같은 checkpoint의 `content + snapshot` 조합만 쓰도록 정리했다.
- `GH도급사업 > GH 도급` large diagram baseline에서 first ticket 평균 `44.1s`, preview fallback 평균 `45.4s`, final ws-connected 평균 `47.7s`를 관찰했다.
- 같은 이슈의 직접 원인은 WebSocket transport가 아니라, diagram runtime 진입 직후 메인 스레드에서 발생하는 약 `41.2s` 규모 long task로 판단했다.

- large diagram 1차 수정으로 large sync canvas의 full shared draft overlay를 숨기고, 컬럼 handle DOM을 연결/FK 모드 기준으로만 렌더하게 줄였다.
- `TableNode` 의 `updateNodeInternals()` 는 배치 실행으로 바꿨고, 핸들이 없는 테이블은 초기 update를 건너뛰게 정리했다.
