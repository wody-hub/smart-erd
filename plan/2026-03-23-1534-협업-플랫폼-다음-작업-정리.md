## 3. 다음 우선순위

### 우선순위 1. Phase 3
목표:
- diagram 채널 plugin 구조를 실제 확장 가능한 형태로 한 단계 더 일반화

해야 할 일:
- `application/diagram/*`에 남아 있는 diagram 전용 channel 하드코딩 추가 축소
- `CollaborationChannelPlugin`가 직접 `snapshot/handoff/access`만 노출하는 현재 구조에서
  - 향후 `ticket`, `bootstrap`, `presence`, `preview policy` 확장을 고려한 계약 점검
- `DiagramCollaborationResourceKeys` 기준으로 diagram channel key 생성 경로 통일

주의:
- 지금 단계에서는 WebSocket 메시지 타입, `/ws/diagram/*` 경로, Yjs binary 포맷은 바꾸지 않음

### 우선순위 2. Phase 4
목표:
- backend 진입점 연결을 더 플랫폼 구조에 가깝게 정리

해야 할 일:
- `WsTicketHandshakeInterceptor`
- `DiagramWebSocketHandler`
- `SnapshotRequestMessageHandler`
위 3개에서 남아 있는 diagram 전용 배선/해석 로직을 다시 점검

특히 확인할 것:
- legacy `AuthenticatedSession` 제거 가능 시점
- common session key만으로 운영 가능한지
- room lifecycle, peer-left, flush, reconnect가 계속 보존되는지

### 우선순위 3. Phase 5
목표:
- 프론트 협업 runtime/state machine 정리

해야 할 일:
- `useYjsCollaboration`를 더 얇은 wrapper로 축소
- `useCollaborationSession`/runtime state machine 활용 범위 확대
- 상태를 아래 기준으로 명확화
  - `preview`
  - `hydrating`
  - `live`
  - `degraded`
  - `reconnecting`

주의:
- `useBidirectionalCodeSync`
- `useEditorCursorGuard`
- footer/status UI
는 editor-local UX이므로 계속 collaboration core 밖에 둔다
