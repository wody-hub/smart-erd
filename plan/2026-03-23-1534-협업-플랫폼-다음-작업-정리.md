   - code mode overwrite hotfix
   - collaboration runtime/provider 구조 정리

### 우선순위 2. 문서/실행 기준 정리
해야 할 일:
- README를 현재 검증 기준에 맞게 최종 정리
- recovery 실행 예시를 `bootRun-*.sh` 기준으로 통일

### 우선순위 3. durability 후속 개선 판단
현재 남아 있는 메모:
- code mode snapshot persist는 여전히 debounce/keepalive 기반이라 마지막 입력 직후 장애 시 유실 창이 남아 있음
- diagram entity의 `content` vs `ydocSnapshot` 단일 소스 마이그레이션은 아직 장기 과제로 남아 있음

이건 지금 당장 blocking은 아니지만 다음 차수 후보:
1. code mode snapshot durability 강화
2. authoritative source를 `ydocSnapshot` 중심으로 정리하는 마이그레이션 설계
