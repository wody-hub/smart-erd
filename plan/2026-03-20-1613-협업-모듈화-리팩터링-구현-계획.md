## 1. 구현 목표 재정의

이번 구현은 단순히 `diagram 협업 클래스 공통화`를 하는 작업이 아니다.

1차 구현의 실제 목표는 아래다.

1. 협업 기능을 `domain` 밖의 플랫폼 계층으로 재정의한다.
2. 저장/복구/재접속/preview fallback 의미를 코드 계약으로 고정한다.
3. `authoritative content`, `persisted collaboration snapshot`, `warm room state`, `frontend collaboration state machine`을 분리된 시스템 개념으로 만든다.
4. 다이어그램을 첫 번째 채널 플러그인으로 재구성할 준비를 끝낸다.

### 1차에서 반드시 유지할 외부 동작

- WebSocket 경로 유지: `/ws/diagram/*`
- Yjs wire protocol 유지
- ticket/handshake 계약 유지
- save/reload/reconnect 동작 유지
- preview fallback 동작 유지
- 3계정 협업 smoke 유지

### 1차에서 하지 않는 일

- 두 번째 협업 형상 구현
- 다른 CRDT 엔진 일반화
- WebSocket message type 변경
- editor-local UX 훅의 collaboration core 이동
- `DiagramMessageSender`, `DiagramPresenceNotifier` 전면 공통화
- relay handler 전체 이동
- `DiagramRoomManager` 완전 분해

## 4. 1차 구현에서 새로 도입할 핵심 개념

### 4.1 백엔드 공통 개념

#### `CollaborationResourceKey`
- 공통 리소스 식별자
- 1차는 `channelType + resourceId(String)` 유지
- diagram은 `diagramId`를 래핑

#### `CollaborationAuthenticatedSession`
- handshake 이후 세션 메타데이터
- 현재 `AuthenticatedSession`의 공통화 버전

#### `CollaborationSnapshotSaveCommand`
- snapshot 저장 커맨드
- `expectedContentRevision + fullStateUpdate`

#### `CollaborationSnapshotStore`
- persisted collaboration snapshot load/save contract

#### `CollaborationHandoffPolicy`
- warm handoff 규칙
- 단순 store read가 아니라:
  - warm room state
  - cached snapshot
  - persisted snapshot
  를 조합

#### `CollaborationChannelPlugin`
- 채널 타입
- access policy
- snapshot store
- handoff policy
- bootstrap provider
- presence policy

### 4.2 백엔드 application 유스케이스

#### `IssueCollaborationTicketUseCase`
- ws ticket 발급/검증 흐름의 application 진입점

#### `LoadCollaborationHandoffUseCase`
- handoff snapshot 조립 유스케이스
- `SnapshotRequestMessageHandler`가 직접 여러 서비스 조합하지 않게 만드는 목표

#### `ReconcileCollaborationStateAfterSaveUseCase`
- authoritative save 후 `afterCommit` 기반 room/cache 정렬 orchestration

#### `SaveDiagramAuthoritativeContentUseCase`
- diagram 저장 유스케이스
- 협업 snapshot과 authoritative content의 경계를 명확히 유지

### 4.3 프론트 공통 개념

#### `CollaborationRuntimeState`
- `preview`
- `hydrating`
- `live`
- `degraded`
- `reconnecting`

#### `useCollaborationRuntime`
- generic runtime hook
- provider lifecycle
- session machine
- transport binding

#### `CollaborationChannelPlugin`
- ticket 요청
- binding 생성
- preview policy 제공
- document adapter 제공

#### `DiagramChannelPlugin`
- diagram-specific channel plugin
- bootstrap source는 여전히 `DiagramPage`/React Query가 소유

#### `DiagramPreviewPolicy`
- preview/fallback/live 전이 규칙

#### `DiagramYjsDocumentAdapter`
- bootstrap -> Y.Doc 반영
- Y.Doc -> snapshot 추출

### 7.2 diagram 채널 플러그인 초안

#### `DiagramChannelPlugin`

```java
package com.smarterd.domain.diagram.collaboration;

import com.smarterd.collaboration.channel.CollaborationAccessPolicy;
import com.smarterd.collaboration.channel.CollaborationChannelPlugin;
import com.smarterd.collaboration.handoff.CollaborationHandoffPolicy;
import com.smarterd.collaboration.snapshot.CollaborationSnapshotStore;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Component;

@Component
@RequiredArgsConstructor
public class DiagramChannelPlugin implements CollaborationChannelPlugin {

    private final DiagramAccessPolicy accessPolicy;
    private final DiagramSnapshotStore snapshotStore;
    private final DiagramHandoffPolicy handoffPolicy;

    @Override
    public String channelType() {
        return "diagram";
    }

    @Override
    public CollaborationAccessPolicy accessPolicy() {
        return accessPolicy;
    }

    @Override
    public CollaborationSnapshotStore snapshotStore() {
        return snapshotStore;
    }

    @Override
    public CollaborationHandoffPolicy handoffPolicy() {
        return handoffPolicy;
    }
}
```

#### `DiagramSnapshotStore`

```java
package com.smarterd.domain.diagram.collaboration;

import com.smarterd.collaboration.channel.CollaborationResourceKey;
import com.smarterd.collaboration.snapshot.CollaborationSnapshotSaveCommand;
import com.smarterd.collaboration.snapshot.CollaborationSnapshotStore;
import com.smarterd.domain.diagram.service.DiagramSnapshotService;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Component;

@Component
@RequiredArgsConstructor
public class DiagramSnapshotStore implements CollaborationSnapshotStore {

    private final DiagramSnapshotService diagramSnapshotService;

    @Override
    public byte[] load(CollaborationResourceKey resourceKey) {
        final long diagramId = Long.parseLong(resourceKey.resourceId());
        return diagramSnapshotService.loadSnapshot(diagramId);
    }

    @Override
    public void save(CollaborationResourceKey resourceKey, CollaborationSnapshotSaveCommand command) {
        final long diagramId = Long.parseLong(resourceKey.resourceId());
        diagramSnapshotService.replaceSnapshotWithClientState(
            diagramId,
            command.expectedContentRevision(),
            command.fullStateUpdate()
        );
    }
}
```

주의:
- 이 store는 persisted snapshot load/save만 담당한다.
- warm handoff 조합은 `DiagramHandoffPolicy`가 소유해야 한다.
- authoritative content 저장은 계속 application/diagram 유스케이스가 소유한다.

### 7.3 application 유스케이스 초안

#### `LoadCollaborationHandoffUseCase`

```java
package com.smarterd.application.collaboration.query;

import com.smarterd.collaboration.channel.CollaborationChannelPlugin;
import com.smarterd.collaboration.channel.CollaborationResourceKey;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
public class LoadCollaborationHandoffUseCase {

    private final CollaborationChannelPlugin diagramChannelPlugin;

    public byte[] load(CollaborationResourceKey resourceKey) {
        return diagramChannelPlugin
            .handoffPolicy()
            .buildHandoffSnapshot(resourceKey, diagramChannelPlugin.snapshotStore());
    }
}
```

```ts
import * as Y from 'yjs';
import { useEffect, useRef, useState } from 'react';
import { YjsProvider } from '@/collaboration/YjsProvider';
import type { CollaborationChannelPlugin } from '@/collaboration/channel/collaboration-channel-plugin';
import type { CollaborationRuntimeState } from './collaboration-session-machine';

export function useCollaborationRuntime<TBootstrap>(
  bootstrap: TBootstrap | undefined,
  plugin: CollaborationChannelPlugin<TBootstrap> | null,
) {
  const providerRef = useRef<YjsProvider | null>(null);
  const [runtimeState, setRuntimeState] = useState<CollaborationRuntimeState>('preview');

  useEffect(() => {
    if (!bootstrap || !plugin) {
      return;
    }

    const doc = new Y.Doc();
    const documentAdapter = plugin.createDocumentAdapter();
    documentAdapter.applyBootstrapToDoc(doc, bootstrap);

    const provider = new YjsProvider(doc, {
      diagramId: '',
      getTicket: () => plugin.requestTicket(),
    });

    providerRef.current = provider;
    return () => {
      provider.destroy();
      providerRef.current = null;
    };
  }, [bootstrap, plugin]);

  return { providerRef, runtimeState, setRuntimeState };
}
```

주의:
- 위 코드는 방향을 설명하는 skeleton이다.
- 실제 1차에서는 `DiagramPage` bootstrap ownership과 `useYjsCollaboration` wrapper를 유지한다.
- preview/fallback/live/degraded 의미는 상태 머신으로 끌어올리되, 첫 버전은 현재 로직 의미를 그대로 보존해야 한다.

## 8. 가장 중요한 회귀 포인트

### 리스크 1. warm handoff 회귀

현재 `SnapshotRequestMessageHandler`는 단순 snapshot load가 아니다.

실제 의미:
- pending update가 있으면 warm handoff
- 아니면 cached snapshot
- 아니면 persisted snapshot

따라서 `SnapshotStore.load()` 하나로 뭉개면 회귀한다.

대응:
- `DiagramHandoffPolicy`를 별도 구현체로 둔다.
- `LoadCollaborationHandoffUseCase`가 policy를 호출한다.

### 리스크 2. preview/fallback/live 상태 회귀

현재 `useYjsCollaboration`은:
- preview 표시
- WS hydrate 대기
- fallback timeout
- live 전환
을 한곳에서 관리한다.

대응:
- 상태 머신으로 승격
- 단, 1차에선 의미 보존 우선

### 리스크 3. session lifecycle 회귀

`AuthenticatedSession` 교체는:
- room join
- rate limit
- peer-left
- last user flush
전체에 영향을 준다.

대응:
- `CollaborationAuthenticatedSession` 도입 시 속성 키/필드 의미 호환 유지
- 핸들러/컨텍스트/handshake를 한 번에 바꾸지 않고 단계적으로 바꾼다.

### 리스크 4. editor UX 오염

`useBidirectionalCodeSync`, `useEditorCursorGuard`를 collaboration core로 옮기면 구조가 다시 흐려진다.

대응:
- editor layer 유지
- collaboration runtime과 wrapper/component 계층에서만 연결

## 9. 1차 완료 정의

아래를 만족하면 1차 완료로 본다.

1. `domain / application / collaboration / infrastructure` 계층 경계가 코드에 나타난다.
2. `CollaborationAuthenticatedSession`이 도입되고 handshake/runtime이 이를 사용하기 시작한다.
3. `CollaborationSnapshotStore`, `CollaborationHandoffPolicy`, `CollaborationChannelPlugin`이 도입된다.
4. `SnapshotRequestMessageHandler`가 handoff 유스케이스를 통해 snapshot 조합을 시작한다.
5. 프론트에 `CollaborationRuntimeState`, `useCollaborationRuntime`, `DiagramPreviewPolicy`, `DiagramYjsDocumentAdapter`, `createDiagramChannelPlugin`이 도입된다.
6. `useYjsCollaboration`은 wrapper로 축소되지만 외부 동작은 유지된다.
7. editor-local UX 훅은 현 위치를 유지한다.
8. README가 새 계층 구조를 반영한다.
9. 3계정 협업 smoke, save/reload/reconnect, preview fallback, warm handoff 검증이 통과한다.

## 10. 최종 한 줄 결론

이번 구현은 협업 기능을 “조금 더 깔끔하게 나누는 리팩터링”이 아니라, **앞으로 새 형상과 새 시스템을 안정적으로 수용할 수 있는 협업 플랫폼의 기준선을 실제 코드에 세우는 작업**으로 진행한다.
