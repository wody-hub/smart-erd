## 적용한 변경

- P1/P5 `edgeAutoRoute.ts`: 공간 인덱스, clear 경로 증분 재사용, 최선 후보 우선 탐색 (결과는 참조 구현과 동일, 4,320건 + 동점 격자 비교)
- P2/P3/P4: `ErdRelationEdge` memo, 잠금·프리뷰 노드/엣지별 구독, 사이드바 행 memo, 경로를 store 선택자로 이동해 경로가 바뀐 엣지만 렌더
- 컨텍스트 값 안정화: `ErdPermission`, `ErdDictionary`, `DiagramCodeNavigation` (TableNode 불필요 렌더 약 26,000 → 약 230 / 10초, S200 개발 빌드)

## 남은 병목과 한계

- S500에서 4명이 초당 8건을 계속 편집하는 부하는 여전히 처리 한계를 넘는다. 남은 비용은 React Flow 내부 `EdgeWrapper`/`NodeWrapper`가 커밋마다 전체(엣지 약 600개)를 렌더하는 것이다.
- 다음 후보: 뷰포트 밖 요소 렌더 생략(`onlyRenderVisibleElements`, 내보내기 때만 끄기), 원격 업데이트 배치 적용.
- C4(부하 중 합류)는 S500에서 일부 편집이 "전파 시간 초과"로 기록된다. 같은 컬럼을 연속 변경하는 하네스에서 중간 값이 덮어써져 관찰되지 않는 경우일 수 있으나 확인하지 못했다(유실 증거는 없음, C3 수렴은 통과).
- "편집 가능" 시각은 편집 버튼 활성화 시점이라 전체 렌더 완료 시간이 아니다.

### 알려진 문제 (미해결)

- C4(부하 중 늦은 합류) S500: 합류 전에 일어난 편집은 합류 클라이언트가 관찰할 수 없어 "전파 시간 초과"가 기록된다(변경 전 빌드에서도 동일).
- S500 C4를 변경 후 빌드로 11회 반복했을 때 1회, 합류 클라이언트가 최종값 대신 시드 값을 보여 `final-diverged`로 기록됐다(변경 전 빌드 5회에서는 0회). 표본이 적어 원인은 확정하지 못했다. 재발 여부와 원인(합류 클라이언트의 동기화 지연 vs 실제 누락) 확인이 필요하다.
- smoke E2E: 변경 전후 동일하게 9건 실패(사전 존재, 작업모드/코드모드 UI·사전 다이얼로그·markdown 3계정)와 `diagram-loading`(환경변수 필요). 프로덕션 빌드 preview에서는 screen-spec 2건이 추가로 실패하나 변경 전 프로덕션 빌드에서도 동일하다(개발 서버에서는 통과).
