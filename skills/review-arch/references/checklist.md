## 공통 아키텍처 체크리스트

### 1. 아키텍처 구조 (Critical)

- [ ] Layered Architecture 경계가 유지되는지 확인
- [ ] Controller / UI가 비즈니스 규칙이나 영속성 세부사항을 직접 다루지 않는지 확인
- [ ] Hexagonal 구조가 필요한 외부 연동 지점에서 Port / Adapter 분리가 되어 있는지 확인
- [ ] Domain 모델이 프레임워크, 외부 SDK, 인프라 구현체에 잠식되지 않았는지 확인
- [ ] DDD 관점에서 Aggregate / Entity / Value Object / Service 책임이 뒤섞이지 않았는지 확인

### 2. 의존성 규칙 (Critical)

- [ ] 의존성이 반드시 안쪽 계층으로 향하는지 확인
- [ ] 상위 정책 계층이 하위 구현체를 직접 new / import / static call 하지 않는지 확인
- [ ] 인터페이스 기반 설계가 필요한 지점에서 구현체 직접 의존이 남아 있지 않은지 확인
- [ ] 순환 의존, 양방향 결합, 패키지 간 역방향 참조가 없는지 확인

### 3. 비즈니스 로직 배치 (High)

- [ ] 핵심 규칙이 Domain에 있어야 하는데 Service / Controller / UI에 흩어져 있지 않은지 확인
- [ ] Service가 오케스트레이션을 넘어 도메인 규칙 저장소처럼 비대해지지 않았는지 확인
- [ ] 정책 변경 시 여러 클래스/계층을 동시에 수정해야 하는 산탄총 수술 냄새가 없는지 확인

### 4. 데이터 설계 (High)

- [ ] 데이터 모델 변경에 대응하는 ERD, 스키마 문서, 동등한 구조 근거가 존재하는지 확인
- [ ] 엔티티 책임과 경계가 명확한지 확인
- [ ] 중복 컬럼, 중복 상태, 파생값 저장 등으로 정규화가 과하게 깨지지 않았는지 확인
- [ ] 참조 무결성과 생명주기 소유권이 구조적으로 설명 가능한지 확인

### 5. SOLID / 확장성 (Medium)

- [ ] SRP 관점에서 클래스나 모듈이 하나의 책임만 갖는지 확인
- [ ] OCP 관점에서 새 정책 추가 시 기존 구현을 과도하게 수정해야 하지 않는지 확인
- [ ] DIP 관점에서 상위 정책이 저수준 구현 세부사항에 종속되지 않는지 확인

## 백엔드 구조 체크리스트 (Java / Spring Boot)

### 6. 패키지 / 계층 배치 (High)

- [ ] `api/`, `domain/`, `config/` 경계가 README 규칙대로 유지되는지 확인
- [ ] DTO가 `api/` 밖으로 새어 나가거나 Entity가 API 계약을 직접 대체하지 않는지 확인
- [ ] Service가 해당 도메인 패키지 안에 위치하며 다른 도메인의 내부 구현을 침범하지 않는지 확인

### 7. Repository / 영속성 경계 (High)

- [ ] Domain Service가 QueryDSL / JPA 세부 구현에 과도하게 결합되지 않았는지 확인
- [ ] Repository가 단순 조회를 넘어 도메인 정책 판단까지 수행하지 않는지 확인
- [ ] Custom Repository / Port 경계가 필요한 조회 복잡도에 맞게 유지되는지 확인

### 8. 도메인 무결성 / 모델 책임 (High)

- [ ] 엔티티가 자신의 상태 변경 규칙을 스스로 보장하는지 확인
- [ ] 단순 CRUD Service에 비즈니스 정책이 누적되어 도메인 모델이 빈약해지지 않았는지 확인
- [ ] 예외 체계가 도메인 의미를 표현하고 범용 예외로 흐르지 않는지 확인

## 프론트엔드 구조 체크리스트 (TypeScript / React)

### 9. 책임 분리 / 계층 방향 (High)

- [ ] `pages -> hooks -> stores -> lower-level modules` 방향이 유지되는지 확인
- [ ] Page / Component에서 API, 스토어, 실시간 협업 세부 구현이 한 번에 섞이지 않는지 확인
- [ ] 공용 layout이 도메인 전용 상태나 협업 구현에 직접 결합되지 않는지 확인

### 10. 상태 모델 설계 (High)

- [ ] 동일 데이터가 여러 store / local state / query cache에 중복 저장되지 않는지 확인
- [ ] SSOT가 깨져 동기화 코드가 늘어나는 구조인지 확인
- [ ] UI 컴포넌트가 도메인 규칙이나 영속성 포맷을 직접 알지 않아도 되는지 확인

### 11. 도메인 경계 / 공통화 (Medium)

- [ ] ERD, Dictionary, Collaboration 경계가 README 가드레일대로 유지되는지 확인
- [ ] 반복 로직이 훅, 유틸, 공통 컴포넌트로 적절히 추출되어 있는지 확인
- [ ] 기능 확장 시 분기 추가보다 전략/구성 분리로 대응 가능한 구조인지 확인

## 경계 보안 체크리스트 (필요 시)

### 12. 보안 경계 설계 (Medium)

- [ ] 인증 / 인가 / 외부 연동 경계가 계층 구조 안에서 일관되게 강제되는지 확인
- [ ] 민감 정보, 토큰, 권한 판단이 UI 또는 임시 유틸에 흩어져 있지 않은지 확인
- [ ] 외부 입력 검증이 어댑터 / API 경계에서 수행되고 Domain까지 오염되지 않는지 확인
- [ ] WebSocket, 비동기 메시지, 실시간 협업 경계에서 리소스 접근 통제가 유지되는지 확인

## 문서화 계약 체크리스트 (공통)

### 13. 문서화 계약 (Medium)

- [ ] 백엔드(Java) 신규/수정 메서드에 Javadoc이 있는지 확인 (`@param`, `@return`, 필요 시 `@throws`)
- [ ] 프론트엔드(TypeScript/React) 신규/수정 함수/훅/핸들러에 JSDoc이 있는지 확인 (`@param`, 반환값 설명)
