# 아키텍처 및 보안 체크리스트

점검 대상 스택에 해당하는 항목만 적용한다.

## 백엔드 체크리스트 (Java / Spring Boot)

### 1. 동시성 및 스레드 안전성 (Critical)

- [ ] concurrent 컬렉션 사용 시에도 복합 연산(TOCTOU 레이스)이 없는지 확인
- [ ] `synchronized` 블록 범위가 과도하거나 부족하지 않은지 확인
- [ ] `@Scheduled` 메서드의 공유 상태 접근이 안전한지 확인
- [ ] WebSocket `sendMessage` 호출의 세션 단위 동기화가 필요한 위치에 적용되었는지 확인

### 2. 데이터 무결성 및 영속성 (Critical)

- [ ] 인메모리 캐시/버퍼가 full state인지 delta-only인지 확인
- [ ] 인메모리 -> DB 영속화 경로에 크래시/OOM 데이터 유실 구간이 없는지 확인
- [ ] 스케줄 flush와 연결 종료 flush 사이에 중복/누락이 없는지 확인
- [ ] 루프 내부 `findById` 등 N+1 쿼리 패턴이 없는지 확인

### 3. 리소스 생명주기 (High)

- [ ] 비정상 연결 종료 시 WebSocket 세션/방 정리가 되는지 확인
- [ ] `rooms`, `snapshots` 등 인메모리 맵에 stale 엔트리 누수가 없는지 확인
- [ ] 연결 종료 시 피어에게 필요한 cleanup 메시지가 전송되는지 확인

### 4. 에러 복구 및 장애 격리 (High)

- [ ] 한 세션의 `sendMessage` 실패가 전체 브로드캐스트를 중단시키지 않는지 확인
- [ ] 예외 발생 후 세션/방/스냅샷 상태 일관성이 유지되는지 확인
- [ ] `@Scheduled` 예외 발생 시 스케줄 실행이 멈추지 않도록 처리되는지 확인

### 5. URL/프로토콜 파싱 견고성 (Medium)

- [ ] URL 파싱이 하드코딩 split 인덱스에 과도하게 의존하지 않는지 확인
- [ ] 바이너리 프로토콜 파싱에서 payload 길이 검증이 충분한지 확인

## 프론트엔드 체크리스트 (TypeScript / React)

### 6. 상태 관리 아키텍처 (Critical)

- [ ] 스토어/모듈이 단일 책임을 유지하는지 확인
- [ ] 동일 데이터의 SSOT가 깨지지 않는지 확인
- [ ] 상위 계층이 CRDT 저수준 구조를 직접 조작하지 않는지 확인

### 7. Dual-mode 분기 안티패턴 (High)

- [ ] 플래그 분기로 동일 로직이 중복 구현되지 않았는지 확인
- [ ] 중복 분기 경로가 모두 실제 사용되는지 확인하고, 레거시는 제거/전략 분리하는지 확인
- [ ] 기능 추가 시 다수 분기를 동시에 고쳐야 하는 산탄총 수술 냄새가 없는지 확인

### 8. 정리 및 메모리 누수 (High)

- [ ] `useEffect` cleanup에서 등록한 리스너/observer가 모두 해제되는지 확인
- [ ] CRDT observer 등록에 대응하는 unobserve 호출이 있는지 확인
- [ ] `Y.Doc.destroy()` 등 리소스 정리 함수가 호출되는지 확인
- [ ] timeout/interval 및 모듈 스코프 타이머 정리가 되는지 확인

### 9. 모듈 스코프 가변 상태 (Medium)

- [ ] 스토어 바깥 module-scope `let` 가변 상태가 남아 있지 않은지 확인
- [ ] unmount/remount/HMR 상황에서 모듈 상태 초기화가 되는지 확인
- [ ] 숨겨진 모듈 상태로 디버깅/관찰성이 저하되지 않는지 확인

### 10. 중복 및 공통화 (Medium)

- [ ] 3줄 이상 반복 로직이 2곳 이상이면 공통 함수/훅으로 추출되는지 확인
- [ ] 반복적인 map/object 생성 패턴에 빌더/팩토리 추출 여지가 있는지 확인
- [ ] 에러/토스트/재시도 같은 횡단 관심사 패턴이 일관적인지 확인

### 11. 의존성 방향 (Medium)

- [ ] `pages -> hooks -> stores -> collaboration` 단방향 의존이 유지되는지 확인
- [ ] `collaboration -> stores` 역방향 의존/순환 의존이 생기지 않는지 확인
- [ ] 순환 발생 시 인터페이스 분리 또는 이벤트 기반 경계로 해소하는지 확인

## 보안 체크리스트 (OWASP 기반)

### 12. 인증/인가 우회 (Critical)

- [ ] WebSocket 핸드셰이크 JWT 검증 누락/우회 경로가 없는지 확인
- [ ] URL query token 사용 시 로그/히스토리 유출 위험이 관리되는지 확인
- [ ] 핸드셰이크 이후 메시지 처리에서도 자원 바인딩 기반 인가가 유지되는지 확인
- [ ] 장기 WebSocket 연결에서 토큰 만료 처리가 되는지 확인
- [ ] 프론트 토큰 저장(`localStorage`)의 XSS 탈취 위험이 고려되었는지 확인

### 13. 입력 검증 및 인젝션 (Critical)

- [ ] 바이너리 메시지 relay 전 최소 검증이 있는지 확인
- [ ] WebSocket 메시지 크기 제한으로 OOM/DoS를 방어하는지 확인
- [ ] JSON 파싱 시 과도한 중첩/대용량 payload 방어가 있는지 확인
- [ ] 네이티브/동적 쿼리 문자열 결합으로 SQL Injection 위험이 없는지 확인
- [ ] `innerHTML`/`dangerouslySetInnerHTML` 기반 XSS sink가 없는지 확인

### 14. WebSocket 보안 (High)

- [ ] Origin 검증이 적용되고 와일드카드 허용이 남아 있지 않은지 확인
- [ ] 사용자/방 단위 연결 수 제한이 있는지 확인
- [ ] 메시지 rate limiting이 있는지 확인
- [ ] 알 수 없는 메시지 타입 수신 시 서버가 안정적으로 처리되는지 확인

### 15. 데이터 노출 및 정보 유출 (High)

- [ ] 클라이언트 오류 응답에 스택트레이스/내부 토폴로지가 노출되지 않는지 확인
- [ ] 로그에 토큰/비밀번호 등 비밀값이 기록되지 않는지 확인
- [ ] API 응답에 불필요한 내부 민감 필드가 포함되지 않는지 확인
- [ ] CORS 정책이 와일드카드 대신 허용 목록 기반인지 확인

### 16. 의존성 및 공급망 보안 (Medium)

- [ ] `npm audit`/SCA/Gradle 플러그인 등으로 알려진 CVE를 점검하는지 확인
- [ ] 미사용 의존성이 공격 표면을 넓히지 않는지 확인
- [ ] 프로덕션 번들/소스맵 노출이 통제되는지 확인

### 17. CRDT/실시간 협업 특화 보안 (Medium)

- [ ] 악성 CRDT update relay로 문서 손상이 가능한지 점검하는지 확인
- [ ] awareness/client identity 스푸핑 가능성을 점검하는지 확인
- [ ] 방 간 메시지 격리가 유지되는지 확인
